### Amazon Dynamo and DynamoDB: Availability First

The original Dynamo system, described in Amazon's 2007 paper, is the best-known example of an AP design. Its motivating requirement was stated plainly: customers should be able to view and add items to their shopping cart even if disks are failing, network routes are flapping, or data centers are unreachable. An "add to cart" that fails costs revenue, so Dynamo chose availability over consistency.

**How Dynamo made that choice.** Data is partitioned on a consistent hash ring and replicated to N nodes. Writes use a "sloppy quorum": if a replica is unreachable, another node accepts the write and hands it back later (hinted handoff). Concurrent versions of a value are tracked with vector clocks and merged by the application. For a shopping cart, the merge is a union of the items, which means a deleted item can occasionally reappear. That is an acceptable cost for a cart that never rejects an add.

**DynamoDB the service is a descendant, not a copy.** The managed DynamoDB service that AWS launched in 2012 keeps the goals of high availability and predictable performance, but its internals differ. According to AWS's 2022 paper, each table is split into partitions, and each partition is replicated across three Availability Zones using a leader-based (Multi-Paxos) protocol. A write is acknowledged once a majority of replicas have it. Reads are eventually consistent by default and can be served by any replica. A strongly consistent read goes to the leader, and it can fail if the leader is unreachable. Global tables replicate across Regions asynchronously and resolve conflicts with last-writer-wins, so across Regions the service behaves like an AP system.

**Result.** DynamoDB offers a 99.99 percent availability SLA for a single Region, and 99.999 percent for global tables. During Prime Day, AWS has reported peaks well above 100 million requests per second. The trade-off is that applications must cope with eventually consistent reads by default, and last-writer-wins can silently discard one of two concurrent writes.

**Public references**: "Dynamo: Amazon's Highly Available Key-value Store" (SOSP 2007) and "Amazon DynamoDB: A Scalable, Predictably Performant, and Fully Managed NoSQL Database Service" (USENIX ATC 2022).
