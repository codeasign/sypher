### Failure 5: State Bloat from Node ID Churn (PN-Counter)

**What**: A PN-Counter tracks increments and decrements in two vectors with one entry per node ID. Over months of operation, autoscaled counter-service instances come and go, and each new instance gets a fresh ID. Each counter's state grows from 128 bytes to 1,024 bytes as dead IDs accumulate. Memory usage across all 64 shards doubles from 64 GB to 128 GB. Cache hit rates drop because the larger state causes more evictions. Read latency increases by 30%.
