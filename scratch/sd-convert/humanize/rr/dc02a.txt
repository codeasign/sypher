**Step 12. Compaction of Retired Node IDs (PN-Counter only)**: A PN-Counter keeps one entry per node ID, so the metadata grows when node IDs churn (for example, autoscaled instances that each get a fresh ID). Using stable slot IDs avoids the problem. If node IDs must be retired, a background task periodically folds the entries of retired nodes into a single base value, but only after every replica is known to have merged those entries. Compacting earlier would change the total, so this step needs coordination.
