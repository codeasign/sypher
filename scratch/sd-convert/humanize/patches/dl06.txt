**Considerations**: The semaphore must handle the case where a holder crashes without releasing. A TTL per acquisition prevents this. However, the TTL also causes premature release under normal operation if the operation runs long. The solution is to set the TTL generously (e.g., 60 seconds for a 10-second operation) and rely on lease renewal for longer operations.
====
**Considerations**: This counter version leaks a permit when a holder crashes without releasing, because nothing ever returns it (and a single counter cannot expire individual permits). A more robust design stores each holder as a member of a sorted set scored by its acquisition or expiry time, removes expired members inside the same Lua script, and compares the set size with the limit. Per-holder expiry has the same trade-off as a lock TTL: it can release a permit while a slow operation is still running. Set the TTL generously (e.g., 60 seconds for a 10-second operation) and rely on lease renewal for longer operations. The release step above only increments when the owner was actually in the set, so a duplicate release cannot inflate the count.
