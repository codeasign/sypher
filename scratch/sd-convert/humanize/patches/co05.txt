**AWS MemoryDB for Redis**: A Redis-compatible, durable, in-memory database that uses a Multi-Paxos consensus protocol for replication and durability. Each write is replicated to a quorum of nodes and durably stored in a transaction log. MemoryDB provides Redis semantics with the durability of a consensus-based system.
====
**AWS MemoryDB for Redis**: A Redis-compatible, durable, in-memory database. Instead of relying on Redis's asynchronous replication, MemoryDB writes each update to a distributed multi-AZ transaction log and acknowledges it only once it is durably stored there, so it gets the durability that a replicated-log design provides while keeping Redis semantics.

**Amazon DynamoDB**: Uses a quorum-based replication system (N=3, W=2, R=2) that provides configurable consistency. DynamoDB's internal replication is based on the Dynamo paper's quorum system, not a full consensus protocol. It uses hinted handoff and version vectors for conflict resolution.
====
**Amazon DynamoDB**: Each partition is replicated across three Availability Zones, with a leader per partition that replicates writes using Multi-Paxos, according to AWS's published description of the service. The original Dynamo paper (2007) described a different, leaderless quorum design with hinted handoff and version vectors, which Cassandra and Riak followed.
