Write latency includes the cross-region RTT to the farthest follower that the leader needs for quorum. With a 3-node cluster across US East, US West, and EU West, write latency is approximately 80ms (the time to reach EU West and back).
====
Write latency includes the cross-region round trip to the slowest follower that the leader needs for quorum. With a 3-node cluster across US East, US West, and EU West, the leader needs only one follower besides itself, so a write costs about the round trip to the nearer follower (tens of milliseconds to US West), and about 80ms or more if EU West is the one needed.

Redis Sentinel uses a gossip-based consensus (not Raft/Paxos but a custom protocol) to monitor Redis instances and perform failover.
====
Redis Sentinel uses gossip to share observations and a Raft-inspired election among the sentinels (not a full Raft or Paxos log) to pick which sentinel performs a failover.

Kafka's availability depends on ZooKeeper's consensus guarantees.

In this classic architecture, Kafka's availability depends on ZooKeeper's consensus guarantees. (Newer Kafka versions replace ZooKeeper with KRaft, which runs Raft inside Kafka's own controller quorum.)

<<<<
Algorithms that use clock timestamps for ordering (Paxos with wall-clock proposal numbers) are vulnerable to clock skew.
====
Paxos does not need synchronized clocks for safety. If proposal numbers are derived from wall-clock time, skew can cause proposers to keep out-numbering each other, which hurts liveness, but never correctness. Systems that use time-based leases for reads, however, do depend on bounded clock drift.

<<<<
The primary data center can operate independently if both secondary data centers become unreachable (the primary's 2 nodes plus the leader form a quorum of 3). Write latency is bounded by the closest secondary data center.
====
Note the limit of this layout: with only 2 of the 5 nodes in the primary data center, the primary cannot form a quorum on its own if the other data centers become unreachable. Placing 3 of the 5 nodes in the primary would allow that, but then losing the primary data center loses the quorum. Write latency is bounded by the closest secondary data center.
