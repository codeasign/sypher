Given current working set of 200 GB on a 256 GB instance with 30 GB/month data growth, you have approximately 2 months before cache misses start degrading performance. In 4 months, the working set exceeds RAM entirely. The vertical option is an r7g.8xlarge (512 GB) at $2,400/month, which buys another 8 months. The horizontal option is a sharded architecture with 4 nodes (4x r7g.xlarge at $800/month total), plus application changes for query routing. I would recommend immediately adding a Redis cache layer to reduce the working set pressure, buying 3-4 months for the horizontal migration. Start the sharding design in month 2, implement in months 3-5, and dual-write in month 6, switching over before month 8 when the vertical ceiling is reached.
====
Given a current working set of 200 GB on a 256 GB instance with 30 GB/month of growth, the working set is already about 78% of RAM and reaches 100% in under 2 months, so cache misses start degrading performance almost immediately. The vertical option is an r7g.16xlarge (512 GB) at about $2,500/month, which buys roughly 7-9 more months. The horizontal option is a sharded architecture with 4 nodes (4x r7g.4xlarge with 128 GB each, about $2,500/month total), plus application changes for query routing. I would recommend immediately upgrading or adding a Redis cache layer to relieve the memory pressure, buying time for the horizontal migration. Start the sharding design in month 2, implement in months 3-5, and dual-write in month 6, switching over before month 8 when the vertical ceiling approaches.
