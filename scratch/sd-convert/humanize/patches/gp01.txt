**Question 3:** Why does pull gossip converge more slowly than push gossip in most scenarios?

**Answer:** In pull gossip, only the requesting node learns new information. The node that receives the request does not learn anything unless the protocol is push-pull. This means each exchange teaches only one node instead of two. Additionally, pull gossip requires two messages per exchange (request + response) compared to push gossip's single message, so the effective convergence rate is roughly half.
====
**Question 3:** How do push and pull gossip differ in how fast they spread a new piece of information, and why do many systems use push-pull?

**Answer:** Push is fast at the start and slow at the end. While few nodes know the rumor, every push tells an uninformed node, but once most nodes know it, random pushes mostly hit nodes that are already informed, so the last stragglers take a while. Pull is the opposite: early on most pulls ask a peer that has nothing new, but once most nodes know the rumor a random pull almost always finds it. Push-pull combines both behaviors in one exchange, so it spreads quickly in the early phase and finishes quickly in the late phase, at the cost of sending state in both directions.
