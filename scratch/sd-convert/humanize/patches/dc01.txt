**Counter tombstone**: A record that a counter was decremented, preserved to prevent re-application of the same decrement during merge. Why it matters: without tombstones, merging replicas can double-apply decrements and undercount. Tombstones make the state grow unboundedly unless garbage-collected.
====
**Base value compaction**: Folding the contributions of retired nodes into one number so that a counter's state does not grow with every node ID it has ever seen. Why it matters: CRDT counters keep one entry per node, so churning through instance IDs makes the state grow. Compaction is only safe once every replica has merged those entries, so it needs coordination.

The API gateway hashes `post_id` using consistent hashing across 64 counter shards. `hash("abc123") % 64 = 7`. The request is forwarded to shard 7, a Redis instance dedicated to approximately 1/64th of all post counters.
====
To avoid a single hot key, each post's counter is split into 64 sub-counters (slots) spread over the counter shards. The API gateway picks a slot for this request, for example `hash(user_id) % 64 = 7`. The request is forwarded to the Redis instance that holds `likes:abc123:slot7`.
