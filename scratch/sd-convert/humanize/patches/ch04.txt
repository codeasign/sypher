**Why it happens**: The hash function has a distribution bias. CRC32, for instance, has known patterns that cause clustering in the hash space. Even MurmurHash3 can produce uneven distributions at certain virtual node counts.
====
**Why it happens**: A weak hash function (or a good one applied to highly structured inputs such as sequential node names) can cluster positions in the hash space. Even a good hash function gives uneven results when there are too few virtual nodes, and unweighted virtual nodes ignore differences in node capacity.
