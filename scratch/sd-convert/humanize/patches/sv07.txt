2. Client uploads each part individually: PUT /uploads/upload_id/part/1 with the part data.
3. The service receives the part bytes and streams them directly to S3 multipart upload using the S3 SDK. The service does not buffer the entire part in memory; it uses streaming upload. (An even better stateless variant: the service returns a pre-signed S3 URL for each part, and the client uploads straight to S3 so the file bytes never pass through the service at all.)
4. After the part is uploaded to S3, the service records it in a Redis set: `SADD uploads:upload_id:parts 1`. A set is used instead of a counter so that a retried part is not counted twice.
5. Client polls GET /uploads/upload_id/progress to get the part count (`SCARD` of the set). Polling returns `{completed: 12, total: 50, status: "in_progress"}`.
