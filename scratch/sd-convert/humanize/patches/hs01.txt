Practical limits come from coordination overhead: every new node adds communication cost. In well-designed systems that cost grows slowly (roughly logarithmically with tree-shaped or gossip-style communication), while all-to-all designs grow linearly or worse.

A poor shard key creates hot spots: one shard handling 80% of traffic while others sit idle. Consistent hashing minimizes how much data moves when nodes are added or removed, but it does not fix a hot key.

====
Each PostgreSQL connection is a separate server process that typically uses several MB of RAM (5-10 MB is a common estimate), so 100 connections can consume 0.5-1 GB before executing a single query.
