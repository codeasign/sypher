Consider a cluster of N nodes where exactly one node (the source) knows the information. If the source repeatedly selects the same peer (which already knows the information), no new nodes learn. In the next round, the same scenario repeats. This can continue indefinitely.
====
Consider any round in which some subset of nodes is informed. Every informed node picks its peers at random, and there is a nonzero probability that all of those picks land on nodes that are already informed, so no new node learns anything in that round. That can happen again in the next round, and the next, so for every finite k there is a nonzero probability that more than k rounds are needed. No deterministic bound exists, even though long delays are exponentially unlikely.

**Model Answer:**

**A design caveat first:** This is a numeric exercise. In a real system, partition leadership needs a consistent view, which is why Kafka distributes it through its controller (ZooKeeper-based earlier, KRaft consensus now) rather than gossip. Gossip is only suitable here as a fast way to spread hints or caches of metadata whose authority stays with a consensus-backed component, and receivers should validate leadership with epochs (a stale leader epoch is rejected).

**Gossip configuration:**
- Interval: 100ms (fast convergence required)
