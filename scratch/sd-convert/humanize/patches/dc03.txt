**Redis version upgrade**: Deploy a new Redis cluster running the target version alongside the old cluster. Dual-write for 5 minutes, then cutover. No data loss, no downtime.
====
**Redis version upgrade**: Use the standard rolling approach. Upgrade the replicas first, fail over so an upgraded replica becomes the primary (replication keeps the data in sync, so no counter value is lost), then upgrade the old primary. Replicas of a newer version can usually follow an older primary, so check the release notes for the supported order.
