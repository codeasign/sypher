Each node holds a subset of the data, acts as primary for that subset, and replicates to other nodes for durability. Writes scale horizontally because each node handles its own partition.
====
Each node holds a subset of the data. In some systems (MongoDB sharded clusters) each partition has one primary. In leaderless systems (Cassandra, DynamoDB) any of a partition's replicas can accept writes. Either way, writes scale horizontally because each partition's traffic is handled by its own nodes.

Kubernetes is the canonical example: worker pods are stateless, while the control plane (etcd, API server, scheduler) is stateful. The compute layer handles ephemeral work; the control plane holds the cluster state.
====
Kubernetes is the canonical example: application pods are stateless, while etcd holds all cluster state. The API server and scheduler are themselves stateless processes that read and write that state in etcd. The compute layer handles ephemeral work; the control plane holds the cluster state.
