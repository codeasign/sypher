Network Load Balancer handles TCP termination at the edge (millions of packets per second). Application Load Balancer handles HTTP routing, path-based routing, and TLS termination. The NLB shields the ALB from DDoS attacks and provides static IP addresses for DNS.
====
Network Load Balancer handles layer 4 traffic at the edge (millions of packets per second) and provides static IP addresses per availability zone. Application Load Balancer handles HTTP routing, path-based routing, and TLS termination. Placing the NLB in front of the ALB is a common pattern when clients need fixed IPs (for allow-lists) but you still want layer 7 routing. DDoS protection comes from AWS Shield and a WAF rather than from the NLB itself.

====
Data is sharded across 16,384 hash slots. Redis Cluster performs automatic failover itself, promoting a replica when a primary stops responding (Sentinel is only needed for non-clustered setups). The cluster provides session storage, cache, and rate-limit counters.

Consumers in each region read from their local broker. This provides exactly-once semantics for order processing and event sourcing.
====
Consumers in each region read from their local broker. Within one cluster, idempotent producers and transactions can provide exactly-once processing. Cross-region replication with MirrorMaker 2 is at-least-once, so consumers of replicated topics must be idempotent.

<<<<
Write-behind cache batches updates (higher throughput, risk of stale data).
====
Write-behind cache batches updates to the database (higher throughput, but writes can be lost if the cache node fails before flushing).

<<<<
Kafka allows up to one consumer per partition, so if you need more workers, increase partition count during topic creation.
====
Within a consumer group, Kafka assigns each partition to at most one consumer, so the partition count caps your parallelism. Choose it with growth in mind: you can add partitions later, but doing so changes which partition a given key maps to.
