Clock skew is the primary threat to lease correctness. If Node A's clock is 5 seconds behind Node B's clock, a lease that expires at T=100 on Node B expires at T=95 on Node A. Clock skew is the primary threat to lease correctness. Suppose Node A's clock is 5 seconds behind Node B's. When Node B's clock reads 100 and the lease has expired by Node B's reckoning, Node A's clock reads only 95, so Node A still believes it holds the lease for another 5 seconds. Well-designed lease systems measure elapsed time locally with a monotonic clock, so what matters is clock rate drift more than absolute offset, and they add a safety margin. Clock synchronization via NTP with tight bounds is still essential, and fencing tokens protect the data even when a lease check goes wrong.

Let:
  L = lease duration in seconds
  S = maximum clock skew between any two nodes (seconds)
  R = maximum network round-trip time (seconds)
  P = processing time for lease renewal (seconds)

Safe lease duration:
  L > S + R + P + margin

For a typical deployment with NTP synchronization:
  S = 200ms (NTP with local time server, tight bound)
  R = 50ms (p99 intra-datacenter latency)
  P = 10ms (lease renewal processing)

  L > 200 + 50 + 10 = 260ms
  With 50% margin: L > 390ms

  Practical minimum: L = 1 second (includes margin and operational tolerance)
  Recommended production: L = 5-10 seconds

If NTP is unavailable (air-gapped deployment):
  S = 5,000ms (5 seconds drift possible without NTP)
  R = 50ms
  P = 10ms

  L > 5,000 + 50 + 10 = 5,060ms
  With 50% margin: L > 7,590ms
  Practical minimum: L = 10 seconds
====
Let:
  L = lease duration in seconds
  S = maximum clock error between any two nodes over one lease (seconds)
  R = maximum network round-trip time (seconds)
  P = processing time for lease renewal (seconds)

Safety rules:
  Leader: treat the lease as expired at (t_sent + L - S), where t_sent is the
          local time at which the renewal request was SENT
  Others: do not grant the lease to anyone else until (last_grant_time + L + S)
  Together these keep two leaders from overlapping even with skew S.

Liveness rule (renewal must succeed before expiry):
  renewal_interval + R + P < L - S

For a typical deployment with NTP synchronization:
  S = 200ms (NTP with local time server, tight bound)
  R = 50ms (p99 intra-datacenter latency)
  P = 10ms (lease renewal processing)

  With renewal every L/3, a lease of L = 1 second already satisfies
  333 + 50 + 10 < 1000 - 200, but leaves little slack for hiccups.
  Recommended production: L = 5-10 seconds

If NTP is unavailable (air-gapped deployment):
  S = 5,000ms (a large allowance, since unsynchronized clocks can differ widely)
  R = 50ms
  P = 10ms

  L must clearly exceed S plus renewal overhead, so L = 15-30 seconds is a
  reasonable minimum, and fencing tokens become even more important.
