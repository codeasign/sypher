<<<<
- Why does Cassandra use a 1-second interval while Redis uses 100ms? Cassandra prioritizes bandwidth efficiency over convergence speed. Redis prioritizes fast detection in a smaller cluster.
- Why does Redis only gossip 2-3 random entries? Redis clusters are typically smaller (under 100 nodes), and the slot bitmap requires a separate consensus mechanism. Gossip only needs to propagate health information, not full state.
====
- Why does Cassandra gossip once a second while Consul gossips every 200ms in a LAN? Cassandra's exchanges carry more state, and its failure detector (phi accrual over heartbeat arrivals) is tuned for a one-second heartbeat cadence. Consul's messages are small and piggybacked, so it can gossip more often to spread news quickly.
- Why does Redis only include a subset of nodes in each gossip section? Each ping and pong already carries a 2 KB slot bitmap, so keeping the gossip section to a fraction of the cluster bounds message size, and every node gets pinged regularly anyway. Failover decisions (replica promotion) use a separate voting mechanism with configuration epochs.
