Lagging replicas serve increasingly stale reads. Separately, if a replica is unavailable for longer than the hint window (3 hours by default in Cassandra), the writes it missed are not replayed and it needs a full repair to converge. As lag grows, the system's effective consistency degrades from "eventual" toward "eventually, after someone runs a repair."

When a node is down for extended time, the live nodes buffer hinted handoff writes. If the buffer fills, new writes are rejected. The cluster experiences reduced write capacity even though most nodes are healthy.
====
When a node is down for an extended time, the live nodes buffer hinted handoff writes. If the buffer fills or the hint window passes, hints stop being stored. Writes continue, but the down replica will miss data until it is repaired, and hint storage and replay add load on the healthy nodes.

**Synchronous replication with single leader:** A single-leader system with synchronous replication to followers does not have the PACELC trade-off in the same way. All writes go through the leader, so there is no write conflict. The trade-off is about read scalability, not consistency vs latency.

**Synchronous replication with single leader:** A single-leader system still faces the latency-versus-consistency choice: synchronous replication adds write latency, and reads from followers can be stale. What it avoids is write conflicts, because all writes go through the leader.
