**Disruptive scaling**: The process of upgrading an instance type while the application is running. In most cloud environments, changing instance types requires stopping the instance, which terminates all network connections and in-memory state. Workarounds include blue-green deployment (run both instances side by side, switch traffic) or live migration (GCP preemptible instance migration).
====
**Disruptive scaling**: Changing an instance type in a way that interrupts the running application. In most cloud environments, changing instance types requires stopping the instance, which terminates all network connections and in-memory state. Workarounds include blue-green deployment (run both instances side by side, then switch traffic) or live migration (which GCP offers for most VM types).

**Super-linear cost curve**: The phenomenon where a 2x larger instance costs more than 2x the price. AWS `c7g.medium` (1 vCPU, 2 GB) costs $0.0414/hour. `c7g.16xlarge` (64 vCPU, 128 GB) costs $2.4864/hour, 60x the cores for 60x the price (roughly linear). But memory-optimized instances show worse ratios: `r7g.large` (2 vCPU, 16 GB) at $0.1008/hour versus `r7g.16xlarge` (64 vCPU, 512 GB) at $2.4256/hour, 24x the price for 32x the RAM. The ratio varies by family.
====
**Super-linear cost curve**: The phenomenon where a machine twice as large costs more than twice as much. Inside one cloud instance family, on-demand pricing is close to linear: AWS `c7g.medium` (1 vCPU, 2 GB) costs about $0.036/hour and `c7g.16xlarge` (64 vCPU, 128 GB) about $2.32/hour, which is 64x the cores for 64x the price. The super-linear jumps show up when you leave the mainstream families: high-memory (`u-*`) and bare-metal instances cost far more per GB of RAM than `r7g`, and per-core software licenses multiply the total cost of every core you add.

Vertical scaling has a non-linear cost curve. Doubling capacity rarely doubles cost. Sometimes it more than doubles.
====
Vertical scaling looks linear on the price sheet but is often super-linear in practice. Inside one instance family, doubling the size doubles the price. The extra cost appears when you outgrow the family: high-memory and bare-metal instances, per-core software licenses, and the premium storage needed to keep up.

The linear pricing of most instance families is a relatively recent development. Five years ago, the largest instances had a significant per-unit premium. Today, the cost decision often favors vertical scaling for small-to-medium workloads.
====
Linear pricing within a family means the cost question is mostly about how much capacity you need, not which size you pick. For small-to-medium workloads, that often favors one bigger machine over the operational overhead of several smaller ones.
