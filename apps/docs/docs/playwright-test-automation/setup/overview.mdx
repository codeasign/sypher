# Setting Up Your Playwright Test Environment

⏱ 15 minutes · Difficulty: Beginner

## What You Will Learn

By the end of this lesson you will be able to:

- Fork the system under test — a 4-role RBAC healthcare app — so you end up with a repo you actually own
- Get its backend (Express + SQLite) and frontend (React) installed, seeded, and running
- Install Playwright and let it generate a `playwright.config.ts` for you
- Set a permanent `baseURL` so every test in this course can just use relative paths
- Verify the whole environment end to end before you write a single test

## Why This Matters

Every module in this course — locators, fixtures, network mocking, the RBAC permission matrix, CI — runs against the same running application: [`rbac-healthcare-system`](https://github.com/codedbyabhishekc/rbac-healthcare-system), a 4-role (admin/doctor/nurse/patient) healthcare app with a real Express API and SQLite database behind it. That's a deliberate choice, not an accident of convenience. You're not testing a disposable to-do-list demo here — you're testing a small but real system with authentication, role-based permissions, and a documented (and, as you'll see, not fully implemented) permission matrix. Every mistake and every debugging technique later in this course happens against this one app, so the setup you do here is the foundation for all twenty-five modules.

Get the setup wrong — wrong `baseURL`, an unseeded database, a backend that silently isn't running — and every test you write afterward fails for the wrong reason. You will spend your first hour of Playwright convinced your locators are broken when the real problem is that `localhost:3002` isn't serving anything. A careful, verified setup now saves you that entire class of confusion later.

## The Problem

You write your first test:

```typescript
await page.goto('/login');
await page.getByLabel('Username').fill('admin');
```

It times out. `page.goto('/login')` never resolves to anything, because Playwright does not know what `/login` is relative *to*. Without a `baseURL`, `page.goto('/login')` tries to navigate to a page literally named `/login` with no host at all, and fails immediately. This is the single most common first-hour Playwright error, and it has nothing to do with locators.

## The Concept

A Playwright test run really comes down to three moving pieces, and all three have to be up and correctly wired together before a single `expect()` can pass:

1. **The backend** — Express + SQLite, serving the REST API and Swagger docs, seeded with role accounts and sample data.
2. **The frontend** — the React app that actually renders the login screen and role dashboards your tests interact with.
3. **`playwright.config.ts`** — the file that tells every test in the suite where the frontend lives, via `use: { baseURL: ... }`. Get this one right and `page.goto('/login')` just works everywhere, in every test file, without you ever repeating the full URL.

Set `baseURL` once, in one place, and every test file in every module from here on can just write `page.goto('/login')`, `page.goto('/dashboard')`, and so on — never a full URL. That's why it's worth getting right, permanently, in this very first lesson.
