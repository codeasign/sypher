# Setting Up Your Playwright Test Environment: Review

⏱ 3 minutes

## Key Takeaways

- You fork `rbac-healthcare-system` rather than clone it, so you actually own a repo that a later continuous-integration workflow can run against.
- The backend (`:5000`, Express + SQLite, Swagger at `/api-docs`) and frontend (`:3002`, React) are two separate servers, and you're the one who starts them and leaves them running for every module in this course.
- `npm run seed` gives you the fixed set of role accounts and sample data (3 Admins, 8 Doctors, 7 Nurses, 15 Patients, 22 Appointments, 15 Medical Records) that every later module's examples count on existing.
- `baseURL: 'http://localhost:3002'` in `playwright.config.ts` only needs to be set once, permanently, and after that every test can write relative paths like `page.goto('/login')` instead of full URLs.
- Before moving on, make sure both servers respond and `npx playwright test --list` runs cleanly. Every later module assumes this environment is already working.

## Recap in 60 Seconds

If you only remember three things:

1. Fork the repo, then get the backend running on `:5000` and seeded, and the frontend running on `:3002`.
2. Set `baseURL: 'http://localhost:3002'` once in `playwright.config.ts`, and never hardcode the URL inside a test.
3. Before you write your first real test, verify everything with `npx playwright test --list` and a direct `curl` to both servers.
