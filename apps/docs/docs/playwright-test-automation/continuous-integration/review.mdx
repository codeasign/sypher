# Continuous Integration for Playwright Tests — Review

⏱ 4 minutes

## Key Takeaways

- This module is where forking `rbac-healthcare-system` instead of cloning it back during setup finally pays off — a clone would have left you with no push access and no Actions tab to run a workflow against.
- The `webServer` config from the project structure and config lesson needs no CI-specific changes at all, because GitHub Actions sets `CI=true` automatically, which makes `reuseExistingServer: !process.env.CI` start fresh backend and frontend processes on every run.
- `actions/cache` for `~/.cache/ms-playwright` and the three `node_modules` directories (root, `backend/`, `frontend/`) turns most CI runs into cache hits, skipping browser downloads and `npm ci` entirely.
- `actions/upload-artifact` with `if: always()` for the HTML report and `if: failure()` for traces is what makes a red run in the Actions tab debuggable without reproducing the failure locally.
- Splitting a fast `@smoke`-tagged job for pull requests from the full suite on `main` — built directly on the test organization and tagging lesson's tagging — gives quick PR feedback without weakening the safety net on the branch that matters most.

## Recap in 60 Seconds

If you only remember three things:

1. You forked back during setup for exactly this reason — so this module's workflow file would have somewhere to push to, and an Actions tab to actually run in.
2. `npx playwright test` in CI is the same single command as locally — `webServer` starts both servers itself because `CI=true`, and no manual service block is needed.
3. Cache `node_modules` and `~/.cache/ms-playwright` between runs, and always upload the HTML report and traces so a failure is debuggable from the Actions tab alone.

## Try It

Extend the workflow from this module: add a `--project=firefox` matrix entry to the `smoke` job so pull requests run the `@smoke`-tagged tests against both Chromium and Firefox in parallel, using GitHub Actions' `strategy: matrix:` syntax. Push it to your fork, open a pull request against your own `main`, and confirm two separate smoke runs appear in the Actions tab — one per browser — each uploading its own report artifact.
