# Authentication and Session State — Review

⏱ 5 minutes

## Key Takeaways

- Programmatic login (calling `POST /api/auth/login` directly) gets you a valid JWT without ever touching a browser, and it's far faster and more reliable than driving the login form through every single test.
- `storageState` is a per-origin snapshot of cookies and `localStorage` — for a JWT-in-localStorage app like this one, it only captures a real session if a page has actually visited the frontend's origin and written the token there first.
- `globalSetup` in `playwright.config.ts` runs once before the whole test run, not once per test or file, which makes it the right place to authenticate all 4 roles exactly once and write out 4 separate `playwright/.auth/*.json` files.
- Defining 4 Playwright `projects`, each with its own `use: { storageState }`, is what lets a spec file run "as a doctor" or "as a patient" via `--project=<role>`, with zero login code inside the test itself.
- Storage state files contain live credentials, so they need to be `.gitignore`d, kept per-role (never shared across roles "for convenience"), and regenerated any time the backend is reseeded.

## Recap in 60 Seconds

If you only remember three things:

1. Authenticate each of the 4 roles once via the real API inside `globalSetup`, and save the result as `storageState` — never inside individual tests or fixtures.
2. For a `localStorage`-based JWT app, you still need a real page navigation before capturing state, since `localStorage` only exists per-origin once a page has actually visited that origin.
3. One Playwright `project` per role, each pointing at its own `.auth/<role>.json`, is what lets `npx playwright test --project=doctor` run an entire spec file already logged in as a doctor.

## Try It

Try extending `globalSetup.ts` and `playwright.config.ts` to add a 5th, negative-auth "project": an `unauthenticated` project with no `storageState` at all (or an explicitly empty one). Then write a spec that navigates to `/dashboard` under that project and asserts the app redirects back to `/login` — a test that only exists because this lesson's pattern makes "no session" just as easy to set up as "a doctor's session."
