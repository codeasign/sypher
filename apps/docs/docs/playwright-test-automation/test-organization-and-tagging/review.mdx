# Test Organization and Tagging: Review

⏱ 4 minutes

## Key Takeaways

- `test.describe` groups related specs (like all of a role's dashboard tests) into a named unit that reads clearly in code and in the HTML reporter, and that `--grep` can target as a whole.
- `test.step` names the phases inside a single test, so trace viewer shows a readable, collapsible timeline instead of one undifferentiated sequence of actions when a longer flow fails.
- Tags are plain `@word` tokens embedded in a test's title (or passed via the structured `tag` option in newer Playwright versions). There's no separate tag registry, just text that `--grep` matches against.
- `--grep @smoke` runs only the tagged fast subset; `--grep-invert @regression` runs everything except the tagged slow subset. These are two different filters over the same one suite, not two separate suites.
- The RBAC suite splits concretely: roughly a dozen `@smoke` tests, one or two core flows per role, gate every pull request in under a minute, while the full permission matrix from the RBAC permission-matrix lesson, every visual baseline from the visual and snapshot testing lesson, and the complete cross-browser matrix from the cross-browser and responsive testing lesson run nightly under `@regression`.

## Recap in 60 Seconds

If you only remember three things:

1. Use `test.describe` to group specs and `test.step` to name phases inside one test. Both are about readability, in the reporter and in trace viewer.
2. Tag tests `@smoke` for a fast, representative subset and `@regression` for full depth, then filter with `npx playwright test --grep @smoke` or `--grep-invert @regression`.
3. Keep the smoke subset small on purpose (a dozen or so tests across all four RBAC roles) and let the nightly run carry the permission matrix, visual snapshots, and cross-browser coverage that would otherwise slow down every pull request.

## Try It

Extend the RBAC smoke suite with one more role-specific case: tag a test that confirms a nurse cannot create medical records (an action the permission matrix reserves for doctors only) `@smoke` and `@regression` both, the same way this lesson's "patient cannot view all users" and "doctor cannot view the admin user list" checks do. Run `npx playwright test --grep @smoke` and confirm your new test appears in the output alongside the others, then run `npx playwright test --grep @regression` and confirm it appears there too.
