The setup module installed `pytest` and `httpx` just enough to run one script. This module turns that into an actual test project — real config, a real test file, and your first test that `pytest` itself runs and reports on, instead of a script you run with `python3` and read by eye.

## Project structure

Inside `rbac-api-tests/` (the folder from the setup module, with `venv` already active), you don't need much structure yet:

```bash
rbac-api-tests/
├── venv/
├── pytest.ini
└── test_health.py
```

pytest's own convention is what makes this work with almost no configuration: any file named `test_*.py` (or `*_test.py`) is automatically discovered, and inside it, any function named `test_*` is automatically treated as a test. There's no registration step, no import of a test suite object — naming the file and function correctly *is* the registration.

## Configuring pytest

Create `pytest.ini` in the project root:

```ini
[pytest]
testpaths = .
python_files = test_*.py
python_functions = test_*
```

`testpaths` tells pytest where to look for tests (`.` means "this whole project"); `python_files` and `python_functions` spell out the naming convention explicitly, even though they match pytest's defaults — worth having in the file so the convention is documented, not just assumed. Some projects use `pyproject.toml` instead, with the same settings under a `[tool.pytest.ini_options]` table:

```toml
[tool.pytest.ini_options]
testpaths = ["."]
python_files = ["test_*.py"]
python_functions = ["test_*"]
```

Either works identically — this course sticks with `pytest.ini` for its own examples since it's the more common one to reach for in a project this small.

## Your first test

Create `test_health.py`:

```python
import httpx

BASE_URL = "http://localhost:5000"


def test_health_check_returns_ok():
    response = httpx.get(f"{BASE_URL}/health")

    assert response.status_code == 200
    assert response.json() == {"status": "OK", "message": "Server is running"}
```

`httpx.get(...)` sends a real `GET` request and blocks until the response comes back — this is httpx's synchronous API, the simplest way to call it, and exactly what you used in the setup module's smoke check. `response.status_code` is an integer; `response.json()` parses the response body as JSON and returns a Python `dict`. The two `assert` statements are the entire test — `assert` is a plain Python keyword here, not a special testing function, and that's deliberate: pytest doesn't require a special assertion library the way some frameworks do.

## Running it

With the RBAC server still up from the setup module, run:

```bash
pytest
```

You should see something like:

```bash
======================== test session starts =========================
collected 1 item

test_health.py .                                                 [100%]

========================= 1 passed in 0.05s ==========================
```

That single `.` represents your one passing test. Run `pytest -v` instead for a more readable, one-line-per-test output:

```bash
test_health.py::test_health_check_returns_ok PASSED               [100%]
```

## Watching a test actually fail

It's worth seeing pytest's failure output at least once before you're relying on it to tell you something's wrong. Temporarily change the assertion to something false:

```python
assert response.status_code == 999
```

Run `pytest` again, and instead of a quiet failure, you get a detailed breakdown:

```bash
    def test_health_check_returns_ok():
        response = httpx.get(f"{BASE_URL}/health")

>       assert response.status_code == 999
E       assert 200 == 999
E        +  where 200 = <Response [200 OK]>.status_code
```

pytest rewrites plain `assert` statements at import time so failures show you both sides of the comparison automatically (`200 == 999`) and exactly which expression produced each value — no special `assertEqual`-style method needed, unlike some other languages' test frameworks. Put the assertion back to `== 200` before moving on.

## Try it

Add a second test function, `test_login_with_valid_credentials`, to `test_health.py`, sending the same login request from the setup module (`POST /api/auth/login` with `admin`/`admin123`) and asserting the status code is `200` and `response.json()["user"]["role"] == "Administrator"`. Run `pytest -v` and confirm both tests show up and pass independently.
