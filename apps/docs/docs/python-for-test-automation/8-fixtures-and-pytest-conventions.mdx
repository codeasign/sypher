Look back at the login test from earlier — logging in as `nurse1` took four lines, repeated inside that one test function. Now imagine five different tests that all need a logged-in nurse before they can do anything else. Copy-pasting that setup into every single one is exactly the kind of repetition pytest gives you a real tool to avoid: the **fixture**.

## What a fixture is

A fixture is a function that provides setup data to a test, without the test having to build that data itself. You mark it with `@pytest.fixture`, and pytest wires it up automatically — any test that lists the fixture's name as a parameter gets whatever the fixture returns, no explicit calling required.

```python
import pytest
import requests

@pytest.fixture
def logged_in_nurse():
    response = requests.post(
        "http://localhost:5000/api/auth/login",
        json={"username": "nurse1", "password": "nurse123"},
    )
    return response.json()
```

`@pytest.fixture` is a **decorator** — a line starting with `@` placed right above a function, which tells pytest "treat this function specially." You don't need to know how decorators work under the hood to use one; just recognize the pattern: `@pytest.fixture` above a function means "this function provides setup data to tests."

## Using a fixture in a test

Now any test that wants a logged-in nurse just asks for it by name, as a parameter:

```python
def test_nurse_token_is_present(logged_in_nurse):
    assert "token" in logged_in_nurse
    assert len(logged_in_nurse["token"]) > 0


def test_nurse_login_response_has_no_error(logged_in_nurse):
    assert "error" not in logged_in_nurse
```

Neither test calls `logged_in_nurse()` directly, and neither repeats the login request — pytest sees the parameter name `logged_in_nurse`, matches it to the fixture with that name, runs it, and hands the result in. Both tests get a fresh login without either one containing the setup code itself.

Run `pytest` and both pass, each having received its own call to the fixture:

```text
collected 2 items

test_fixtures.py ..                                                    [100%]

2 passed in 0.31s
```

## Why this matters beyond just "less typing"

Beyond saving retyping, fixtures keep setup in exactly one place. If the login endpoint's request shape ever changes, you update the fixture once, and every test using it is automatically fixed too — instead of hunting down every test that copy-pasted the old login code.

## Try it

Write a fixture called `logged_in_admin` that logs in with `"admin"` / `"admin123"` and returns the response JSON. Then write a test called `test_admin_token_is_present` that takes `logged_in_admin` as a parameter and asserts `"token" in logged_in_admin`. Run `pytest` and confirm it passes.
