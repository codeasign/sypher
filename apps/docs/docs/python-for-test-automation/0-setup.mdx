If you've spent your career clicking through an app and filing bugs, this page is your on-ramp into automating that work. By the end of it, you'll have Python installed, a code editor set up, and you'll have run your very first `.py` file on your own machine. That's it — no prior coding experience needed.

## Install Python

Head to [python.org](https://python.org/downloads) and download the latest stable version for your operating system.

1. Run the installer. On Windows, make sure you tick the checkbox that says **"Add Python to PATH"** before clicking Install — this is the single most common thing people forget, and skipping it means your terminal won't be able to find Python afterward. On macOS and Linux this step isn't needed.
2. Once it's done, open a terminal (Command Prompt, PowerShell, or the terminal inside VS Code once you install it below) and check it worked:

```bash
python --version
```

On some systems (mostly macOS and Linux) the command is `python3` instead of `python`. Whichever one prints a version number like `Python 3.12.4` is the one you'll use for the rest of this course.

`pip` (Python's package installer) comes bundled with Python — it's the tool you'll use to install pytest and, later, the `requests` library. Confirm it's there too:

```bash
pip --version
```

**Quick gloss:** Python is what's called an "interpreted" language — you write a `.py` file, and Python reads it top to bottom and runs it directly, no separate compile step. That's part of why it's such a common choice for test automation: you can write a test, run it, and see the result in seconds.

## Set up Visual Studio Code

You can technically write Python in any text editor, but **Visual Studio Code (VS Code)** is one of the most widely used editors for Python, and it has excellent Python support once you add one extension.

1. Download it from [code.visualstudio.com](https://code.visualstudio.com) and install it like any other application.
2. Open a folder in VS Code (File → Open Folder) to start a project — VS Code organizes everything around folders rather than single files.
3. Open the Extensions panel (the icon that looks like four squares on the left sidebar), search for **Python** (the official one published by Microsoft), and click Install.

That one extension gives you everything you need to start: syntax highlighting, autocomplete, and — importantly for later — the ability to run and debug tests directly from inside the editor. You don't need to configure anything about it right now; just having it installed is enough to get the benefit.

## Run your first .py file

Let's prove all of this works. Create a new folder anywhere on your computer, open it in VS Code, and create a file called `hello.py` with this in it:

```python
tester_name = "Alex"
app_under_test = "rbac-healthcare-system"

print(f"{tester_name} is starting to automate tests for {app_under_test}")
```

Unlike some languages, Python doesn't need a separate compile step — you run the `.py` file directly. In your terminal, inside the folder where you saved `hello.py`, run:

```bash
python hello.py
```

You should see your message printed to the terminal. Congratulations — you just wrote and ran your first Python file.

This course is deliberately narrow: it's a fast path to reading and writing Python test code against a real healthcare app, not a full tour of the language. Once you're comfortable automating tests here and find yourself curious about Python itself — data structures, APIs, building real applications, the deeper "why" behind the syntax — the ["Python for AI Engineers"](/docs/python-for-ai-engineers/) course on this same site is where to go for that full depth.

## Get the RBAC healthcare app backend running

Starting a few modules from now, you'll call a real API instead of just printing values to the terminal, so it's worth getting that API running now, once, rather than pausing mid-lesson later. This course only needs the **backend** — there's no browser involved anywhere in it, so you can skip the frontend entirely.

Clone the repo:

```bash
git clone https://github.com/codedbyabhishekc/rbac-healthcare-system.git
cd rbac-healthcare-system
```

Install and start the backend:

```bash
cd backend
npm install
mkdir database
```

The `database` folder has to exist before the app's first run — it's where the SQLite file gets created, and the app doesn't create the folder itself. Create a `.env` file inside `backend/`:

```bash
PORT=5000
JWT_SECRET=<any-long-random-string>
NODE_ENV=development
```

Then start it:

```bash
npm start
```

Confirm it's up by opening [http://localhost:5000/api-docs](http://localhost:5000/api-docs) — you should see the Swagger UI listing every endpoint this course calls. Leave this terminal running for the rest of the course.

In a new terminal, from `backend/`, seed the database with the test data every later module (including the capstone) works against:

```bash
npm run seed
```

This creates 3 Admins, 8 Doctors, 7 Nurses, 15 Patients, 22 Appointments, and 15 Medical Records — including the default admin login, `admin` / `admin123`, and a nurse login, `nurse1` / `nurse123`, used in several examples later on.

## Try it

Edit `hello.py` so it also declares a `role` variable set to `"nurse"` (one of the four roles in the RBAC healthcare app you'll be testing later), and update the `print` line to include it in the printed message using an f-string. Run `python hello.py` again to see your updated message.
