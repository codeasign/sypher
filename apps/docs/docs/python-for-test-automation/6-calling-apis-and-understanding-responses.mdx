So far every dict you've worked with has been typed by hand. Real test automation spends most of its time doing something different: calling a real API and checking what comes back. This page hits the RBAC healthcare app's actual backend and turns the response into a pytest assertion.

## Installing requests

`requests` is the standard library nearly every Python developer reaches for to make HTTP calls. It isn't built into Python, so install it:

```bash
pip install requests
```

## Logging in against the real API

The RBAC backend exposes a real login endpoint at `POST http://localhost:5000/api/auth/login`. Send it a username and password as JSON, and it responds with a token that proves who you are on later requests:

```python
import requests

response = requests.post(
    "http://localhost:5000/api/auth/login",
    json={"username": "nurse1", "password": "nurse123"},
)

print(response.status_code)
print(response.json())
```

```text
200
{'token': 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...'}
```

A few things worth noticing:

- `requests.post(...)` sends the actual HTTP request. Passing `json={...}` tells `requests` to encode that dict as JSON and set the right headers for you — you don't have to do that by hand.
- `response.status_code` is a number telling you how the request went. `200` means success; you'll also run into `401` (not authorized) and `404` (not found) constantly in real testing work.
- `response.json()` takes the raw response body and turns it back into a Python dict, so you can work with it like any other dict you've already seen.

## Accessing fields on the response

Once you have `response.json()` as a dict, everything from earlier applies directly:

```python
data = response.json()
token = data["token"]

print(f"received a token starting with: {token[:10]}...")
```

```text
received a token starting with: eyJhbGciOi...
```

## Pairing it with a pytest assertion

This is the actual shape of test you'll be writing from here on — call the API, then assert on what came back:

```python
def test_nurse_login_returns_a_token():
    response = requests.post(
        "http://localhost:5000/api/auth/login",
        json={"username": "nurse1", "password": "nurse123"},
    )

    assert response.status_code == 200

    data = response.json()
    assert "token" in data
    assert len(data["token"]) > 0
```

Three separate `assert` lines, each checking a different thing: the request succeeded, the response has the field you expect, and that field actually has a value. If the API started returning something different — say, `access_token` instead of `token` — this test would fail immediately and tell you exactly which assertion broke, instead of you discovering it later some other way.
