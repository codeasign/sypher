Think about how you write manual test cases. You probably don't retype "log in as a user" from scratch every single time — you have a step you reuse, over and over, with different details plugged in. A function is that same idea, brought into code: a reusable test step you can call by name instead of retyping.

## Writing a function

Here's a function that builds a test user for the RBAC healthcare app:

```python
def build_test_user(role):
    return {
        "username": f"test_{role}",
        "role": role,
        "is_active": True,
    }
```

Breaking that down:

- `def` starts a function definition — short for "define."
- `build_test_user` is the name you'll call it by later.
- `role` in the parentheses is a **parameter** — a placeholder for whatever value gets passed in when the function is called.
- `return` hands back a value to whoever called the function.

Now instead of writing that dict by hand every time, you just call the function:

```python
nurse_user = build_test_user("nurse")
doctor_user = build_test_user("doctor")

print(nurse_user)
print(doctor_user)
```

```text
{'username': 'test_nurse', 'role': 'nurse', 'is_active': True}
{'username': 'test_doctor', 'role': 'doctor', 'is_active': True}
```

One function, called twice with different input, no retyping. That's the entire point — the same reason you'd rather have one reusable manual test step than five slightly different copies of it.

## Why real test projects need more than one file

A single file works fine for a quick experiment, but real test projects never stay that way for long. You'll end up with helper functions like `build_test_user`, the test files that use them, and eventually shared setup code — and none of that belongs jammed into one giant file. Python's answer to this is `import`.

## Splitting code across files

Say you put `build_test_user` in its own file called `helpers.py`:

```python
# helpers.py
def build_test_user(role):
    return {
        "username": f"test_{role}",
        "role": role,
        "is_active": True,
    }
```

From another file in the same folder, you can pull that function in with `import`:

```python
# main.py
import helpers

nurse_user = helpers.build_test_user("nurse")
print(nurse_user)
```

`import helpers` brings in everything from `helpers.py`, and you reach into it with `helpers.build_test_user(...)` — the file name acts like a namespace.

If you only need one specific thing from a file, `from ... import` skips the namespace and pulls the name in directly:

```python
# main.py
from helpers import build_test_user

nurse_user = build_test_user("nurse")
print(nurse_user)
```

Both are valid. `from ... import` is the more common style once you're calling the same helper many times across a file, since you don't have to prefix it with the module name every time.
