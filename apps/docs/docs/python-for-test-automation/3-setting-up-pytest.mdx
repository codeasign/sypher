Everything so far has relied on `print()` and your own eyes to tell whether something worked. That doesn't scale — real test suites have dozens or hundreds of checks, and nobody has time to eyeball terminal output for each one. **pytest** is the tool that runs your checks for you and tells you, unambiguously, which ones passed and which ones failed.

## Installing pytest

From your terminal, run:

```bash
pip install pytest
```

Confirm it installed:

```bash
pytest --version
```

## Writing the smallest possible test

pytest has a simple rule: any file named `test_something.py`, containing a function named `test_something`, is treated as a test. Inside that function, an `assert` statement is your check.

Create a file called `test_basics.py`:

```python
def test_two_plus_two():
    assert 2 + 2 == 4
```

`assert` says "this must be true, or the test fails." Here, `2 + 2 == 4` is true, so this test passes. It's deliberately trivial — the point right now is just to see the whole loop work end to end before anything test-automation-specific gets involved.

## Running it

From the same folder as `test_basics.py`, run:

```bash
pytest
```

You'll see something like:

```text
collected 1 item

test_basics.py .                                                       [100%]

1 passed in 0.01s
```

That single `.` represents your one passing test. `collected 1 item` means pytest found one test to run; `1 passed` is your unambiguous result — no reading through printed values required.

## Reading a failure

It's worth seeing what a failure actually looks like, since this is the output you'll be staring at constantly once real tests exist. Change the assertion to something false:

```python
def test_two_plus_two():
    assert 2 + 2 == 5
```

Run `pytest` again:

```text
collected 1 item

test_basics.py F                                                       [100%]

================================== FAILURES ===================================
______________________________ test_two_plus_two _______________________________

    def test_two_plus_two():
>       assert 2 + 2 == 5
E       assert 4 == 5

test_basics.py:2: AssertionError
====================================1 failed in 0.01s ====================================
```

That `F` instead of a `.` is the first thing to look for — it tells you at a glance something broke. Below it, pytest shows you the exact line that failed and, crucially, `assert 4 == 5` — the *actual* value it computed versus what you expected. You don't have to add your own `print()` to figure out what went wrong; pytest already shows you.

## Try it

In `test_basics.py`, add a second test function called `test_role_is_string` that asserts `type("nurse") == str`. Run `pytest` and confirm you see `2 passed`. Then, just to see a failure on purpose, temporarily change it to assert `type("nurse") == int`, run `pytest` again, and read the failure output before changing it back.
