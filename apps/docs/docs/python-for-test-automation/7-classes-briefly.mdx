Everything so far has been plain functions and dicts, and that'll take you a long way. But there's one more shape worth recognizing before moving on, because you're going to see it constantly the moment you pick up a browser-automation tool like Selenium or Playwright's Python bindings: the **class**.

## What a class looks like

A class bundles data and the functions that work on that data into one thing. Here's a small one modeling a test user from the RBAC app:

```python
class TestUser:
    def __init__(self, username, role):
        self.username = username
        self.role = role

    def is_clinical_staff(self):
        return self.role in ("doctor", "nurse")
```

Breaking that down:

- `class TestUser:` starts the definition, same as `def` starts a function.
- `__init__` is a special method that runs automatically when you create a new `TestUser` — it's where you set up the object's starting data. Think of it as the "build this thing" step.
- `self` refers to the specific object being worked with. `self.username = username` says "store the `username` I was given, on this particular user."
- `is_clinical_staff` is a regular method — a function that belongs to the class and can use `self` to look at that object's own data.

Using it looks like this:

```python
nurse = TestUser("test_nurse", "nurse")
admin = TestUser("test_admin", "admin")

print(nurse.username)
print(nurse.is_clinical_staff())
print(admin.is_clinical_staff())
```

```text
test_nurse
True
False
```

Each `TestUser` you create — `nurse`, `admin` — keeps its own `username` and `role`, and `is_clinical_staff()` checks that specific object's own role.

## Why this shape matters for what's next

If you go on to automate a browser with Selenium or Playwright's Python bindings, you'll run into a pattern called a **Page Object** almost immediately — a class that represents one page of an app, with methods for the actions you can take on it (`login_page.enter_username(...)`, `login_page.click_submit()`, and so on). That's the exact same shape as `TestUser` above: data the object holds (`self.something`), and methods that act on that data. Nothing new to learn when you get there — just this same idea, applied to a page instead of a user.
