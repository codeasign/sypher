Test data is rarely a single value. A user has multiple fields. A test needs several appointments to check against. This page covers the three everyday structures you'll use to model that: `list`, `dict`, and `set`.

## Dicts — modeling one thing

A `dict` (dictionary) models one real-world thing as a set of labeled fields — exactly like a row in a spreadsheet, or a single record from the RBAC app's database. Here's a doctor, modeled as a dict:

```python
doctor = {
    "id": 5,
    "name": "Dr. Patel",
    "role": "doctor",
    "is_active": True,
}

print(doctor)
```

```text
{'id': 5, 'name': 'Dr. Patel', 'role': 'doctor', 'is_active': True}
```

Access a single field with square brackets:

```python
print(doctor["name"])
```

```text
Dr. Patel
```

Check whether a field exists with `in`:

```python
print("role" in doctor)
print("email" in doctor)
```

```text
True
False
```

And add a new field the same way you'd read one:

```python
doctor["specialty"] = "Cardiology"
print(doctor)
```

```text
{'id': 5, 'name': 'Dr. Patel', 'role': 'doctor', 'is_active': True, 'specialty': 'Cardiology'}
```

## Lists — modeling many things

A `list` is an ordered collection — useful the moment you have more than one of something, like every appointment scheduled for a day:

```python
appointments = [
    {"id": 100, "patient_id": 1, "status": "scheduled"},
    {"id": 101, "patient_id": 2, "status": "completed"},
    {"id": 102, "patient_id": 3, "status": "cancelled"},
]

print(appointments)
```

```text
[{'id': 100, 'patient_id': 1, 'status': 'scheduled'}, {'id': 101, 'patient_id': 2, 'status': 'completed'}, {'id': 102, 'patient_id': 3, 'status': 'cancelled'}]
```

Access one item by its position, counting from `0`:

```python
print(appointments[0])
print(appointments[0]["status"])
```

```text
{'id': 100, 'patient_id': 1, 'status': 'scheduled'}
scheduled
```

Add a new item to the end with `.append()`:

```python
appointments.append({"id": 103, "patient_id": 4, "status": "scheduled"})
print(len(appointments))
```

```text
4
```

And `in` works on lists the same way it worked on dicts — this time checking whether a value shows up anywhere in the list:

```python
statuses = [a["status"] for a in appointments]
print("cancelled" in statuses)
```

```text
True
```

(That line building `statuses` is a small preview of a pattern called a list comprehension — don't worry about the syntax yet, just know it collects one field out of every appointment into its own list.)

## Sets — comparing groups regardless of order

A `set` is a collection like a list, but with two differences that matter for testing: it can't contain duplicates, and it doesn't care about order. That makes it the right tool for a very specific, very common testing situation: checking that a list of *expected* values matches a list of *actual* values, when the order genuinely doesn't matter.

Say the RBAC app is supposed to give a nurse exactly these permissions, and an API response comes back with the same permissions but in a different order:

```python
expected_permissions = {"view_appointments", "schedule_appointments", "cancel_appointments"}
actual_permissions = {"cancel_appointments", "view_appointments", "schedule_appointments"}

print(expected_permissions == actual_permissions)
```

```text
True
```

If you'd compared those as lists, a different order could make an otherwise-correct comparison look wrong. As sets, order is irrelevant — `==` only cares whether the same items are present.

You can also check that one set fully contains another, useful for confirming a role has *at least* the permissions it's supposed to, even if the response includes extras:

```python
required = {"view_appointments"}
print(required.issubset(actual_permissions))
```

```text
True
```

This is exactly the kind of check that comes up constantly when comparing an API response's permissions to what a role should have — and it's most of what you'll need `set` for in testing work.

### A couple more set operations, briefly

Two more worth knowing, shown once so you recognize them later:

```python
admin_permissions = {"view_users", "delete_users", "view_appointments"}
nurse_permissions = {"view_appointments", "schedule_appointments"}

print(admin_permissions | nurse_permissions)  # union — everything in either set
print(admin_permissions & nurse_permissions)  # intersection — only what's in both
```

```text
{'view_users', 'delete_users', 'view_appointments', 'schedule_appointments'}
{'view_appointments'}
```

## Putting it together with pytest

Now that pytest exists, this is the kind of check you'd actually write as a real test rather than a printed comparison:

```python
def test_nurse_has_expected_permissions():
    expected_permissions = {"view_appointments", "schedule_appointments", "cancel_appointments"}
    actual_permissions = {"cancel_appointments", "view_appointments", "schedule_appointments"}

    assert expected_permissions == actual_permissions
```
