By now you've written helper functions like `build_test_user`, fixtures like `logged_in_nurse`, and a handful of real tests. If all of that has been living in one file, you've probably already felt it getting crowded. This page is about giving each piece its own home, the way a real pytest project on an automation team is laid out.

## A typical pytest project layout

```text
rbac-healthcare-tests/
├── requirements.txt
├── pytest.ini
├── conftest.py
├── helpers.py
├── test_appointments.py
├── test_login.py
└── test_permissions.py
```

A few things worth noticing:

- `requirements.txt` lists the packages the project needs (`pytest`, `requests`), so anyone can set up the project with one `pip install -r requirements.txt`.
- `pytest.ini` is optional configuration — things like where pytest should look for tests. A small project often doesn't need one at all; pytest's defaults (any `test_*.py` file) are usually enough.
- `helpers.py` holds plain functions used across multiple test files, like the RBAC helper functions you've already written.
- `conftest.py` is special, and it's the one genuinely new idea on this page.

## What makes `conftest.py` special

Every fixture you've written so far (`logged_in_nurse`, `logged_in_admin`) has lived in the same file as the tests using it. That works for a single file, but once you have several test files that all need a logged-in nurse, you don't want to redefine that fixture in each one.

`conftest.py` is a file pytest treats specially: any fixture defined inside it is automatically available to every test file in the same folder (and any folder below it) — **with no import needed**. That's different from a normal helper function, which you always have to `import` explicitly.

```python
# conftest.py
import pytest
import requests

@pytest.fixture
def logged_in_nurse():
    response = requests.post(
        "http://localhost:5000/api/auth/login",
        json={"username": "nurse1", "password": "nurse123"},
    )
    return response.json()


@pytest.fixture
def logged_in_admin():
    response = requests.post(
        "http://localhost:5000/api/auth/login",
        json={"username": "admin", "password": "admin123"},
    )
    return response.json()
```

## Using shared fixtures from a test file

Now any test file in the project can simply ask for `logged_in_nurse` or `logged_in_admin` as a parameter, exactly like before — pytest finds it in `conftest.py` automatically:

```python
# test_permissions.py
def test_nurse_can_view_appointments(logged_in_nurse):
    assert "token" in logged_in_nurse


def test_admin_can_view_users(logged_in_admin):
    assert "token" in logged_in_admin
```

Notice `test_permissions.py` doesn't import anything from `conftest.py` — no `from conftest import logged_in_nurse`. pytest discovers `conftest.py` on its own and makes its fixtures available to every test file nearby. This is genuinely different from how you share a plain helper function, which you always import explicitly.

## Where plain helper functions still go

Not everything belongs in `conftest.py` — only fixtures do. A plain function like `build_test_user`, which you call directly rather than receiving as a test parameter, still needs an explicit import, so it lives in an ordinary file like `helpers.py`:

```python
# helpers.py
def build_test_user(role):
    return {
        "username": f"test_{role}",
        "role": role,
        "is_active": True,
    }
```

```python
# test_login.py
from helpers import build_test_user

def test_build_test_user_sets_role_correctly():
    user = build_test_user("doctor")
    assert user["role"] == "doctor"
```

## Why this is worth doing early

You might only have two or three test files right now, so this distinction can feel like overkill. But the moment a second person joins the project, or a fixture needs to change, this structure pays off immediately: update the login logic once in `conftest.py`, and every test file using `logged_in_nurse` or `logged_in_admin` picks up the fix automatically, with nothing to rewire.

## Try it

Create a small project structure by hand (you don't need to run it, just create the files):

1. Make a `conftest.py` with a fixture called `logged_in_doctor` that logs in with `"doctor1"` / `"doctor123"` and returns the response JSON.
2. Make a `helpers.py` with a function `build_test_appointment(status)` that returns a dict with a `status` key.
3. Make a `test_doctor.py` that imports `build_test_appointment` from `helpers`, and has one test function that takes `logged_in_doctor` as a parameter (no import needed for that one) and asserts `"token" in logged_in_doctor`.

If `test_doctor.py` only needs one `import` line — for the helper, not the fixture — you've structured it correctly.
