Before you write a single test, it helps to be able to open one and understand what you're looking at. This page moves quickly through the small handful of things you'll see constantly in any Python test file: variables, a few basic types, and what it looks like when code calls a function. Then it spends real time on `print()`, because that's the tool you'll reach for constantly from here on, well before there's a proper test runner to give you a pass/fail signal.

## Variables

A variable is just a name you give to a piece of data so you can use it again later. In the RBAC healthcare app, a test might need to remember a username, a role, or whether a user is currently active:

```python
username = "dr_patel"
role = "doctor"
is_active = True
```

That's it — no special keyword needed to create one, just a name, an `=`, and a value. Python figures out the type on its own.

## Basic types

These four cover almost everything you'll see in a beginner test file:

```python
first_name = "Priya"       # str — text, always in quotes
patient_age = 34           # int — a whole number
temperature = 98.6         # float — a number with a decimal point
has_appointment = True     # bool — True or False, capitalized exactly like that
```

- **`str`** (string) — any text, wrapped in quotes. Names, roles, statuses — most of the data you'll model as a tester is a string.
- **`int`** — a whole number, like an age or a count of appointments.
- **`float`** — a number with a decimal point, like a temperature reading.
- **`bool`** — `True` or `False`. You'll see this constantly once you start writing assertions, since a check like "is this user active?" resolves to a `bool`.

## What a function call looks like

You don't need to write your own function yet — that's coming shortly — but you'll see function calls everywhere in test code, so it's worth recognizing the shape: a name, followed by parentheses, with whatever the function needs to do its job inside those parentheses.

```python
print("checking user:", username)
len(username)
```

`print(...)` and `len(...)` are both built into Python already — no setup required. Whenever you see a word immediately followed by `(`, that's a function being called.

## A dedicated look at `print()`

You're going to use `print()` constantly for the next several pages — before pytest exists to give you a real pass/fail signal, it's the only window you have into what your code is actually doing. It's worth slowing down here and seeing every shape it comes in, because these habits carry you all the way through the rest of this course.

### Printing a single value

The simplest case: confirm a variable holds what you think it holds.

```python
name = "dr_patel"
print(name)
```

```text
dr_patel
```

### Printing multiple values at once

Pass `print()` more than one thing, separated by commas, and it prints them all on one line — Python automatically puts a space between each one for you.

```python
name = "dr_patel"
age = 41
print(name, age)
```

```text
dr_patel 41
```

### Printing with a label so output is readable

Once you're printing more than one value, a bare `print(status)` gets confusing fast — you see a value with no idea what it's the value *of*. Add a short label so future-you (or a teammate reading your terminal) knows what they're looking at:

```python
status = "scheduled"
print("status:", status)
```

```text
status: scheduled
```

This is a small habit, but it's the one you'll lean on constantly while debugging a test that isn't behaving the way you expect.

### f-strings for readable formatted output

An f-string lets you build a single readable sentence out of several variables, instead of a comma-separated list. Put an `f` right before the opening quote, and anything inside `{curly braces}` gets swapped in for its real value:

```python
name = "dr_patel"
role = "doctor"
print(f"User {name} has role {role}")
```

```text
User dr_patel has role doctor
```

This is genuinely the most common way real Python code prints things — it reads like a sentence, which makes it far easier to scan a wall of terminal output and immediately understand what each line is telling you.

### Printing a dict or list directly

Once your test data is a structured group of values rather than a single variable — something you'll do a lot once you start modeling RBAC users and appointments — `print()` handles it without any extra work:

```python
user = {"username": "dr_patel", "role": "doctor"}
roles = ["admin", "doctor", "nurse", "patient"]

print(user)
print(roles)
```

```text
{'username': 'dr_patel', 'role': 'doctor'}
['admin', 'doctor', 'nurse', 'patient']
```

You don't need to fully understand dicts and lists yet — just know that `print()` shows you their full contents readably, which matters a lot once your test data stops being a single value.

### Printing to check a value mid-function

Once you start writing your own functions, it's completely normal to drop a `print()` inside one temporarily, just to see what a variable holds partway through — before you've decided whether the logic is even right yet:

```python
def build_test_user(role):
    print("role received:", role)  # temporary — remove once you understand what's happening
    username = f"test_{role}"
    return username
```

Add a print like this while you're figuring something out, and take it back out once you understand what's happening. Debug prints are a scratchpad, not something that belongs sitting in real test code once it's finished.

### Why this matters more once pytest exists

Once there's a real test runner in the picture, a failed `assert` gives you the actual pass/fail signal — you won't need `print()` to tell you whether a test passed. But `print()` doesn't go away at that point; it becomes the tool you reach for to peek at *why* something failed while you're figuring out a broken test. Keep these habits — you'll use every one of them again.

## Try it

Create a new file called `try_it.py`. Declare three variables: `role` set to `"nurse"`, `appointments_today` set to `5`, and `is_on_duty` set to `True`. Then write three separate `print()` statements: one that prints `role` on its own, one that prints all three variables at once separated by commas, and one that uses an f-string to print a full sentence like `"nurse is on duty with 5 appointments today"`. Run the file with `python try_it.py` and check the output matches what you expected.
