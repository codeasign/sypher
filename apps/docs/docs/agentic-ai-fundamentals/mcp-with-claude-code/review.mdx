# MCP with Claude Code: Review

*Reading time: 3 minutes*

## Key Takeaways

- Claude Code has a built-in MCP client: you configure servers under the `mcpServers` key in `.mcp.json` (or with `claude mcp add`), no custom client code needed
- The config format uses `command`, `args`, and optional `env` per server; Claude Code spawns each server as a child process over stdio transport
- Server config has three scopes: project (`.mcp.json`, committed), user (`claude mcp add --scope user`, all your projects), and local (`claude mcp add`, private to one project); a more specific scope wins
- Validate `.mcp.json` with `python -c "import json; json.load(open('.mcp.json'))"` and check `claude mcp list`: invalid JSON causes silent failure
- Use unique tool names that include the domain to prevent conflicts when multiple servers define similarly named tools

## Recap in 60 Seconds

1. Add MCP servers to Claude Code via the `mcpServers` key in `.mcp.json` (or `claude mcp add`): each server is defined by its `command` and `args`, and Claude Code handles the MCP protocol automatically
2. Test your server independently with the MCP Inspector before configuring it in Claude Code: protocol errors are silent in Claude Code but visible in the Inspector
3. Use local- or user-scope servers (`claude mcp add`, stored in `~/.claude.json`) for anything with secrets; use a committed `.mcp.json` for shared team configurations
