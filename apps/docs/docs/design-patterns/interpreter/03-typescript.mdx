## Implementation

Below is a complete TypeScript implementation of the Interpreter pattern using a Stock Market domain. The pattern defines a composable expression grammar for stock filtering. The `Expression` interface declares the `interpret()` method. Terminal expressions (`PriceGreaterThan`, `VolumeGreaterThan`, `TickerEquals`, `SectorEquals`) implement atomic comparisons. Nonterminal expressions (`AndExpr`, `OrExpr`, `NotExpr`) combine expressions logically. The `StockScreener` client evaluates an expression tree against a stock portfolio, collecting matches.

### How the Implementation Works

#### Class Diagram (Pseudocode)

```
// ── Participant Diagram ──
//
//   ┌──────────────────────────────────────┐
//   │   <<interface>>                      │
//   │   Expression (AbstractExpression)    │ ← OOP: Abstraction
//   ├──────────────────────────────────────┤    ISP: single method
//   │   + interpret(stock: StockData): bool│
//   └────────────────┬─────────────────────┘
//                    ▲ implements
//   ┌────────────────┴─────────────────────┐
//   │                │                     │
//   ┌────────────────┐  ┌──────────────────┐
//   │ TerminalExprs  │  │ NonterminalExprs │ ← OOP: Polymorphism
//   │ (PriceCheck,   │  │ (AndExpr,        │    LSP: substitutable
//   │  VolumeCheck,  │  │  OrExpr,         │    for Expression
//   │  TickerMatch,  │  │  NotExpr)        │
//   │  SectorMatch)  │  │                  │
//   └────────────────┘  └──────────────────┘
//
//   ┌──────────────────────────────────────┐
//   │ StockScreener (Client)               │ ← OOP: Encapsulation
//   ├──────────────────────────────────────┤    SRP: only screens
//   │ + screen(stocks, expr): StockData[]  │    DIP: depends on
//   └──────────────────────────────────────┘    Expression interface
```

#### OOP Concepts Applied

The `Expression` interface defines a pure contract that all code depends on rather than any concrete class, and each expression class stores its own data, thresholds, child expressions, while exposing only `interpret()`. Classes implement `Expression` by providing concrete `interpret()` bodies, and because `screen()` calls `interpret()` on any `Expression` reference, the runtime type is what actually determines the behavior.

#### SOLID Principles Applied

Each expression class evaluates exactly one grammar rule while `StockScreener` only iterates and collects results (SRP), and new expression types just implement `Expression` without touching existing expressions or the screener (OCP). Every concrete expression is substitutable for `Expression`, so the screener never has to check concrete types (LSP), and the `Expression` interface itself is a single, minimal, focused method (ISP). `StockScreener` depends on `Expression` throughout, never on any concrete implementation (DIP).

### StockData (Context)

```typescript
// ── Context ──
interface StockData {
  ticker: string;
  price: number;
  volume: number;
  sector: string;
}
```

### Expression (AbstractExpression)

```typescript
// ── Abstract Expression ──
interface Expression {
  interpret(stock: StockData): boolean;
}
```

### PriceGreaterThan (TerminalExpression)

```typescript
class PriceGreaterThan implements Expression {
  private threshold: number;

  constructor(threshold: number) {
    this.threshold = threshold;
  }

  interpret(stock: StockData): boolean {
    return stock.price > this.threshold;
  }
}
```

### VolumeGreaterThan (TerminalExpression)

```typescript
class VolumeGreaterThan implements Expression {
  private threshold: number;

  constructor(threshold: number) {
    this.threshold = threshold;
  }

  interpret(stock: StockData): boolean {
    return stock.volume > this.threshold;
  }
}
```

### TickerEquals (TerminalExpression)

```typescript
class TickerEquals implements Expression {
  private ticker: string;

  constructor(ticker: string) {
    this.ticker = ticker.toUpperCase();
  }

  interpret(stock: StockData): boolean {
    return stock.ticker === this.ticker;
  }
}
```

### SectorEquals (TerminalExpression)

```typescript
class SectorEquals implements Expression {
  private sector: string;

  constructor(sector: string) {
    this.sector = sector;
  }

  interpret(stock: StockData): boolean {
    return stock.sector === this.sector;
  }
}
```

### AndExpr (NonterminalExpression)

```typescript
class AndExpr implements Expression {
  private left: Expression;
  private right: Expression;

  constructor(left: Expression, right: Expression) {
    this.left = left;
    this.right = right;
  }

  interpret(stock: StockData): boolean {
    return this.left.interpret(stock) && this.right.interpret(stock);
  }
}
```

### OrExpr (NonterminalExpression)

```typescript
class OrExpr implements Expression {
  private left: Expression;
  private right: Expression;

  constructor(left: Expression, right: Expression) {
    this.left = left;
    this.right = right;
  }

  interpret(stock: StockData): boolean {
    return this.left.interpret(stock) || this.right.interpret(stock);
  }
}
```

### NotExpr (NonterminalExpression)

```typescript
class NotExpr implements Expression {
  private expr: Expression;

  constructor(expr: Expression) {
    this.expr = expr;
  }

  interpret(stock: StockData): boolean {
    return !this.expr.interpret(stock);
  }
}
```

### StockScreener (Client)

```typescript
// ── Client ──
class StockScreener {
  screen(stocks: StockData[], expression: Expression): StockData[] {
    const results: StockData[] = [];
    for (const stock of stocks) {
      if (expression.interpret(stock)) {
        results.push(stock);
      }
    }
    return results;
  }
}
```

### Main / Driver

```typescript
// ── Main / Driver ──
const stocks: StockData[] = [
  { ticker: 'AAPL', price: 175.50, volume: 85000000, sector: 'Technology' },
  { ticker: 'GOOGL', price: 142.30, volume: 32000000, sector: 'Technology' },
  { ticker: 'MSFT', price: 378.90, volume: 25000000, sector: 'Technology' },
  { ticker: 'JPM', price: 198.40, volume: 12000000, sector: 'Financial' },
  { ticker: 'BAC', price: 39.20, volume: 45000000, sector: 'Financial' },
  { ticker: 'AMZN', price: 178.25, volume: 61000000, sector: 'Technology' },
  { ticker: 'TSLA', price: 245.60, volume: 98000000, sector: 'Automotive' },
  { ticker: 'WMT', price: 72.80, volume: 18000000, sector: 'Retail' },
  { ticker: 'V', price: 275.30, volume: 15000000, sector: 'Financial' },
  { ticker: 'NVDA', price: 820.10, volume: 52000000, sector: 'Technology' },
];

const screener = new StockScreener();

console.log('=== Stock Screener: Interpreter Pattern ===');
console.log('');

// Query 1: price > 150 AND volume > 30000000
const query1 = new AndExpr(
  new PriceGreaterThan(150.0),
  new VolumeGreaterThan(30000000)
);
const result1 = screener.screen(stocks, query1);
console.log('Query 1: price > 150 AND volume > 30000000');
result1.forEach(s => console.log(`  ${s.ticker} | $${s.price} | ${(s.volume / 1000000).toFixed(1)}M vol`));
console.log(`  Matched: ${result1.length} stocks`);
console.log('');

// Query 2: sector = "Financial" OR ticker = "MSFT"
const query2 = new OrExpr(
  new SectorEquals('Financial'),
  new TickerEquals('MSFT')
);
const result2 = screener.screen(stocks, query2);
console.log('Query 2: sector = "Financial" OR ticker = "MSFT"');
result2.forEach(s => console.log(`  ${s.ticker} | $${s.price} | ${s.sector}`));
console.log(`  Matched: ${result2.length} stocks`);
console.log('');

// Query 3: NOT (price > 100): stocks with price <= 100
const query3 = new NotExpr(new PriceGreaterThan(100.0));
const result3 = screener.screen(stocks, query3);
console.log('Query 3: NOT (price > 100): stocks with price <= 100');
result3.forEach(s => console.log(`  ${s.ticker} | $${s.price}`));
console.log(`  Matched: ${result3.length} stocks`);
console.log('');

// Query 4: (ticker = "AAPL" OR ticker = "GOOGL") AND volume > 40000000
const query4 = new AndExpr(
  new OrExpr(
    new TickerEquals('AAPL'),
    new TickerEquals('GOOGL')
  ),
  new VolumeGreaterThan(40000000)
);
const result4 = screener.screen(stocks, query4);
console.log('Query 4: (ticker = "AAPL" OR ticker = "GOOGL") AND volume > 40000000');
result4.forEach(s => console.log(`  ${s.ticker} | $${s.price} | ${(s.volume / 1000000).toFixed(1)}M vol`));
console.log(`  Matched: ${result4.length} stocks`);
console.log('');

// Query 5: sector = "Technology" OR sector = "Financial"
const query5 = new OrExpr(
  new SectorEquals('Technology'),
  new SectorEquals('Financial')
);
const result5 = screener.screen(stocks, query5);
console.log('Query 5: sector = "Technology" OR sector = "Financial"');
result5.forEach(s => console.log(`  ${s.ticker} | $${s.price} | ${s.sector}`));
console.log(`  Matched: ${result5.length} stocks`);
```

### Language-Specific Notes

TypeScript's `interface` keyword gives first-class support to the abstraction participant here: `Expression` is the contract, and `implements Expression` on each concrete class enforces at compile time that every method is actually present. Its structural type system also means any object with a compatible `interpret()` method automatically satisfies `Expression`, duck typing enforced at the type level, which makes DIP and LSP compile-time guarantees rather than just conventions. The `private` keyword enforces encapsulation, `StockData` is a readonly `interface` rather than a class, idiomatic for pure data objects in TypeScript, and `forEach` with arrow functions keeps iteration clean. The `StockData[]` return type from `screen()` tells consumers exactly what shape to expect, and typing price and volume as `number` rules out accidental string concatenation bugs.
