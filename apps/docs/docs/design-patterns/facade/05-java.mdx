## Implementation

Below is a complete Java implementation of the Facade pattern using a cars domain. The `CarFacade` class provides a unified interface for starting, driving, and stopping a modern car. Six subsystem classes (`Engine`, `Transmission`, `CoolingSystem`, `ElectricalSystem`, `FuelSystem`, and `BrakingSystem`) each encapsulate a specific vehicle domain. The facade composes all six and orchestrates the correct startup sequence, ensuring that preconditions (battery voltage, fuel pressure) are met before the engine cranks.

### How the Implementation Works

#### Class Diagram (Pseudocode)

```
// ── Participant Diagram ──
//
//   ┌───────────────────────────────────────────┐
//   │   CarFacade (Facade)                      │  ← OOP: Composition, Encapsulation
//   ├───────────────────────────────────────────┤
//   │   - engine: Engine                        │
//   │   - transmission: Transmission            │
//   │   - cooling: CoolingSystem                │
//   │   - electrical: ElectricalSystem          │
//   │   - fuelSystem: FuelSystem                │
//   │   - brakes: BrakingSystem                 │
//   ├───────────────────────────────────────────┤
//   │   + CarFacade()                           │
//   │   + void startEngine()                    │
//   │   + void drive(int speed)                 │
//   │   + void stopEngine()                     │
//   └───────────────────────────────────────────┘
```

#### OOP Concepts Applied

Java's `private` access modifier enforces strict encapsulation here: subsystem state like `rpm`, `gear`, and `voltage` is inaccessible from outside its owning class, and the facade itself exposes only what the client actually needs. `CarFacade` holds references to six subsystem objects, created eagerly in the constructor so the facade is fully initialized the moment the client receives it, which is composition doing the heavy lifting. And because the client only ever calls `startEngine()`, `drive()`, and `stopEngine()`, the whole sequence of battery checks, fuel priming, and spark timing stays abstracted behind those three names.

#### SOLID Principles Applied

`Engine` handles cranking and RPM, `FuelSystem` manages fuel pressure, and `CarFacade` orchestrates the sequence without implementing any subsystem behavior itself, keeping each class to a single responsibility. New subsystems such as `Turbocharger` or `AdBlueSystem` can be added without changing any existing subsystem class; the facade just gets a new field wired into the start/drive/stop methods (OCP). And each subsystem class keeps a minimal, cohesive interface for ISP's sake: `BrakingSystem` exposes only `release()`, `apply()`, and `isEngaged()`, so no client is ever forced to depend on a method it won't use.

### Code

#### Subsystem: Engine

```java
class Engine {
    private int rpm = 0;

    public void crank() {
        this.rpm = 250;
        System.out.println("Engine: cranking at 250 RPM");
    }

    public void injectFuel() {
        System.out.println("Engine: injecting fuel into cylinders");
    }

    public void spark() {
        System.out.println("Engine: firing spark plugs");
    }

    public int getIdleRPM() {
        return 850;
    }

    public int getRPM() {
        return this.rpm;
    }

    public void rev(int amount) {
        this.rpm += amount;
        System.out.println("Engine: revving to " + this.rpm + " RPM");
    }

    public void stop() {
        this.rpm = 0;
        System.out.println("Engine: stopped");
    }
}
```

#### Facade

```java
class CarFacade {
    private Engine engine;
    private Transmission transmission;
    private CoolingSystem cooling;
    private ElectricalSystem electrical;
    private FuelSystem fuelSystem;
    private BrakingSystem brakes;

    public CarFacade() {
        this.engine = new Engine();
        this.transmission = new Transmission();
        this.cooling = new CoolingSystem();
        this.electrical = new ElectricalSystem();
        this.fuelSystem = new FuelSystem();
        this.brakes = new BrakingSystem();
    }

    public void startEngine() {
        System.out.println("--- Starting Engine ---");
        double voltage = this.electrical.getBatteryVoltage();
        if (voltage < 12.0) {
            System.out.println("ERROR: Battery voltage too low.");
            return;
        }
        this.electrical.powerECU();
        this.electrical.powerAccessories();
        this.electrical.closeStarterRelay();
        this.cooling.runWaterPump();
        this.fuelSystem.prime(55);
        this.engine.crank();
        this.engine.injectFuel();
        this.engine.spark();
        System.out.println("Engine started. Idle RPM: " + this.engine.getIdleRPM());
        this.cooling.runRadiatorFan();
        this.brakes.release();
    }

    public void drive(int speed) {
        System.out.println("--- Driving at " + speed + " RPM ---");
        this.transmission.shiftTo("Drive");
        this.engine.rev(speed);
        double targetTemp = 90.0;
        this.cooling.setThermostat(targetTemp);
        System.out.println("Driving: cruising at " + speed + " RPM");
    }

    public void stopEngine() {
        System.out.println("--- Stopping Engine ---");
        this.transmission.shiftTo("Park");
        this.brakes.apply();
        this.engine.stop();
        this.fuelSystem.shutoff();
        System.out.println("Engine stopped. All subsystems off.");
    }
}
```

#### Main / Driver

```java
public class FacadeDemo {
    public static void main(String[] args) {
        CarFacade car = new CarFacade();
        car.startEngine();
        System.out.println();
        car.drive(2500);
        System.out.println();
        car.stopEngine();
    }
}
```

### Language-Specific Notes

Java's `private` modifier locks down subsystem fields, and the facade class itself is package-private, with no `public` modifier, limiting its visibility so that only `FacadeDemo` is public and serves as the entry point. The facade creates all six subsystem instances eagerly in its constructor; production code would likely swap that for dependency injection, whether constructor parameters or a full DI framework, to decouple instantiation from orchestration. The code favors `int` and `double` primitives over wrapper types for performance, though a real automotive system would probably structure sensor values as domain objects backed by CAN bus data instead.

`System.out.println` stands in for a real logger here; production code would route through something like SLF4J or Log4j to a diagnostic bus or telemetry system. Java also requires a public class matching the filename, so this file needs to be named `FacadeDemo.java`, compiled with `javac FacadeDemo.java`, and run with `java FacadeDemo`. And the subsystem classes here don't extend a common interface; a larger system would define interfaces like `IEngine` and `ITransmission` to support multiple implementations, `V8Engine` and `ElectricMotor` among them, applying the Dependency Inversion Principle along the way.
