## Implementation

Below is a complete JavaScript implementation of the Facade pattern using a cars domain. The `CarFacade` class provides a unified interface for starting, driving, and stopping a modern car. Behind the facade, six subsystem classes (`Engine`, `Transmission`, `CoolingSystem`, `ElectricalSystem`, `FuelSystem`, and `BrakingSystem`) handle the real work. The driver code calls only three high-level methods without ever touching the subsystems directly.

### How the Implementation Works

#### Class Diagram (Pseudocode)

```
// ── Participant Diagram ──
//
//   ┌───────────────────────────────────────────┐
//   │   CarFacade (Facade)                      │  ← OOP: Encapsulation, Composition
//   ├───────────────────────────────────────────┤     SRP: orchestrates subsystems
//   │   - engine: Engine                        │
//   │   - transmission: Transmission            │
//   │   - cooling: CoolingSystem                │
//   │   - electrical: ElectricalSystem          │
//   │   - fuelSystem: FuelSystem                │
//   │   - brakes: BrakingSystem                 │
//   ├───────────────────────────────────────────┤
//   │   + startEngine()                         │
//   │   + drive(speed)                          │
//   │   + stopEngine()                          │
//   └───────────────────────────────────────────┘
```

#### OOP Concepts Applied

Each subsystem class hides its own internal state (RPM, coolant temperature, fuel pressure) behind getter methods, while the facade itself hides the orchestration logic from the client, which is encapsulation working at two levels at once. `CarFacade` composes six subsystem objects in its constructor, a straightforward "has-a" relationship: a car facade has an engine, a transmission, a cooling system, and so on. And because the client only ever interacts with three methods, `startEngine`, `drive`, and `stopEngine`, the whole sequence of battery checks, fuel priming, and spark timing stays abstracted away from view.

#### SOLID Principles Applied

Each subsystem class sticks to a single responsibility: `Engine` manages cranking and injection, `FuelSystem` manages pressure, and `CarFacade` orchestrates without implementing any subsystem behavior itself (SRP). New subsystems like `Turbocharger` or `HybridBattery` can be added without touching existing client code, since the facade is extended by wiring in the new piece internally rather than changing its public API (OCP). The facade does depend on concrete subsystem classes here rather than interfaces; a more advanced design could have subsystems implement interfaces and let the facade depend on those abstractions instead (DIP), though the pattern's core intent, simplifying access, holds either way.

### Code

#### Subsystem: Engine

```javascript
class Engine {
    constructor() {
        this._rpm = 0;
    }

    crank() {
        this._rpm = 250;
        console.log("Engine: cranking at 250 RPM");
    }

    injectFuel() {
        console.log("Engine: injecting fuel into cylinders");
    }

    spark() {
        console.log("Engine: firing spark plugs");
    }

    getIdleRPM() {
        return 850;
    }

    getRPM() {
        return this._rpm;
    }

    rev(amount) {
        this._rpm += amount;
        console.log(`Engine: revving to ${this._rpm} RPM`);
    }

    stop() {
        this._rpm = 0;
        console.log("Engine: stopped");
    }
}
```

class Transmission {

#### Subsystem: BrakingSystem

```javascript
class BrakingSystem {
    constructor() {
        this._engaged = true;
    }

    release() {
        this._engaged = false;
        console.log("Brakes: parking brake released");
    }

    apply() {
        this._engaged = true;
        console.log("Brakes: parking brake applied");
    }

    isEngaged() {
        return this._engaged;
    }
}
```

#### Facade

```javascript
class CarFacade {
    constructor() {
        this.engine = new Engine();
        this.transmission = new Transmission();
        this.cooling = new CoolingSystem();
        this.electrical = new ElectricalSystem();
        this.fuelSystem = new FuelSystem();
        this.brakes = new BrakingSystem();
    }

    startEngine() {
        console.log("--- Starting Engine ---");
        const voltage = this.electrical.getBatteryVoltage();
        if (voltage < 12.0) {
            console.log("ERROR: Battery voltage too low.");
            return;
        }
        this.electrical.powerECU();
        this.electrical.powerAccessories();
        this.electrical.closeStarterRelay();
        this.cooling.runWaterPump();
        this.fuelSystem.prime(55);
        this.engine.crank();
        this.engine.injectFuel();
        this.engine.spark();
        console.log(`Engine started. Idle RPM: ${this.engine.getIdleRPM()}`);
        this.cooling.runRadiatorFan();
        this.brakes.release();
    }

    drive(speed) {
        console.log(`--- Driving at ${speed} RPM ---`);
        this.transmission.shiftTo("Drive");
        this.engine.rev(speed);
        const targetTemp = 90.0;
        this.cooling.setThermostat(targetTemp);
        console.log(`Driving: cruising at ${speed} RPM`);
    }

    stopEngine() {
        console.log("--- Stopping Engine ---");
        this.transmission.shiftTo("Park");
        this.brakes.apply();
        this.engine.stop();
        this.fuelSystem.shutoff();
        console.log("Engine stopped. All subsystems off.");
    }
}
```

#### Main / Driver

```javascript
function main() {
    const car = new CarFacade();
    car.startEngine();
    console.log("");
    car.drive(2500);
    console.log("");
    car.stopEngine();
}

main();
```

### Language-Specific Notes

JavaScript's prototypal inheritance means the facade works with any object that has the expected methods, so subsystem classes can be swapped at runtime as long as they match the duck-typed interface. The constructor eagerly creates all six subsystem instances up front; in a resource-constrained environment, lazy initialization inside each getter would be worth considering instead. This ES6 class version marks private fields with the `_` prefix convention, though modern JavaScript (ES2022+) offers `#` private fields for true encapsulation, as in `#engine = new Engine()`.

The implementation uses `console.log` for simplicity, but a production automotive system would swap that for a structured logger writing to a diagnostic bus or telemetry stream. Production code would also want try/catch blocks around each subsystem call in `startEngine`, with fail-safe defaults for every failure mode, beyond the battery voltage check shown here. One nice side effect of the design: each subsystem class can be unit-tested in isolation, and the facade itself can be tested by mocking all six subsystems and checking that method calls happen in the right order with the right arguments.
