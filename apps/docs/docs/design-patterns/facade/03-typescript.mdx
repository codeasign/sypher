## Implementation

Below is a complete TypeScript implementation of the Facade pattern using a cars domain. TypeScript's static type system enforces the subsystem interfaces at compile time, ensuring that the `CarFacade` only composes components that satisfy the expected contracts. The facade provides three high-level methods (`startEngine`, `drive`, and `stopEngine`) while internally coordinating an `Engine`, `Transmission`, `CoolingSystem`, `ElectricalSystem`, `FuelSystem`, and `BrakingSystem`.

### How the Implementation Works

#### Class Diagram (Pseudocode)

```
// ── Participant Diagram ──
//
//   ┌───────────────────────────────────────────┐
//   │   <<interface>> IEngine                   │  ← DIP: Facade depends on abstractions
//   ├───────────────────────────────────────────┤
//   │   + crank(): void                         │
//   │   + injectFuel(): void                    │
//   │   + spark(): void                         │
//   │   + getIdleRPM(): number                  │
//   │   + getRPM(): number                      │
//   │   + rev(amount: number): void             │
//   │   + stop(): void                          │
//   └───────────────────────────────────────────┘
//
//   ┌───────────────────────────────────────────┐
//   │   CarFacade (Facade)                      │  ← OOP: Composition over inheritance
//   ├───────────────────────────────────────────┤
//   │   - engine: IEngine                       │
//   │   - transmission: ITransmission           │
//   │   - ... (5 more interfaces)               │
//   ├───────────────────────────────────────────┤
//   │   + startEngine(): void                   │
//   │   + drive(speed: number): void            │
//   │   + stopEngine(): void                    │
//   └───────────────────────────────────────────┘
```

#### OOP Concepts Applied

Six interfaces define pure contracts here without any implementation details, and `CarFacade` depends only on those interfaces, never on concrete subsystem classes, which is abstraction doing its job. Composition shows up in how `CarFacade` holds six interface-typed members, with the concrete implementations injected through the constructor rather than created internally, which is what makes dependency injection possible in the first place. That same design buys polymorphism for free: any class that implements `IEngine`, whether `V8Engine`, `ElectricMotor`, or `HybridEngine`, can be substituted without touching the facade at all.

#### SOLID Principles Applied

The facade depends on interfaces like `IEngine` and `ITransmission` rather than concrete classes, with subsystems implementing those interfaces, which is the Dependency Inversion Principle in its purest form. Each subsystem interface sticks to a focused contract too: `IFuelSystem` only deals with fuel pressure, `IBrakingSystem` only with brake state, satisfying SRP. Adding a new engine type only requires a new class implementing `IEngine`, leaving the facade untouched because it depends on the interface rather than any concrete engine class (OCP). And each interface stays small and focused for ISP's sake: `IEngine`'s seven methods are all genuinely about engine operation, so a client that only cares about RPM never has to depend on braking methods it will never call.

### Code

#### Subsystem Interfaces

```typescript
interface IEngine {
    crank(): void;
    injectFuel(): void;
    spark(): void;
    getIdleRPM(): number;
    getRPM(): number;
    rev(amount: number): void;
    stop(): void;
}

interface ITransmission {
    shiftTo(gearName: string): void;
    getCurrentGear(): string;
}

interface ICoolingSystem {
    runWaterPump(): void;
    runRadiatorFan(): void;
    getCoolantTemperature(): number;
    setThermostat(temp: number): void;
}

interface IElectricalSystem {
    getBatteryVoltage(): number;
    powerAccessories(): void;
    powerECU(): void;
    closeStarterRelay(): void;
}

interface IFuelSystem {
    prime(pressure: number): void;
    getRailPressure(): number;
    shutoff(): void;
}

interface IBrakingSystem {
    release(): void;
    apply(): void;
    isEngaged(): boolean;
}
```

#### Concrete Subsystem: Engine

```typescript
class Engine implements IEngine {
    private rpm: number = 0;

    public crank(): void {
        this.rpm = 250;
        console.log("Engine: cranking at 250 RPM");
    }

    public injectFuel(): void {
        console.log("Engine: injecting fuel into cylinders");
    }

    public spark(): void {
        console.log("Engine: firing spark plugs");
    }

    public getIdleRPM(): number {
        return 850;
    }

    public getRPM(): number {
        return this.rpm;
    }

    public rev(amount: number): void {
        this.rpm += amount;
        console.log(`Engine: revving to ${this.rpm} RPM`);
    }

    public stop(): void {
        this.rpm = 0;
        console.log("Engine: stopped");
    }
}
```

#### Facade

```typescript
class CarFacade {
    constructor(
        private engine: IEngine,
        private transmission: ITransmission,
        private cooling: ICoolingSystem,
        private electrical: IElectricalSystem,
        private fuelSystem: IFuelSystem,
        private brakes: IBrakingSystem
    ) {}

    public startEngine(): void {
        console.log("--- Starting Engine ---");
        const voltage = this.electrical.getBatteryVoltage();
        if (voltage < 12.0) {
            console.log("ERROR: Battery voltage too low.");
            return;
        }
        this.electrical.powerECU();
        this.electrical.powerAccessories();
        this.electrical.closeStarterRelay();
        this.cooling.runWaterPump();
        this.fuelSystem.prime(55);
        this.engine.crank();
        this.engine.injectFuel();
        this.engine.spark();
        console.log(`Engine started. Idle RPM: ${this.engine.getIdleRPM()}`);
        this.cooling.runRadiatorFan();
        this.brakes.release();
    }

    public drive(speed: number): void {
        console.log(`--- Driving at ${speed} RPM ---`);
        this.transmission.shiftTo("Drive");
        this.engine.rev(speed);
        const targetTemp = 90.0;
        this.cooling.setThermostat(targetTemp);
        console.log(`Driving: cruising at ${speed} RPM`);
    }

    public stopEngine(): void {
        console.log("--- Stopping Engine ---");
        this.transmission.shiftTo("Park");
        this.brakes.apply();
        this.engine.stop();
        this.fuelSystem.shutoff();
        console.log("Engine stopped. All subsystems off.");
    }
}
```

#### Main / Driver

```typescript
function main(): void {
    const car = new CarFacade(
        new Engine(),
        new Transmission(),
        new CoolingSystem(),
        new ElectricalSystem(),
        new FuelSystem(),
        new BrakingSystem()
    );
    car.startEngine();
    console.log("");
    car.drive(2500);
    console.log("");
    car.stopEngine();
}

main();
```

### Language-Specific Notes

Unlike the JavaScript version, which creates subsystems internally, this facade receives them as constructor parameters, which makes unit testing with mock subsystems straightforward and plays nicely with IoC containers. Each subsystem interface spells out an explicit contract, so a `HybridEngine` class implementing `IEngine` can be swapped in without changing the facade at all, a direct demonstration of the Open/Closed Principle. TypeScript's `private` keyword (or `#` in modern JS) enforces encapsulation at compile time, and interface members default to `public`, exposing only the minimum surface area needed.

`Transmission.shiftTo` currently accepts a plain `string`; a production system would tighten that with a union type like `type Gear = "Park" | "Drive" | "Reverse" | "Neutral"` to catch invalid gear arguments at compile time instead of at runtime. Since TypeScript interfaces exist only at compile time, the runtime behavior here is identical to the JavaScript version, with zero overhead for type checking, and the battery voltage check in `startEngine` benefits from TypeScript's narrowing, since `const voltage: number` keeps the comparison type-safe throughout.
