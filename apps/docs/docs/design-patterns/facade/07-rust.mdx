## Implementation

Below is a complete Rust implementation of the Facade pattern using a cars domain. The `CarFacade` struct provides a unified interface for starting, driving, and stopping a modern car. Six subsystem structs (`Engine`, `Transmission`, `CoolingSystem`, `ElectricalSystem`, `FuelSystem`, and `BrakingSystem`) each encapsulate a specific vehicle domain. The facade owns all six subsystems and orchestrates the correct startup sequence, with a battery voltage check as a precondition before the starter relay engages.

### How the Implementation Works

#### Class Diagram (Pseudocode)

```
// ── Participant Diagram ──
//
//   ┌───────────────────────────────────────────┐
//   │   CarFacade (Facade)                      │  ← OOP: Composition, Encapsulation
//   ├───────────────────────────────────────────┤
//   │   - engine: Engine                        │
//   │   - transmission: Transmission            │
//   │   - cooling: CoolingSystem                │
//   │   - electrical: ElectricalSystem          │
//   │   - fuel_system: FuelSystem               │
//   │   - brakes: BrakingSystem                 │
//   ├───────────────────────────────────────────┤
//   │   + fn new() -> CarFacade                 │
//   │   + fn start_engine(&mut self)            │
//   │   + fn drive(&mut self, speed: u32)       │
//   │   + fn stop_engine(&mut self)             │
//   └───────────────────────────────────────────┘
```

#### OOP Concepts Applied

Rust's module system and private-by-default fields enforce strict encapsulation here, so only the public methods on each struct form the API surface. `CarFacade` owns six subsystem structs outright, and Rust's ownership model guarantees they're dropped the moment the facade is dropped, ruling out resource leaks by construction. Because the caller only ever invokes `start_engine()`, `drive()`, and `stop_engine()`, the whole sequence of battery checks, fuel priming, and spark timing stays hidden behind those three names.

#### SOLID Principles Applied

`Engine` handles cranking and RPM, `FuelSystem` manages fuel pressure, and `CarFacade` orchestrates the sequence without implementing any subsystem behavior itself (SRP). New subsystems like `Turbocharger` or `HybridBattery` can be added without changing any existing subsystem struct, just by giving the facade a new field wired into the orchestration methods (OCP). And each subsystem struct exposes only the methods it needs: `BrakingSystem` has just `release()`, `apply()`, and `is_engaged()`, keeping every interface minimal and focused (ISP).

### Code

#### Subsystem: Engine

```rust
struct Engine {
    rpm: u32,
}

impl Engine {
    fn new() -> Self {
        Engine { rpm: 0 }
    }

    fn crank(&mut self) {
        self.rpm = 250;
        println!("Engine: cranking at 250 RPM");
    }

    fn inject_fuel(&self) {
        println!("Engine: injecting fuel into cylinders");
    }

    fn spark(&self) {
        println!("Engine: firing spark plugs");
    }

    fn get_idle_rpm(&self) -> u32 {
        850
    }

    fn get_rpm(&self) -> u32 {
        self.rpm
    }

    fn rev(&mut self, amount: u32) {
        self.rpm += amount;
        println!("Engine: revving to {} RPM", self.rpm);
    }

    fn stop(&mut self) {
        self.rpm = 0;
        println!("Engine: stopped");
    }
}
```

#### Facade

```rust
struct CarFacade {
    engine: Engine,
    transmission: Transmission,
    cooling: CoolingSystem,
    electrical: ElectricalSystem,
    fuel_system: FuelSystem,
    brakes: BrakingSystem,
}

impl CarFacade {
    fn new() -> Self {
        CarFacade {
            engine: Engine::new(),
            transmission: Transmission::new(),
            cooling: CoolingSystem::new(),
            electrical: ElectricalSystem::new(),
            fuel_system: FuelSystem::new(),
            brakes: BrakingSystem::new(),
        }
    }

    fn start_engine(&mut self) {
        println!("--- Starting Engine ---");
        let voltage = self.electrical.get_battery_voltage();
        if voltage < 12.0 {
            println!("ERROR: Battery voltage too low.");
            return;
        }
        self.electrical.power_ecu();
        self.electrical.power_accessories();
        self.electrical.close_starter_relay();
        self.cooling.run_water_pump();
        self.fuel_system.prime(55.0);
        self.engine.crank();
        self.engine.inject_fuel();
        self.engine.spark();
        println!("Engine started. Idle RPM: {}", self.engine.get_idle_rpm());
        self.cooling.run_radiator_fan();
        self.brakes.release();
    }

    fn drive(&mut self, speed: u32) {
        println!("--- Driving at {} RPM ---", speed);
        self.transmission.shift_to("Drive");
        self.engine.rev(speed);
        let target_temp = 90.0;
        self.cooling.set_thermostat(target_temp);
        println!("Driving: cruising at {} RPM", speed);
    }

    fn stop_engine(&mut self) {
        println!("--- Stopping Engine ---");
        self.transmission.shift_to("Park");
        self.brakes.apply();
        self.engine.stop();
        self.fuel_system.shutoff();
        println!("Engine stopped. All subsystems off.");
    }
}
```

#### Main / Driver

```rust
fn main() {
    let mut car = CarFacade::new();
    car.start_engine();
    println!();
    car.drive(2500);
    println!();
    car.stop_engine();
}
```

### Language-Specific Notes

The facade owns all six subsystem structs directly, so when `CarFacade` is dropped at the end of `main()`, Rust drops each subsystem automatically, ruling out resource leaks without needing a garbage collector or manual `free` calls. Because the facade mutates its subsystems, cranking the engine, shifting gears, priming the fuel pump, all three public methods take `&mut self`, which guarantees only one reference to the facade can exist at a time and rules out data races. Rust doesn't have constructors, so `CarFacade::new()` is the idiomatic associated function that builds and returns a fully initialized instance.

`println!("...", args)` uses format arguments rather than string interpolation, and the compiler checks those format strings at compile time, catching mismatches before the code ever runs. Rust also has no null pointer: every field gets initialized in `new()`, which rules out an entire category of null-reference bugs that plague other languages. And the `Transmission` struct stores the gear as an owned, heap-allocated `String`, while `shift_to` accepts a borrowed `&str` instead, which is more flexible since it accepts both string literals and `String` references.
