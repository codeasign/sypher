## Summary

Linear Search means checking items one at a time, in order, until you find the one you're looking for — or run out of items. Imagine looking for your friend's name on a class roster by reading down the list line by line: that's Linear Search. It works on any list, in any order, but it can be slow: the more items there are, the more you might have to check.

## Pseudocode

```text
1. Start at the first item in the list.
2. Look at the current item. Is it the one you want?
3. If yes, stop — you found it. Report where it is.
4. If no, move to the next item.
5. If you've checked every item and never found a match, report "not found."
```

## Worked Example

## Complexity

- **Best case:** If the target is the very first thing you check, it's basically instant (`O(1)`).
- **Average case:** On a random list, you'll typically check about half the items before finding a match (`O(n)`).
- **Worst case:** If the target is the last item — or isn't in the list at all — you end up checking every single item (`O(n)`).
- **Space:** It only ever needs a single counter to remember which box it's currently looking at, no matter how big the list is (`O(1)`).

## Applications

- **`std::find` in the C++ Standard Library** falls back to a linear scan whenever it's given an iterator that doesn't support jumping straight to the middle (e.g. a linked list), since there's no other way to search it.
- **Python's `in` operator and `list.index()`** run a linear scan under the hood for plain lists — CPython has no sorted-order guarantee to exploit, so it checks items in order.
- **Traversing a linked list**, such as `LinkedList.indexOf()` in Java's standard library, has to use Linear Search because a linked list has no random access — you can't "jump" to the middle element the way you can with an array.
- **Database full table scans** are essentially Linear Search: when a query has no matching index on the column being searched, the database engine checks every row one at a time.
- **Simple in-memory lookups**, like scanning a short list of settings or a small cache, where the list is small enough that sorting or indexing it first wouldn't be worth the extra work.
