The setup module got a project booted and one smoke test passing. This module slows down and actually explains the pieces — JUnit 5's structure, what RestAssured is doing under the hood, and how to read a request/response cycle instead of just copying one that happened to work.

## What JUnit 5 gives you

JUnit 5 is the test *runner* — it's what discovers your test classes, executes each `@Test`-annotated method, and reports pass/fail. It doesn't know anything about HTTP; that's RestAssured's job. The two work together: JUnit decides *when* your test code runs, RestAssured is a library your test code calls to talk to an API.

JUnit 5 is actually three things bundled together — the Jupiter API you write tests against (`@Test`, `assertEquals`, and so on), the Jupiter engine that runs those tests, and a platform layer that lets build tools like Maven discover and run them. Adding the single `junit-jupiter` dependency (as you did in `pom.xml` last module) pulls in all three, which is why one dependency is enough to get a working test.

## What RestAssured gives you

RestAssured is a library purpose-built for testing REST APIs in Java — it wraps the lower-level HTTP client work you'd otherwise have to write by hand (opening a connection, setting headers, serializing a body, parsing a response) behind a fluent, readable style. Its whole design centers on one method chain:

```java
given()
    // set up the request: headers, body, auth, query params
.when()
    // fire it: .get(), .post(), .put(), .delete()
.then()
    // assert on what came back
```

You'll go deep on this exact chain in the next module. For now, just recognize it when you see it — it reads almost like a sentence: *given* this setup, *when* I make this call, *then* expect this result.

## Project structure so far

```

        └── java/
            └── com/
                └── example/
                    └── rbactests/

```

Everything under `src/test/java` is test code Maven's Surefire plugin will pick up automatically when you run `mvn test` — no configuration file lists your tests by name, Surefire just scans for classes matching its default naming pattern (`*Test`, `Test*`, or `*Tests`, among a few others) and runs every `@Test` method it finds inside them.

## Writing your first real request

Create `src/test/java/com/example/rbactests/FirstRequestTest.java`:

```java
package com.example.rbactests;

import io.restassured.response.Response;
import org.junit.jupiter.api.Test;

import static io.restassured.RestAssured.given;
import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertTrue;

class FirstRequestTest {

    @Test
    void loginReturnsATokenAndTheRightUser() {
        Response response =
                given()
                    .baseUri("http://localhost:5000")
                    .contentType("application/json")
                    .body("{\"username\":\"admin\",\"password\":\"admin123\"}")
                .when()
                    .post("/api/auth/login");

        System.out.println("Status: " + response.getStatusCode());
        System.out.println("Body: " + response.getBody().asPrettyString());

        assertEquals(200, response.getStatusCode());
        assertEquals("admin", response.jsonPath().getString("user.username"));
        assertEquals("Administrator", response.jsonPath().getString("user.role"));
        assertTrue(response.jsonPath().getString("token").length() > 20);
    }
}
```

A few things worth being precise about here. `given()`, `when()`, and the assertion imports are all **static imports** — `io.restassured.RestAssured.given` is a `static` method, and importing it statically means you can write `given()` instead of `RestAssured.given()` everywhere. This is the idiomatic RestAssured style you'll see in every module from here on.

`response.jsonPath()` gives you a `JsonPath` object — a small utility, bundled with RestAssured itself, for pulling values out of a JSON response body using dot-notation paths, without you having to define a Java class to deserialize into first. `"user.username"` walks into the `user` object and reads its `username` field, exactly the way you'd expect from the shape of the response body. You'll use `jsonPath()` constantly for the rest of this course, right up until the schema-validation module, where you'll validate whole response shapes at once instead of field by field.

Run it:

```bash
mvn test -Dtest=FirstRequestTest
```

`-Dtest=<ClassName>` tells Surefire to run just that one test class instead of your whole suite — useful while you're actively working on one file, though a plain `mvn test` (no filter) is what you'll run once you have more than a couple of tests, and what CI will run in the reporting module.

## Reading the response object

`Response` is RestAssured's representation of whatever came back — status code, headers, and body all live on it. The three you'll reach for constantly:

- `response.getStatusCode()` — the HTTP status code as an `int`.
- `response.getBody().asString()` — the raw response body as text.
- `response.jsonPath()` — a queryable view into the body, assuming it's JSON (which every RBAC app response is).

## Try it

Write a second test in `FirstRequestTest` that logs in as `doctor1` / `pass@123` instead, and asserts the returned `user.role` is `"Doctor"` and `user.id` equals `5`. Print the full response body first with `System.out.println`, the way the example above does, before you write the assertions — get comfortable looking at real output before you decide what to check.
