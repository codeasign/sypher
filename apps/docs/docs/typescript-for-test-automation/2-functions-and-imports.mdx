Think about how you write a manual test case. You don't write out "open the browser, go to the login page, type the username, type the password, click login" every single time you need to log in. You write that once as a step called "Log in as admin" and then you just reference it whenever you need it.

A **function** is that same idea in code. It's a reusable test step you can call by name instead of retyping. Write it once, give it a name, and then use that name anywhere you need to do that thing again.

## Writing a simple function

Here's a function that builds greeting text for a patient in the `rbac-healthcare-system` app. It takes in some information (the **parameters**) and hands back a result (the **return value**):

```typescript
function greetPatient(firstName: string, lastName: string): string {
  return `Welcome back, ${firstName} ${lastName}`;
}

console.log(greetPatient("Alice", "Nguyen"));
```

Run that and you'll see:

```text
Welcome back, Alice Nguyen
```

Let's break down what's typed here:

- `firstName: string` and `lastName: string` are the parameters — the inputs the function expects, each with a type.
- `: string` right before the `{` is the **return type** — it tells TypeScript (and anyone reading your code) exactly what kind of value comes back out.

If you try to call `greetPatient(123, "Nguyen")`, TypeScript stops you immediately, because `123` is a number, not a string. That's the whole point of typing your test steps: mistakes get caught before you ever run the test against the real app.

You can call this function as many times as you want, for as many patients as you want, without ever retyping the template string:

```typescript
console.log(greetPatient("Ravi", "Shah"));
console.log(greetPatient("Emma", "Clarke"));
```

```text
Welcome back, Ravi Shah
Welcome back, Emma Clarke
```

## Splitting code across files

Real test projects are never one giant file. As your suite grows, you'll end up with dozens or hundreds of test steps, and dumping them all into one file makes it impossible to find anything. Instead, TypeScript lets you write a function in one file and use it in another, with `export` and `import`.

- `export` in front of something means "other files are allowed to use this."
- `import { name } from "./file"` in another file means "bring that exported thing in here."

Let's build a small helper that creates a test patient object for the RBAC app, matching this shape:

```typescript
interface TestPatient {
  id: number;
  firstName: string;
  lastName: string;
  dateOfBirth: string;
}
```

**`testData.ts`** — the file where the helper lives:

```typescript
export interface TestPatient {
  id: number;
  firstName: string;
  lastName: string;
  dateOfBirth: string;
}

export function createTestPatient(id: number): TestPatient {
  return {
    id,
    firstName: "Jordan",
    lastName: "Blake",
    dateOfBirth: "1990-04-12",
  };
}
```

**`runPatientCheck.ts`** — a different file that imports and uses that helper:

```typescript
import { createTestPatient } from "./testData";

const patient = createTestPatient(101);

console.log(patient);
console.log(`Testing patient record for ${patient.firstName} ${patient.lastName}`);
```

Run `runPatientCheck.ts` and you'll see:

```text
{ id: 101, firstName: 'Jordan', lastName: 'Blake', dateOfBirth: '1990-04-12' }
Testing patient record for Jordan Blake
```

Notice the import path is `"./testData"` — no `.ts` extension. TypeScript figures that part out for you. The `./` just means "look in this same folder."

This pattern is exactly how a real Playwright or automation project against `rbac-healthcare-system` stays organized: one file holds reusable data-builders and helpers (things like `createTestPatient`, or later a `loginAsRole` helper), and your actual test files just import what they need. As you add more roles — admin, doctor, nurse, patient — you can keep growing `testData.ts` with more exported functions, and every test file that needs test data imports from that one shared place instead of redefining it.

## Try it

Create two files.

In `roleData.ts`, write and export a function called `createTestUser` that takes one parameter, `role: string`, and returns a `string` message like `"Created test user with role: admin"`.

```typescript
export function createTestUser(role: string): string {
  return `Created test user with role: ${role}`;
}
```

In a second file, import `createTestUser` from `./roleData` and call it three times — once each for `"admin"`, `"nurse"`, and `"patient"` — logging each result with `console.log()`. You should see three separate lines of output, one per role, all produced by calling the same function three times instead of writing the message out by hand.
