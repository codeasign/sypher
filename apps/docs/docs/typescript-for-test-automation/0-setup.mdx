If you've spent your career clicking through an app and filing bugs, this page is your on-ramp into automating that work. By the end of it, you'll have TypeScript installed, a code editor set up, and you'll have run your very first `.ts` file on your own machine. That's it — no prior coding experience needed.

## Install Node.js

TypeScript needs a program called **Node.js** to run on your computer. Think of Node.js as the engine that lets your machine understand and execute code files, the same way a PDF reader lets your machine open a `.pdf` file.

1. Go to [nodejs.org](https://nodejs.org) and download the **LTS** version (LTS just means "long-term support" — it's the stable, recommended one).
2. Run the installer and click through with the defaults. You don't need to change any settings.
3. Once it's done, open a terminal (Command Prompt, PowerShell, or the terminal inside VS Code once you install it below) and check it worked:

```bash
node --version
npm --version
```

You should see two version numbers print out. `npm` (Node Package Manager) comes bundled with Node.js — it's the tool you'll use to install TypeScript and, later, testing tools.

## Install TypeScript

TypeScript itself is just a package you install with `npm`. Run this in your terminal:

```bash
npm install -g typescript
```

The `-g` means "install globally," so the `tsc` (TypeScript Compiler) command is available anywhere on your machine, not just inside one project folder. Confirm it installed:

```bash
tsc --version
```

**Quick gloss:** TypeScript is a superset of JavaScript — it's JavaScript with a layer on top that catches mistakes for you *before* you run anything, like a spellchecker for your code. That's the whole reason it's such a good fit for test automation: it flags typos and wrong assumptions (like calling a method that doesn't exist on a page object) while you're still writing the test, instead of letting you discover it mid test run.

## Set up Visual Studio Code

You can technically write TypeScript in any text editor, but **Visual Studio Code (VS Code)** is the one almost every test automation engineer uses, and it has excellent TypeScript support baked in from the start.

1. Download it from [code.visualstudio.com](https://code.visualstudio.com) and install it like any other application.
2. Open a folder in VS Code (File → Open Folder) to start a project — VS Code organizes everything around folders rather than single files.

VS Code already understands TypeScript out of the box — no setup required. The moment you save a `.ts` file with a mistake in it, you'll see a red squiggly underline, and hovering over it tells you exactly what's wrong. That's TypeScript talking to you through the editor.

On top of that built-in support, there are two extensions worth installing on day one:

- **ESLint** — catches common mistakes and bad patterns in your code as you type (things like an unused variable or a forgotten `await`, which matters a lot once you're writing test steps).
- **Prettier** — automatically reformats your code so it's neatly indented and consistent, so you never have to think about spacing or line breaks by hand.

To install either one: open the Extensions panel in VS Code (the icon that looks like four squares on the left sidebar), search for the name, and click Install. You don't need to configure anything about them right now — just having them installed is enough to start getting the benefit. Think of them as "helpful red squiggly lines and auto-formatting," not something you need to tune or understand deeply yet.

## Run your first .ts file

Let's prove all of this works. Create a new folder anywhere on your computer, open it in VS Code, and create a file called `hello.ts` with this in it:

```typescript
const testerName: string = "Alex";
const appUnderTest: string = "rbac-healthcare-system";

console.log(`${testerName} is starting to automate tests for ${appUnderTest}`);
```

A `.ts` file can't be run directly by your browser or by Node.js — it needs to be compiled into plain JavaScript first. That's what the `tsc` command you installed earlier does. Run this in your terminal, inside the folder where you saved `hello.ts`:

```bash
tsc hello.ts
```

You'll notice a new file appear next to it: `hello.js`. That's the compiled, plain-JavaScript version. Now run that with Node.js:

```bash
node hello.js
```

You should see your message printed to the terminal. Congratulations — you just wrote, compiled, and ran your first TypeScript file.

Later on, you won't run `tsc` and `node` by hand like this every time — the testing tool you'll use handles that compile-and-run step for you automatically whenever you run a test. This was just to see the moving parts once with your own eyes.

This course is deliberately narrow: it's a fast path to reading and writing TypeScript test code against a real healthcare app, not a full tour of the language. Once you're comfortable automating tests here and find yourself curious about TypeScript itself — generics, advanced types, the deeper "why" behind the syntax — the "Learn TypeScript" course on this same site is where to go for that full depth.

## Get the RBAC healthcare app backend running

Starting a few modules from now, you'll call a real API instead of just printing values to the terminal, so it's worth getting that API running now, once, rather than pausing mid-lesson later. This course only needs the **backend** — there's no browser involved anywhere in it, so you can skip the frontend entirely.

Clone the repo:

```bash
git clone https://github.com/codedbyabhishekc/rbac-healthcare-system.git
cd rbac-healthcare-system
```

Install and start the backend:

```bash
cd backend
npm install
mkdir database
```

The `database` folder has to exist before the app's first run — it's where the SQLite file gets created, and the app doesn't create the folder itself. Create a `.env` file inside `backend/`:

```bash
PORT=5000
JWT_SECRET=<any-long-random-string>
NODE_ENV=development
```

Then start it:

```bash
npm start
```

Confirm it's up by opening [http://localhost:5000/api-docs](http://localhost:5000/api-docs) — you should see the Swagger UI listing every endpoint this course calls. Leave this terminal running for the rest of the course.

In a new terminal, from `backend/`, seed the database with the test data every later module (including the capstone) works against:

```bash
npm run seed
```

This creates 3 Admins, 8 Doctors, 7 Nurses, 15 Patients, 22 Appointments, and 15 Medical Records — including the default admin login, `admin` / `admin123`, and a nurse login, `nurse1` / `nurse123`, used in several examples later on.

## Try it

Edit `hello.ts` so it also declares a `role: string` variable set to `"nurse"` (one of the four roles in the RBAC healthcare app you'll be testing later), and update the `console.log` line to include it in the printed message. Recompile with `tsc hello.ts` and run it again with `node hello.js` to see your updated message.
