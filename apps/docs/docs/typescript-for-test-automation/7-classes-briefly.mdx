You've been writing functions and objects on their own. A **class** (a blueprint for creating objects that bundle data and behavior together) is just a way to group related data and functions into one reusable shape. Here's the smallest useful example, built around something you already know: logging into the `rbac-healthcare-system` app.

```typescript
class LoginPage {
  url: string;

  constructor(baseUrl: string) {
    this.url = baseUrl;
  }

  getLoginUrl(): string {
    return `${this.url}/login`;
  }
}

const login = new LoginPage("http://localhost:3002");
console.log(login.getLoginUrl());
```

Running this prints `http://localhost:3002/login`. Let's break down the three pieces you just saw:

- **A property** — `url` is a piece of data that belongs to the class. Every `LoginPage` you create will have its own `url`.
- **A constructor** — the special function named `constructor` that runs automatically when you create a new object with `new`. It's where you set up the starting values, here by saving whatever `baseUrl` gets passed in.
- **A method** — `getLoginUrl` is just a function that lives inside the class. Inside a method, `this` means "the specific object I'm working with," so `this.url` refers back to the `url` this particular `LoginPage` was built with.

That's genuinely most of what you need to *read* a class. You could add more properties (like a username field) or more methods (like a `login` method that fills in a form), but the shape stays the same: some data, a constructor to set it up, and methods that act on it.

Here's why this matters for where you're headed. Almost every test automation framework, including Playwright, encourages you to organize your tests using **Page Objects** — and a Page Object is really nothing more than a class like the one above, representing one page of an app. Instead of a `getLoginUrl` method, a real Page Object for the login page would have methods like `enterUsername`, `enterPassword`, and `submit`, each one wrapping up the actions a tester would normally do by hand. You don't need to build one yet. Just notice that the shape — a class with a constructor and methods for the actions on a page — is exactly what you'll be using once you get into the Playwright Test Automation course.

## Try it

Extend the `LoginPage` class above by adding a second method called `getSignupUrl()` that returns `this.url` with `/signup` appended instead of `/login`. Create a new `LoginPage` for `http://localhost:3002` and log the result of calling both `getLoginUrl()` and `getSignupUrl()` to confirm they each print the right address.
