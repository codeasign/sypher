Say you're building out BookHaven, the online bookstore, and you've already got your `Book` interface:

```typescript
interface Book {
  title: string;
  author: string;
  price: number;
  inStock: boolean;
}
```

That's a solid, complete shape for a book. But real code rarely wants the *exact same shape* everywhere. An edit form only has some of the fields filled in so far. A search result card only needs the title and price. A "mark as sold out" function shouldn't need the whole book, just its stock status. Instead of writing brand new interfaces for every one of these situations, TypeScript gives you **utility types**: built-in helpers that take an existing type and reshape it for you.

Think of utility types as functions, but for types instead of values. You pass in a type, you get a new type out. Let's go through the four you'll reach for constantly: `Partial`, `Pick`, `Omit`, and `Record`.

## Partial: make every property optional

`Partial` just means every property becomes optional. That's it. If you wrap `Book` in `Partial<Book>`, you get a type where `title`, `author`, `price`, and `inStock` are all allowed to be missing.

This is perfect for an "update a book" function, where the caller might only want to change the price and leave everything else alone:

```typescript
function updateBook(book: Book, changes: Partial<Book>): Book {
  return { ...book, ...changes };
}

const original: Book = {
  title: "The Hobbit",
  author: "J.R.R. Tolkien",
  price: 14.99,
  inStock: true,
};

const updated = updateBook(original, { price: 12.99 });
```

Notice that `{ price: 12.99 }` is missing `title`, `author`, and `inStock`, and TypeScript is fine with that, because `Partial<Book>` says every field is optional. Without `Partial`, TypeScript would complain that the object you passed in is missing three required properties.

## Pick: keep only the fields you name

`Pick` just means you're keeping only the fields you name, and dropping everything else. You give it the original type plus a list of property names, and it builds a smaller type out of just those.

A search result card in BookHaven probably doesn't need the full `Book`, just enough to display a preview:

```typescript
type BookPreview = Pick<Book, "title" | "price">;

const preview: BookPreview = {
  title: "The Hobbit",
  price: 14.99,
};
```

`BookPreview` only has `title` and `price`. If you tried to add `author` or `inStock` to it, TypeScript would stop you, because `Pick<Book, "title" | "price">` never mentioned those fields.

## Omit: the opposite of Pick

`Omit` is the opposite of `Pick`: instead of naming the fields you want to keep, you name the fields you want to leave out, and you keep everything else.

Say BookHaven has a form for adding a brand new book, and the store always assumes new arrivals are in stock by default, so the form itself shouldn't even ask about `inStock`:

```typescript
type NewBookInput = Omit<Book, "inStock">;

function addBook(input: NewBookInput): Book {
  return { ...input, inStock: true };
}

const newBook = addBook({
  title: "Dune",
  author: "Frank Herbert",
  price: 18.5,
});
```

`NewBookInput` has `title`, `author`, and `price`, but no `inStock`, so the object passed into `addBook` doesn't need it, and `addBook` fills it in itself.

A handy way to remember the difference: `Pick` is a guest list ("only these get in"), and `Omit` is a blocklist ("everyone except these").

## Record: an object keyed by a set of names, all with the same shape

`Record` just means an object where every value has the same shape, keyed by some set of names. You give it two things: the type of the keys, and the type of the values.

BookHaven organizes its catalog by genre, and every genre maps to one featured `Book`:

```typescript
type Genre = "fantasy" | "sci-fi" | "mystery";

const featuredByGenre: Record<Genre, Book> = {
  fantasy: {
    title: "The Hobbit",
    author: "J.R.R. Tolkien",
    price: 14.99,
    inStock: true,
  },
  "sci-fi": {
    title: "Dune",
    author: "Frank Herbert",
    price: 18.5,
    inStock: true,
  },
  mystery: {
    title: "The Big Sleep",
    author: "Raymond Chandler",
    price: 9.99,
    inStock: false,
  },
};
```

`Record<Genre, Book>` says: this object must have exactly the keys `"fantasy"`, `"sci-fi"`, and `"mystery"` (nothing more, nothing less), and every single value must be a full `Book`. If you forgot the `mystery` entry, or if `sci-fi` were missing `price`, TypeScript would catch it immediately.

## Putting them side by side

Here's all four in one place, so you can see how each one changes `Book` differently:

```typescript
type DraftBook = Partial<Book>;               // every field optional
type BookPreview = Pick<Book, "title" | "price">; // only title and price
type NewBookInput = Omit<Book, "inStock">;    // everything except inStock
type CatalogByGenre = Record<Genre, Book>;    // keyed object, every value a full Book
```

You don't need to memorize any of this. Once you've used each one a couple of times in real code, reaching for the right one becomes automatic. The pattern to hold onto is: `Partial` softens a type, `Pick` and `Omit` trim a type down (from opposite directions), and `Record` builds a keyed collection out of a type.

## Try it

BookHaven wants a function that only updates a book's price, nothing else. Define a type called `PriceUpdate` using one of the utility types above so it contains only a `price: number` field, then write a function with this signature:

```typescript
function updatePrice(book: Book, update: PriceUpdate): Book {
  // your code here
}
```

It should return a new `Book` object with the price changed and every other field kept the same. Try writing `PriceUpdate` with `Pick` first, then see if you can write an equivalent version using `Omit` instead. Both are valid, just approached from opposite directions.
