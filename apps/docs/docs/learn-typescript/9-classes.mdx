BookHaven doesn't just sell books; it has members, too. Up to now you've been describing shapes with `interface` and `type`, but those only describe data. A **class** lets you bundle data together with the behavior that goes with it, all in one place. Here's a `Member` class for BookHaven:

```typescript
class Member {
  name: string;
  email: string;
  isPremium: boolean;

  constructor(name: string, email: string, isPremium: boolean) {
    this.name = name;
    this.email = email;
    this.isPremium = isPremium;
  }
}
```

A few things to notice. The three lines at the top (`name`, `email`, `isPremium`) declare the class's **properties**: the pieces of data every `Member` will carry, along with their types. The **constructor** is a special function that runs when you create a new member, and its job is to fill in those properties from whatever gets passed in. Inside it, `this` refers to "the member currently being created," so `this.name = name` means "set this member's name property to whatever name was passed in."

Creating a member looks like calling a function, but with the `new` keyword in front:

```typescript
const alice = new Member("Alice Chen", "alice@example.com", true);
console.log(alice.name); // "Alice Chen"
console.log(alice.isPremium); // true
```

## Adding a method

A class is more useful once it can *do* something with its own data, not just store it. A function that lives inside a class is called a **method**. Let's give `Member` one that checks whether this member qualifies for BookHaven's discount, which is only available to premium members:

```typescript
class Member {
  name: string;
  email: string;
  isPremium: boolean;

  constructor(name: string, email: string, isPremium: boolean) {
    this.name = name;
    this.email = email;
    this.isPremium = isPremium;
  }

  describe(): string {
    const discount = this.isPremium ? "gets 10% off every order" : "pays full price";
    return `${this.name} ${discount}.`;
  }
}

const alice = new Member("Alice Chen", "alice@example.com", true);
console.log(alice.describe()); // "Alice Chen gets 10% off every order."
```

Notice the method reads the object's own properties through `this`, exactly the same way the constructor wrote them.

## Public and private

By default, every property on a class is **public**, meaning any code outside the class can read or change it freely: `alice.email = "new@example.com"` just works, no questions asked. Most of the time that's fine. But sometimes a class has a detail that's really only its own business, something other code shouldn't be able to poke at directly. That's what the `private` keyword is for: private just means other code can't touch this from outside the class. Only methods defined inside the class itself are allowed to read or change it.

Say BookHaven wants to track how many times a member has logged in, purely for its own internal use, where nothing outside the class needs to see or change that number directly:

```typescript
class Member {
  name: string;
  email: string;
  isPremium: boolean;
  private loginCount: number;

  constructor(name: string, email: string, isPremium: boolean) {
    this.name = name;
    this.email = email;
    this.isPremium = isPremium;
    this.loginCount = 0;
  }

  logIn(): void {
    this.loginCount = this.loginCount + 1;
    console.log(`${this.name} has logged in ${this.loginCount} time(s).`);
  }
}

const alice = new Member("Alice Chen", "alice@example.com", true);
alice.logIn(); // "Alice Chen has logged in 1 time(s)."
alice.logIn(); // "Alice Chen has logged in 2 time(s)."

alice.loginCount = 100; // Error: Property 'loginCount' is private and only accessible within class 'Member'
```

The `logIn` method, being defined inside the class, is allowed to read and update `loginCount`. Code outside the class, like that last line, is not. TypeScript catches the attempt at compile time, before it ever runs. You could write `public` in front of `name`, `email`, and `isPremium` too, but since public is the default, most people leave it off and only write `private` where it actually matters.

## Try it

Write a `Book` class with public properties `title: string`, `author: string`, and `price: number`, plus a private property `copiesSold: number` that starts at `0` in the constructor. Add a method `sell(): void` that increases `copiesSold` by one and logs a message like `"Dune has sold 1 copies."` Create one `Book`, call `sell()` on it twice, and confirm the count goes up each time. Then try writing `yourBook.copiesSold = 500` directly and confirm TypeScript blocks it.
