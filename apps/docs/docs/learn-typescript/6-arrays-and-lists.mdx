BookHaven doesn't sell one book at a time; it sells a whole catalog. So instead of a single `Book`, you'll usually be working with a list of them. TypeScript lets you type that list precisely, so you get the same safety net for arrays that you already get for single objects.

Here's the `Book` shape you've already seen, and a small catalog built from it:

```typescript
interface Book {
  title: string;
  author: string;
  price: number;
  inStock: boolean;
}

const catalog: Book[] = [
  { title: "The Silent Shelf", author: "Mara Ellison", price: 14.99, inStock: true },
  { title: "Paper Trails", author: "Dev Osei", price: 9.5, inStock: false },
  { title: "Ink and Ledger", author: "Priya Nandan", price: 21.0, inStock: true },
  { title: "The Last Bookmark", author: "Mara Ellison", price: 12.25, inStock: true },
];
```

The type `Book[]` reads as "an array of `Book`." You could also write it as `Array<Book>`, which is the same type, just a different syntax. Both mean "every element in here must satisfy the `Book` interface." Try sneaking in an object that's missing `price`, or one where `inStock` is a string instead of a boolean, and TypeScript will flag it right there in the array literal, before you ever run the code.

## Looping through a typed array

Because TypeScript knows `catalog` holds `Book` objects, it knows exactly what properties are available on each one as you loop:

```typescript
for (const book of catalog) {
  console.log(`${book.title} by ${book.author} — $${book.price}`);
}
```

Inside that loop, `book` is typed as `Book`. If you try `book.pric` (a typo) or `book.publisher` (a property that doesn't exist on `Book`), your editor will underline it immediately. That's the real payoff of typing the array: every single item you touch while looping gets checked, not just the array as a whole.

## Transforming and filtering with `.map()` and `.filter()`

Two array methods you'll reach for constantly are `.map()`, which transforms each item into something new, and `.filter()`, which keeps only the items that pass a test.

Say you want a plain list of titles, without all the other details:

```typescript
const titles: string[] = catalog.map((book) => book.title);
```

`.map()` runs your function once per book and collects the results into a new array. Since each `book.title` is a `string`, TypeScript infers that `titles` is a `string[]`. You don't even have to annotate it yourself, though writing it out (as above) can make the intent clearer to a reader.

Now say you want only the books that are actually in stock:

```typescript
const availableBooks: Book[] = catalog.filter((book) => book.inStock);
```

`.filter()` runs your function once per book too, but instead of transforming anything, it just decides "keep this one" (return `true`) or "drop this one" (return `false`). The result is a brand-new array (`catalog` itself is untouched), and because you started with `Book[]`, the filtered result is still `Book[]`. You haven't lost any type information along the way.

You can chain the two together when you need it:

```typescript
const affordableTitles: string[] = catalog
  .filter((book) => book.price < 15)
  .map((book) => book.title);
```

First filter down to the books under $15, then map what's left down to just their titles. Reading it top to bottom tells you exactly what's happening at each step.
