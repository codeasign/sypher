Picture a `@logAccess` line sitting right above a method, and every time that method runs, TypeScript quietly logs "calling this" before and "done" after, without you writing any of that logging code inside the method itself. That's a decorator. It's a way to attach extra behavior to a class, a method, or a property from the outside, without touching the original code.

In plain English: a decorator is just a function that gets handed a piece of your class (like a method) and gets a chance to wrap it, replace it, or record something about it before TypeScript moves on. You write the decorator once, then you can stick it on top of any method you want, using an `@` symbol.

Before decorators will compile, you need one setting turned on in your `tsconfig.json`:

```json
{
  "compilerOptions": {
    "experimentalDecorators": true
  }
}
```

That's the whole setup step. Decorators are still an evolving part of TypeScript (and JavaScript), so this flag is how you opt in to the version most codebases use today.

## A logging decorator for BookHaven

Let's say BookHaven has a small `Inventory` class that manages which books are in stock:

```typescript
interface Book {
  title: string;
  author: string;
  price: number;
  inStock: boolean;
}

class Inventory {
  private books: Book[] = [];

  addBook(book: Book) {
    this.books.push(book);
    return book;
  }
}
```

Nothing fancy so far: `addBook` just pushes a new `Book` onto an array. Now let's say we want to log every time `addBook` gets called, without editing the method's body. That's exactly what a method decorator is for:

```typescript
function logAccess(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const originalMethod = descriptor.value;

  descriptor.value = function (...args: any[]) {
    console.log(`Calling ${propertyKey}...`);
    const result = originalMethod.apply(this, args);
    console.log(`${propertyKey} finished.`);
    return result;
  };

  return descriptor;
}
```

A method decorator like this always receives three things: the class it's attached to (`target`), the name of the method (`propertyKey`), and a `descriptor`, which is just an object describing the method, including the actual function, stored at `descriptor.value`. The trick is to grab that original function, then replace `descriptor.value` with a new function that logs something, calls the original, and then logs again.

Now we attach it to `addBook` with an `@`:

```typescript
class Inventory {
  private books: Book[] = [];

  @logAccess
  addBook(book: Book) {
    this.books.push(book);
    return book;
  }
}

const store = new Inventory();
store.addBook({ title: "The Hobbit", author: "J.R.R. Tolkien", price: 12.99, inStock: true });
```

Running that logs:

```text
Calling addBook...
addBook finished.
```

Notice that `addBook`'s own code never mentions logging at all. The decorator bolted that behavior on from outside, which is the whole point: you can reuse `@logAccess` on any method in BookHaven, and if you ever want to remove the logging, you just delete the one line with the `@`, and the method itself is untouched.

## Where you'll actually run into these

You probably won't write decorators like `@logAccess` every day in typical application code, but you'll see the `@` syntax a lot once you start working with certain frameworks. NestJS (a popular Node.js framework) leans on decorators heavily, for things like marking a class as a controller or marking a method as handling a specific route. Some database libraries (ORMs, which just means tools that map your classes to database tables) use decorators to say "this property maps to this column." When you see `@Something` above a class or method in one of those tools, it's doing exactly what `@logAccess` does here: wrapping or annotating that piece of code from the outside.

## Try it

Add a `removeBook(title: string)` method to the `Inventory` class that filters `books` to remove any book matching that title. Apply `@logAccess` to it too, then create an `Inventory`, add two books, remove one by title, and check the console output to confirm you see "Calling removeBook..." and "removeBook finished." around the removal.
