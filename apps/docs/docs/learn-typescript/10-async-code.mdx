A lot of real code doesn't get its answer right away. When BookHaven looks up a book, that lookup might involve a network request to a server somewhere, and the server needs a moment to respond. JavaScript (and TypeScript, since it's built on top of JavaScript) handles this kind of "the answer is coming, but not yet" situation with something called a **Promise**: an object that represents a value you don't have yet, but will have eventually.

TypeScript's job here is to make sure you know exactly what type of value that Promise will eventually hand you, so you get the same safety net for async code that you already get everywhere else.

## A Promise that resolves to a Book

Let's simulate BookHaven's book lookup. Instead of making a real network call, we'll use `setTimeout` to pretend there's a delay, the same way a real request would take a little time to come back:

```typescript
interface Book {
  title: string;
  author: string;
  price: number;
  inStock: boolean;
}

function fetchBook(title: string): Promise<Book> {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({ title, author: "Unknown", price: 12.99, inStock: true });
    }, 500);
  });
}
```

The return type here is `Promise<Book>`, which reads as "a Promise that will eventually resolve to a `Book`." That angle-bracket syntax is the same generic syntax you've already seen elsewhere in this course: `Promise` is a generic type, and `Book` is filling in the blank for what it eventually contains.

Inside the function, `resolve` is the function you call once you actually have the value. Calling `resolve({...})` is how the Promise announces "here's your book, it's ready." Until `resolve` is called, anyone waiting on this Promise just... waits.

## Waiting for it with `await`

You could work with a Promise using `.then(...)` callbacks, but TypeScript (like modern JavaScript) gives you a much more readable option: `async` and `await`. These two keywords let you write asynchronous code that reads top-to-bottom, just like ordinary synchronous code, instead of nesting callbacks inside callbacks.

Here's how you'd use `fetchBook` inside an `async` function:

```typescript
async function printBookDetails(title: string): Promise<void> {
  const book = await fetchBook(title);
  console.log(`${book.title} by ${book.author} — $${book.price}`);
}

printBookDetails("The Hobbit");
```

A few things worth noticing:

- The function is declared with the `async` keyword in front of it. Any function marked `async` automatically returns a Promise, even if you write a plain `return` statement inside it.
- Its return type is `Promise<void>`, because `printBookDetails` doesn't hand back any value once it's done; it just logs something to the console. If it did return a value, say a `boolean`, the return type would be `Promise<boolean>`.
- Inside the function, `await fetchBook(title)` pauses execution right there until the Promise resolves, and then unwraps it for you. That means `book` isn't a `Promise<Book>`; TypeScript already knows that once you `await` it, `book` is a plain `Book`, with `title`, `author`, `price`, and `inStock` all available and correctly typed.

You can only use `await` inside a function marked `async`. If you try to use it outside one, TypeScript will stop you with an error, because `await` only makes sense somewhere that's already agreed to pause and wait.

## Returning a typed value from an async function

Let's write one more version that actually hands something back, rather than just logging it:

```typescript
async function getBookPrice(title: string): Promise<number> {
  const book = await fetchBook(title);
  return book.price;
}
```

Notice the return type is `Promise<number>`, not just `number`. That's a rule worth remembering: any function marked `async` always wraps its return value in a Promise, so the type annotation always needs a `Promise<...>` wrapper around whatever the function actually hands back.

Calling it looks the same as before: you `await` it from inside another `async` function:

```typescript
async function checkPrice(): Promise<void> {
  const price = await getBookPrice("Dune");
  console.log(`It costs $${price}`);
}
```

The type checking here is doing real work for you. If you tried to write `book.pyrce` instead of `book.price` inside `getBookPrice`, TypeScript would catch that typo immediately, before you ever ran the code, even though the value only exists after an asynchronous wait.
