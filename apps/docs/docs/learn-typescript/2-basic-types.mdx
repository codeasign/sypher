Before we get into types, let's cover one thing you'll lean on constantly for the rest of this course: printing a value so you can actually see it.

```typescript
console.log("Hello, BookHaven!");
```

`console.log()` takes whatever you hand it and prints it out — to your terminal if you're running the compiled file with `node`, or to the browser's console if the code is running on a page. You already used it once, without much comment, back when you ran your first `.ts` file. From here on, every example on this page prints its value with `console.log()` too, so you can compile and run each one yourself and see exactly what TypeScript is working with, instead of just reading typed code that never actually runs.

Let's start stocking BookHaven's catalog with some actual data. Every value you work with — a book's title, its price, whether it's in stock — has a type, and TypeScript wants to know what that type is so it can stop you from making silly mistakes later, like trying to multiply a title by two.

Here's a book title, annotated with its type:

```typescript
let title: string = "The Hobbit";
console.log(title);
```

The `: string` part is called a **type annotation** — it's you telling TypeScript "this variable will only ever hold text." If you later try `title = 42`, TypeScript will stop you before your code even runs, because a number is not a string.

## The basics: string, number, boolean

BookHaven needs three kinds of primitive (meaning: simple, single-value) data almost everywhere: text, numbers, and yes/no flags.

```typescript
let title: string = "The Hobbit";
let price: number = 14.99;
let inStock: boolean = true;

console.log(title);
console.log(price);
console.log(inStock);
```

`string` covers any text — titles, author names, ISBNs written as text. `number` covers all numbers in TypeScript, there's no separate type for whole numbers versus decimals, it's just `number`. And `boolean` covers `true` or `false` — perfect for a flag like whether a book is currently in stock.

Try changing one of these to a mismatched value and see what happens:

```typescript
let price: number = 14.99;
price = "free"; // Type 'string' is not assignable to type 'number'.
```

TypeScript catches that immediately, right in your editor, long before this code would ever run and blow up in a customer's browser.

## Arrays

BookHaven doesn't sell one book, it sells many, so you'll often have a list of values of the same type. To annotate an array, you write the type followed by square brackets:

```typescript
let bookTitles: string[] = ["The Hobbit", "Dune", "Circe"];
let bookPrices: number[] = [14.99, 21.5, 17.25];

console.log(bookTitles);
console.log(bookPrices);
```

`string[]` means "an array where every item is a string." If you try to sneak a number into `bookTitles`, TypeScript will flag it:

```typescript
let bookTitles: string[] = ["The Hobbit", "Dune", "Circe"];
bookTitles.push(9.99); // Argument of type 'number' is not assignable to parameter of type 'string'.
```

That's genuinely useful — it means a typo like accidentally pushing a price into a list of titles gets caught right away, instead of quietly corrupting your data.

## Letting TypeScript figure it out for you

Here's the thing a lot of people don't expect when they start: you don't have to annotate everything. TypeScript is smart enough to look at the value you're assigning and figure out the type on its own. This is called **type inference** — TypeScript "infers," or works out, the type from context.

```typescript
let author = "Frank Herbert";
console.log(author);
```

No `: string` anywhere, but TypeScript still knows `author` is a string, because you handed it a string literal right there. Hover over `author` in your editor and it'll tell you the type it inferred. Try the same "assign the wrong thing later" trick as before:

```typescript
let author = "Frank Herbert";
author = 42; // Type 'number' is not assignable to type 'string'.
```

Same error as before, even though you never wrote `string` anywhere yourself. TypeScript locked in the type the moment you initialized the variable.

In everyday BookHaven code, you'll actually skip explicit annotations most of the time and let inference do the work — it keeps your code shorter and just as safe:

```typescript
let bestsellerCount = 12;
let genres = ["Fantasy", "Sci-Fi", "Mystery"];

console.log(bestsellerCount);
console.log(genres);
```

`bestsellerCount` is inferred as `number`, and `genres` is inferred as `string[]`, exactly as if you'd typed those annotations by hand. A good rule of thumb: annotate when you're declaring a variable without an initial value, or when you want to be extra explicit for readers of your code; otherwise, let TypeScript infer and keep things tidy.

## Try it

Create a new file called `catalog.ts` and, without writing any type annotations at all, declare three variables: one holding a book title as a string, one holding its price as a number, and one array holding a few genre names as strings. Then hover over each variable in your editor (or try assigning it a mismatched value, like a number to the title) and confirm TypeScript already knows the correct type for each one, purely from inference.
