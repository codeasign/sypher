You've spent this whole course building up pieces of BookHaven, the online bookstore: a `Book` interface here, a class there, a generic helper somewhere else. This page puts all of it into one small program you can actually run from start to finish. There's nothing new to learn here, just familiar tools working together.

Let's start with the shapes. These should look immediately familiar:

```typescript
interface Book {
  title: string;
  author: string;
  price: number;
  inStock: boolean;
}

type OrderStatus = "pending" | "shipped" | "delivered";

interface Order {
  id: number;
  book: Book;
  quantity: number;
  status: OrderStatus;
}
```

`Book` describes a single book. `OrderStatus` is a union type: an order can only ever be `"pending"`, `"shipped"`, or `"delivered"`, nothing else. `Order` ties a `Book` together with a quantity and a status.

## A catalog to hold the books

Rather than scattering an array and loose functions around, let's wrap the bookstore's inventory in a small class. A class is a natural fit here because it bundles the data (the list of books) together with the behavior that acts on it (adding, filtering, searching):

```typescript
class Catalog {
  private books: Book[] = [];

  addBook(book: Book): void {
    this.books.push(book);
  }

  getAll(): Book[] {
    return this.books;
  }
}
```

`books` is marked `private`, meaning outside code can't reach in and mess with the array directly; the only way to add a book is through the `addBook` method. `getAll` gives read access back out. Both methods have their return types spelled out (`void` for "returns nothing," `Book[]` for "returns an array of books"), so anyone calling them knows exactly what to expect.

## Filtering for what's in stock

Now let's add a method that finds only the books currently in stock, using `.filter()`, the same array method you've used elsewhere, working here on a fully typed `Book[]`:

```typescript
class Catalog {
  private books: Book[] = [];

  addBook(book: Book): void {
    this.books.push(book);
  }

  getAll(): Book[] {
    return this.books;
  }

  findInStock(): Book[] {
    return this.books.filter((book) => book.inStock);
  }

  searchByAuthor(author: string): Book[] {
    return this.books.filter((book) =>
      book.author.toLowerCase().includes(author.toLowerCase())
    );
  }
}
```

`findInStock` keeps only the books where `inStock` is `true`. `searchByAuthor` does a simple case-insensitive match against each book's `author` field. Both return a fresh `Book[]`; nothing here mutates the original list.

## A generic helper for picking the first match

Sometimes you don't want every match, just the first one, if there is one. This is a good place for a small generic function, since "give me the first item of a list, or nothing if the list is empty" is useful no matter what the list is holding:

```typescript
function firstResult<T>(items: T[]): T | undefined {
  return items.length > 0 ? items[0] : undefined;
}
```

`T` stands in for whatever type gets passed in: an array of `Book`, an array of `Order`, an array of strings, doesn't matter. The return type `T | undefined` is another union: you get back an item of type `T` if the array had one, or `undefined` if it was empty. TypeScript figures out what `T` is automatically from whatever array you hand it.

## Updating a book's price

BookHaven occasionally runs a sale, and you don't want to rebuild an entire `Book` object just to change its price. This is exactly the situation `Partial` is built for: it takes `Book` and makes every one of its properties optional, so the caller only has to supply the fields they actually want to change:

```typescript
function applyPriceChange(book: Book, changes: Partial<Book>): Book {
  return { ...book, ...changes };
}
```

Passing in `{ price: 9.99 }` works fine even though it's missing `title`, `author`, and `inStock`, because `Partial<Book>` says all of those are optional, so TypeScript doesn't complain.

## Printing a receipt

Finally, a function that takes an `Order` and prints a simple receipt. This is where the union-typed `status` field gets narrowed: checking which of the three possible strings it actually is, and picking the right message for each:

```typescript
function printReceipt(order: Order): string {
  const subtotal = order.book.price * order.quantity;
  let statusLine: string;

  if (order.status === "pending") {
    statusLine = "Your order is being prepared.";
  } else if (order.status === "shipped") {
    statusLine = "Your order is on its way.";
  } else {
    statusLine = "Your order has been delivered.";
  }

  return [
    `Receipt for Order #${order.id}`,
    `${order.quantity} x "${order.book.title}" by ${order.book.author}`,
    `Subtotal: $${subtotal.toFixed(2)}`,
    `Status: ${statusLine}`,
  ].join("\n");
}
```

`printReceipt` is a typed function with a real return value: it hands back a `string` rather than just logging one, so whoever calls it can decide what to do with it (print it, save it, send it somewhere). The `if`/`else if`/`else` chain narrows `order.status` down to exactly one of its three possible values each time it runs.

## Running the whole thing

Here's everything wired together into one script you could paste into a `.ts` file and run:

```typescript
interface Book {
  title: string;
  author: string;
  price: number;
  inStock: boolean;
}

type OrderStatus = "pending" | "shipped" | "delivered";

interface Order {
  id: number;
  book: Book;
  quantity: number;
  status: OrderStatus;
}

class Catalog {
  private books: Book[] = [];

  addBook(book: Book): void {
    this.books.push(book);
  }

  getAll(): Book[] {
    return this.books;
  }

  findInStock(): Book[] {
    return this.books.filter((book) => book.inStock);
  }

  searchByAuthor(author: string): Book[] {
    return this.books.filter((book) =>
      book.author.toLowerCase().includes(author.toLowerCase())
    );
  }
}

function firstResult<T>(items: T[]): T | undefined {
  return items.length > 0 ? items[0] : undefined;
}

function applyPriceChange(book: Book, changes: Partial<Book>): Book {
  return { ...book, ...changes };
}

function printReceipt(order: Order): string {
  const subtotal = order.book.price * order.quantity;
  let statusLine: string;

  if (order.status === "pending") {
    statusLine = "Your order is being prepared.";
  } else if (order.status === "shipped") {
    statusLine = "Your order is on its way.";
  } else {
    statusLine = "Your order has been delivered.";
  }

  return [
    `Receipt for Order #${order.id}`,
    `${order.quantity} x "${order.book.title}" by ${order.book.author}`,
    `Subtotal: $${subtotal.toFixed(2)}`,
    `Status: ${statusLine}`,
  ].join("\n");
}

const store = new Catalog();

store.addBook({ title: "The Hobbit", author: "J.R.R. Tolkien", price: 14.99, inStock: true });
store.addBook({ title: "Dune", author: "Frank Herbert", price: 18.5, inStock: false });
store.addBook({ title: "The Silmarillion", author: "J.R.R. Tolkien", price: 22.0, inStock: true });

console.log("In stock:", store.findInStock().map((book) => book.title));

const tolkienBooks = store.searchByAuthor("tolkien");
console.log("By Tolkien:", tolkienBooks.map((book) => book.title));

const firstTolkienBook = firstResult(tolkienBooks);

if (firstTolkienBook) {
  const discounted = applyPriceChange(firstTolkienBook, { price: 11.99 });

  const order: Order = {
    id: 1001,
    book: discounted,
    quantity: 2,
    status: "shipped",
  };

  console.log(printReceipt(order));
}
```

Run it and you'll see the in-stock titles, the Tolkien search results, and a full receipt printed for an order on a discounted book, every step checked by the type system before any of it ran.

Look at what just came together. An interface describes a shape, a union type limits a field to a few exact values, and a class keeps its own data private while exposing safe methods to touch it. `.filter()` works over a typed array without any guesswork, a generic function handles whatever type you throw at it, and a utility type reshapes an existing interface instead of you writing a new one by hand. The union gets narrowed to handle each case correctly, and the final function returns a real, typed value. None of these pieces are exotic; they're the same tools from every earlier page, just standing next to each other in one small program.

That's really what learning TypeScript comes down to: not memorizing every rule up front, but getting comfortable enough with each piece that reaching for the right one becomes automatic. You've now got all of them. From here, you get faster the same way you got here: reading real code, writing real code, and letting the compiler flag what's off before it becomes a bug someone else has to find.

## Try it

Here's a small, self-contained starting point. You don't need anything from earlier on this page to use it:

```typescript
interface Book {
  title: string;
  author: string;
  price: number;
  inStock: boolean;
}

type OrderStatus = "pending" | "shipped" | "delivered";

interface Order {
  id: number;
  book: Book;
  quantity: number;
  status: OrderStatus;
}

const books: Book[] = [
  { title: "The Hobbit", author: "J.R.R. Tolkien", price: 14.99, inStock: true },
  { title: "Dune", author: "Frank Herbert", price: 18.5, inStock: false },
];

function printReceipt(order: Order): string {
  const subtotal = order.book.price * order.quantity;
  return `Order #${order.id}: ${order.quantity} x "${order.book.title}" — $${subtotal.toFixed(2)} (${order.status})`;
}

const sampleOrder: Order = {
  id: 1,
  book: books[0],
  quantity: 1,
  status: "pending",
};

console.log(printReceipt(sampleOrder));
```

Extend `OrderStatus` to also allow `"cancelled"`, then update `printReceipt` so that when an order is cancelled, it prints `"Order #<id> was cancelled — no charge."` instead of the usual receipt line, without touching how the other statuses are handled.
