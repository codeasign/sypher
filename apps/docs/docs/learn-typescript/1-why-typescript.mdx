# Why TypeScript

Here's the whole idea in one sentence: **TypeScript adds types to JavaScript so mistakes get caught while you're writing the code, instead of while a customer is using it.**

A "type" is just a label for what kind of value something is — a number, a string, a `Book` object with a `price` and a `title`. JavaScript doesn't check any of that until the code actually runs. TypeScript checks it the moment you write it, right in your editor, before you ever hit run.

## A bug JavaScript won't catch

Say BookHaven has a little helper that adds sales tax to a book's price:

```javascript
function priceWithTax(book) {
  return book.price * 1.08;
}

const book = { title: "The Hobbit", author: "J.R.R. Tolkien" };

console.log(priceWithTax(book));
```

That `book` object is missing `price` — maybe it came from a form a developer forgot to finish wiring up, or a typo (`prise` instead of `price`) somewhere else in the codebase. Run this and JavaScript doesn't stop you. It just quietly computes `undefined * 1.08`, which is `NaN` ("Not a Number"), and prints that to the console. No error, no warning — just a wrong number that might not get noticed until a customer sees a nonsense price on the checkout page.

## The same bug, but caught immediately

Now here's the same function in TypeScript, with a type describing what a `Book` actually looks like:

```typescript
type Book = {
  title: string;
  author: string;
  price: number;
};

function priceWithTax(book: Book) {
  return book.price * 1.08;
}

const book = { title: "The Hobbit", author: "J.R.R. Tolkien" };

console.log(priceWithTax(book));
```

This won't even compile. TypeScript looks at `book` and sees it's missing `price`, which the `Book` type says is required, and it stops you right there with an error like "Property 'price' is missing." You fix it before the code ever runs — not after it ships.

That's the whole trade: you spend a few seconds describing the shape of your data up front, and in exchange, an entire category of "quietly wrong" bugs turns into a loud, immediate error in your editor.

## Try it

Write a plain JavaScript function called `describeMember` that takes a `member` object and returns a string like `"Ada is a premium member"` using `member.name` and `member.isPremium`. Call it with a member object that's missing the `isPremium` field, and look at what gets printed. Notice that JavaScript runs it anyway and just produces a slightly broken sentence, without any error telling you why. That "runs fine, quietly wrong" feeling is exactly what the rest of this course helps you avoid.
