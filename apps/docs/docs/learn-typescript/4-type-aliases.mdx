You already know how to describe the shape of a `Book` using an `interface`. TypeScript gives you a second way to do the exact same thing: a **type alias** (a name you give to a type, so you can reuse it instead of writing the same shape over and over).

Here's the same `Book` shape from before, written with `type` instead of `interface`:

```typescript
type Book = {
  title: string;
  author: string;
  price: number;
  inStock: boolean;
};

const dune: Book = {
  title: "Dune",
  author: "Frank Herbert",
  price: 12.99,
  inStock: true,
};
```

Notice how similar this looks to the `interface` version. The syntax is a little different (`type Book = { ... }` with an equals sign, versus `interface Book { ... }` with no equals sign), but the end result is the same: `Book` is now a name you can use anywhere you'd otherwise have to write out `{ title: string; author: string; price: number; inStock: boolean }`.

## Type aliases aren't just for objects

This is where `type` starts to show what makes it different. An `interface` can only describe the shape of an object. A `type` alias can name *any* type, including simple ones and combinations of values.

For example, BookHaven might want a type that represents just the genres it sells:

```typescript
type Genre = "fiction" | "non-fiction" | "poetry" | "reference";

function describeGenre(genre: Genre): string {
  return `This book is filed under: ${genre}`;
}

describeGenre("poetry");
```

That `|` is called a **union** (a type made by joining several possible values together, meaning "this could be any one of these"). `Genre` isn't an object shape at all; it's just a name for "one of these four strings." An `interface` can't do that, but a `type` alias can.

You can also use a type alias to name a simpler thing, like a price that's always a number:

```typescript
type Price = number;

function formatPrice(price: Price): string {
  return `$${price.toFixed(2)}`;
}
```

## Using a type alias inside another type

Type aliases combine nicely. You could tighten up the `Book` shape so that instead of any string, `author` only accepts genres you actually stock:

```typescript
type Book = {
  title: string;
  author: string;
  price: Price;
  inStock: boolean;
  genre: Genre;
};

const dune: Book = {
  title: "Dune",
  author: "Frank Herbert",
  price: 12.99,
  inStock: true,
  genre: "fiction",
};
```

Now if someone tries to set `genre` to `"mystery"`, TypeScript will complain, because `"mystery"` isn't one of the values listed in `Genre`.

## type or interface: which one should you reach for?

Since `interface` and `type` can both describe an object shape like `Book`, it's natural to wonder which one to pick. A simple rule of thumb that works for most everyday code: reach for `interface` as your default for object shapes, especially if you think you might want to extend it later, and reach for `type` when you're naming something that isn't just an object, like a union of specific values, or a shorthand for a simpler type. You'll see both used across real BookHaven-style code, and that's completely normal.

## Try it

BookHaven wants to track how a book was published. Create a type alias called `Format` that's a union of the strings `"hardcover"`, `"paperback"`, and `"ebook"`. Then create a `Book` type alias with `title` (string), `price` (number), and `format` (your new `Format` type). Finally, declare a `const` variable of type `Book` for a paperback book of your choosing, and log a sentence describing it with `console.log`.
