## Building the store

```python
# rag_store.py
import os
import ollama

EMBED_MODEL = "nomic-embed-text"
DOCS_DIR = "docs"

def load_chunks() -> list[dict]:
    chunks = []
    for filename in sorted(os.listdir(DOCS_DIR)):
        if not filename.endswith(".md"):
            continue
        with open(os.path.join(DOCS_DIR, filename), encoding="utf-8") as f:
            text = f.read()
        chunks.append({"source_doc": filename, "text": text})
    return chunks

def embed(text: str) -> list[float]:
    response = ollama.embeddings(model=EMBED_MODEL, prompt=text)
    return response.embedding

def build_store() -> list[dict]:
    chunks = load_chunks()
    for chunk in chunks:
        chunk["embedding"] = embed(chunk["text"])
    return chunks
```

Fernwood's five doc files are each short enough to treat as one chunk per file, per Module 4's note. `build_store()` embeds all five once, in memory, no vector database needed at this scale.

## Building the pipeline

```python
# rag_pipeline.py
import ollama
from rag_store import build_store, embed

GEN_MODEL = "llama3.2:3b"
TOP_K = 2

SYSTEM_PROMPT = """You are a support assistant for Fernwood, a project management app.
Answer the user's question using ONLY the CONTEXT below. If the answer is not
contained in the CONTEXT, say exactly: "Not documented." Do not use any
outside knowledge."""

def cosine_similarity(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    norm_a = sum(x * x for x in a) ** 0.5
    norm_b = sum(y * y for y in b) ** 0.5
    return dot / (norm_a * norm_b)

class RagPipeline:
    def __init__(self):
        self.store = build_store()

    def retrieve(self, question: str, top_k: int = TOP_K) -> list[dict]:
        q_embedding = embed(question)
        scored = [
            (cosine_similarity(q_embedding, chunk["embedding"]), chunk)
            for chunk in self.store
        ]
        scored.sort(key=lambda pair: pair[0], reverse=True)
        return [chunk for _, chunk in scored[:top_k]]

    def ask(self, question: str, top_k: int = TOP_K) -> dict:
        retrieved = self.retrieve(question, top_k=top_k)
        context = "\n\n".join(chunk["text"] for chunk in retrieved)
        prompt = f"CONTEXT:\n{context}\n\nQUESTION:\n{question}"
        response = ollama.chat(
            model=GEN_MODEL,
            messages=[
                {"role": "system", "content": SYSTEM_PROMPT},
                {"role": "user", "content": prompt},
            ],
        )
        return {
            "question": question,
            "answer": response.message.content,
            "retrieved_contexts": [c["text"] for c in retrieved],
            "retrieved_docs": [c["source_doc"] for c in retrieved],
        }
```

`retrieve()` is Module 4's cosine-similarity comparison, run against all five chunks instead of two. `ask()` retrieves, builds a context block, and generates, the same `ollama.chat()` call from Modules 1–2, now with retrieved context standing in for the source the model didn't have back then.

## Running it against the golden dataset

```python
# run_rag_over_dataset.py
import json
from rag_pipeline import RagPipeline

with open("golden_dataset.json") as f:
    dataset = json.load(f)

pipeline = RagPipeline()

for case in dataset["cases"]:
    result = pipeline.ask(case["question"])
    print(f"[{case['id']}] {case['question']}")
    print(f"  retrieved: {result['retrieved_docs']}")
    print(f"  answer:    {result['answer']}")
    print(f"  reference: {case['reference_answer']}")
    print()
```

Run it:

```bash
python run_rag_over_dataset.py
```

**Run it now.** Read through all 12 results next to their reference answers. Some will look right. That's expected. You're about to look closely at one that doesn't.

## Triggering a real retrieval miss

Ask a question that means the same thing as something in the docs, but doesn't share the docs' vocabulary, and print every chunk's similarity score so you can see the full ranking:

```python
# experiments/retrieval_miss.py
from rag_pipeline import RagPipeline, cosine_similarity
from rag_store import embed

pipeline = RagPipeline()
question = "How do I mark something as finished?"

q_embedding = embed(question)
scores = [
    (cosine_similarity(q_embedding, chunk["embedding"]), chunk["source_doc"])
    for chunk in pipeline.store
]
scores.sort(key=lambda pair: pair[0], reverse=True)

for score, source_doc in scores:
    print(f"{score:.4f}  {source_doc}")
```

The real answer lives in `projects-and-tasks.md` ("a status of To Do, In Progress, or Done"), but "mark something as finished" doesn't share that doc's vocabulary, and `data-export-and-deletion.md` scores highest, with `projects-and-tasks.md` only barely ahead of the rest. That's close enough for `TOP_K` to decide the outcome. Confirm it end-to-end at two different `top_k` values:

```python
# experiments/confirm_miss.py
from rag_pipeline import RagPipeline

pipeline = RagPipeline()

for k in (1, 2):
    result = pipeline.ask("How do I mark something as finished?", top_k=k)
    print(f"top_k={k}  retrieved={result['retrieved_docs']}")
    print(f"  answer: {result['answer']}")
```

**Run it.** At `top_k=1`, only `data-export-and-deletion.md` (the wrong document) gets retrieved. `projects-and-tasks.md` never makes it into context at all: a real, reproduced **retrieval miss**. Watch what the model does with it: it correctly says `"Not documented."` The generation step did exactly what its system prompt told it to. **The failure happened one stage earlier, in retrieval, not generation.** Module 8 formalizes exactly this kind of stage-by-stage diagnosis.

At `top_k=2`, `projects-and-tasks.md` now makes it into context alongside the wrong document, and the answer becomes correct. Same question, same docs, same model. The only thing that changed was how many chunks retrieval was allowed to return. That single variable is the entire difference between a hallucination-shaped failure and a correct answer.

If your own run doesn't reproduce this exact ranking, that's useful information too. Check the raw scores you printed above and note how close `data-export-and-deletion.md` and `projects-and-tasks.md` actually came. Retrieval ranking depends on your embedding model's exact behavior, so treat "how close did the scores come" as the real signal, not just "did the miss literally occur."

## Now run all 12 questions

```bash
python run_rag_over_dataset.py
```

Read every answer next to its reference. Expect more than one mismatch, and not all of them will be retrieval misses. Watch closely for cases where `retrieved_docs` already contains the correct source document and the answer is *still* wrong (often an overly cautious `"Not documented."` on a question the context actually answers). That's a **generation failure**, not a retrieval failure: the right material reached the model and it still didn't use it correctly. Both failure shapes are real and both are common. Module 8 is entirely about telling them apart methodically instead of guessing.

## QE lesson

A RAG system passing on your first few smoke-test questions doesn't mean it's reliable. It means you haven't found where wording diverges from the docs yet. This is the same lesson as testing any search or matching feature: the happy-path query almost always works, and the real bugs live in inputs that are correct but *phrased differently* than whatever the system was implicitly tuned against.
