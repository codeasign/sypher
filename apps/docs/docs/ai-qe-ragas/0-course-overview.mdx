## What this course is

This is an **AI Quality Engineering course that uses RAGAS as its evaluation tool.** It is not a RAGAS API tutorial. If you finish this course able to recite RAGAS class names but unable to explain *why* an evaluation score dropped, the course has failed at its actual goal. RAGAS shows up because it's a working answer to a QE problem — how do you get evidence about the quality of a system that doesn't return the same output twice — not because the tool is the subject.

You already know how to test deterministic software: write a test case, define expected output, run it, compare, pass or fail. This course is about what changes when the thing under test is a RAG (Retrieval-Augmented Generation) system built on a language model, where "expected output" stops being a single fixed string and "pass or fail" stops being self-evident. Every technique here is the AI-testing analogue of something you already know: a golden dataset is a test suite, a RAGAS metric is an oracle, a baseline is a baseline, a CI quality gate is a CI quality gate.

## What this course isn't

- Not a general LLM or prompt-engineering course.
- Not a deep dive into embedding models, vector database internals, or ML theory — RAG is covered at the depth a QE needs to test one, not build one from research papers.
- Not a tour of every evaluation framework that exists — RAGAS is the one tool used throughout, chosen because it's open-source, runs locally against Ollama, and is built specifically for RAG evaluation.
- Not a course where you read about a technique and move on — every module extends one real project you build with your own hands.

## The two questions this course is building you toward

By Module 15, you should be able to answer both of these about a real AI/RAG system, using evidence, not a guess:

1. **How do I know whether my AI/RAG system is actually getting better?**
2. **When my AI evaluation fails, how do I determine whether the problem is the test data, retrieval, prompt, model, evaluator, or quality gate?**

Every module between here and the capstone is building a piece of the answer to one or both of these. The capstone doesn't introduce new technique — it connects the pieces you've already built and uses them to answer both questions for real, against your own finished project.

## Required loop, every module

Past the earliest foundational modules, every new technique follows the same eight steps: **concept → example → hands-on → break it → observe → diagnose → fix → QE lesson.** You will deliberately cause real failures in your own running project — a retrieval miss, a faithfulness drop, a miscalibrated judge — and work each one back to a root cause, the same discipline you'd apply investigating a flaky test or a production incident. The last step always names the transferable testing principle, not just the AI-specific fix.

## Discipline this course holds you to

- **A golden dataset is an engineered artifact, not free output from an LLM.** Anything AI-generated gets reviewed and corrected by you before it's trusted.
- **No arbitrary thresholds.** You will never see "0.8 means good" in this course — a score's meaning depends on your use case, your dataset, your baseline, and your risk tolerance, and Module 7 makes that explicit.
- **No fabricated numbers.** Every metric score you see in this course is either a real result you produced by running the code, or an explicit placeholder — never an invented decimal presented as ground truth.
- **Correctness and user experience are separate axes.** Module 11 evaluates them separately on purpose — a technically correct answer can still be a bad answer.
- **Evaluation reduces risk; it doesn't prove correctness.** You'll see language like "increases confidence" and "identifies potential problems" throughout — never "proves."

## Stack

**Ollama**, running language models locally on your own machine — used continuously from Module 0 through the capstone, not as a one-off setup step. **RAGAS**, an open-source Python library for evaluating RAG and LLM outputs, wired to your local Ollama models rather than a hosted API. Everything in this course runs on your own hardware.

## What's next

Module 0 (Setup) gets Ollama and RAGAS both running and verified — a real model response and a real RAGAS import — before Module 1 starts the first hands-on work.
