## Page purpose

`eval_log.jsonl` has everything a QE needs to investigate a failure — and it's still a wall of JSON no one wants to read to understand "how did today's run go?" This page turns raw observability data into a report a human actually reads, completing Milestone 12 and producing the artifact that makes this framework legible to someone who didn't build it — including, in Module 24, an interviewer.

## Learning objectives

By the end of this page, you should be able to:

- Turn a raw `eval_log.jsonl` into a summarized, human-readable report.
- Group failures by category so patterns are visible at a glance instead of buried in a scroll of JSON.
- Explain why "QE-readable" is a real design constraint, not a cosmetic afterthought.

## From raw log to summary

```python
# llmqe/reporting/report.py
from collections import Counter
from llmqe.observability.logger import read_log


def summarize(entries: list[dict]) -> dict:
    total = len(entries)
    passed = sum(1 for e in entries if e["passed"])
    failures = [e for e in entries if not e["passed"]]
    by_category = Counter(e["failure_category"] for e in failures)
    avg_latency = sum(e["latency_seconds"] for e in entries) / total if total else 0

    return {
        "total_runs": total,
        "passed": passed,
        "failed": len(failures),
        "pass_rate": passed / total if total else 0,
        "failures_by_category": dict(by_category),
        "average_latency_seconds": avg_latency,
        "failures": failures,
    }
```

## Rendering it as something a QE reads, not parses

```python
def render_report(summary: dict) -> str:
    lines = [
        "# LLM Quality & Evaluation Framework — Run Report",
        "",
        f"**Total runs:** {summary['total_runs']}",
        f"**Passed:** {summary['passed']} ({summary['pass_rate']:.0%})",
        f"**Failed:** {summary['failed']}",
        f"**Average latency:** {summary['average_latency_seconds']:.2f}s",
        "",
        "## Failures by category",
        "",
    ]
    if not summary["failures_by_category"]:
        lines.append("None. ")
    for category, count in summary["failures_by_category"].items():
        lines.append(f"- **{category}**: {count}")

    if summary["failures"]:
        lines += ["", "## Failure details", ""]
        for f in summary["failures"]:
            lines.append(f"- `{f['test_case_id']}` — {f['failure_category']} — {f['reason']}")

    return "\n".join(lines)


def write_report(path: str = "llmqe/reporting/latest_report.md") -> None:
    entries = read_log()
    summary = summarize(entries)
    report = render_report(summary)
    with open(path, "w") as f:
        f.write(report)
    print(report)
```

**Run it** after a batch of `run_and_log()` calls from Module 17 — `write_report()` reads the accumulated log and produces a short Markdown summary: pass rate, failure counts grouped by category, and a details section listing exactly which test cases failed and why.

## Why "QE-readable" is a real constraint

A report a QE has to mentally parse — scanning raw JSON for a `"passed": false` here and there — gets skipped under time pressure, which defeats the entire point of building it. `render_report()`'s design choices are deliberate for that reason: pass rate and category counts up top, so a QE scanning quickly gets the shape of the run in five seconds; failure details below, so anyone who needs specifics doesn't have to go back to the raw log; and Markdown output, so it renders cleanly wherever it's pasted — a PR description, a Slack message, a CI job summary (Module 19's subject next). A report nobody reads is worse than no report at all — it creates the appearance of visibility without the substance.
