## Adding citation to the contract

So far, the assistant's answer doesn't say *which* document it drew from — which means a wrong answer gives you no way to check whether it even looked at the right source. Extend the RAG system prompt from Module 9 with one more field:

```python
# llmqe/rag/assistant.py (RAG_SYSTEM_PROMPT, updated)
RAG_SYSTEM_PROMPT = """\
You are Vespera Helpdesk's internal product assistant. You will be given \
retrieved documentation (each piece labeled with a source id) and a \
question. Answer using ONLY the retrieved documentation — if it doesn't \
contain the answer, say so explicitly instead of guessing.

Respond with JSON only:
{"answer": "...", "topic": "billing|security|product|other", "source_doc_id": "<id of the document the answer came from, or null>"}
"""
```

And label each chunk with its id when building the context string:

```python
# llmqe/rag/assistant.py (ask_with_retrieval, updated)
def ask_with_retrieval(question: str, retriever: Retriever, client: OllamaClient) -> dict:
    results = retriever.retrieve(question)
    context = "\n".join(f"[{r['document']['id']}] {r['document']['text']}" for r in results)
    prompt = f"Retrieved documentation:\n{context}\n\nQuestion: {question}"
    result = client.ask_with_system(RAG_SYSTEM_PROMPT, prompt)
    return {"response": result, "retrieved": results}
```

## Citation validation

A citation can be wrong in two different ways, and they map to two different problems:

```python
# llmqe/rag/rag_eval.py (continued)
def citation_is_honest(source_doc_id: str | None, retrieved_ids: list[str]) -> bool:
    """A citation is honest if it names a document that was actually
    retrieved — even if it's the wrong one. Citing a document that was
    never shown to the model is a generation failure: a fabricated source."""
    return source_doc_id is None or source_doc_id in retrieved_ids


def citation_is_correct(source_doc_id: str | None, expected_doc_id: str) -> bool:
    """A citation is correct if it names the right document. This can be
    honest but wrong (cited a real retrieved doc, just not the best one)."""
    return source_doc_id == expected_doc_id
```

**Honest-but-wrong** and **fabricated** are different severities: a citation that names a real (if imperfect) retrieved document is at worst a relevance problem you already know how to diagnose from Module 10. A citation that names a document *never retrieved at all* is the AI equivalent of making up a footnote — a pure generation failure, independent of anything retrieval did.

## Groundedness scoring

**Groundedness** checks whether an answer's specific claims are actually backed by the retrieved context, rather than invented on top of it. A simple, honest rule-based version: extract every number the answer states, and confirm each one appears somewhere in the retrieved context.

```python
# llmqe/rag/rag_eval.py (continued)
import re

def groundedness_score(answer: str, retrieved_context: str) -> float:
    """Returns the fraction of numeric claims in the answer that are
    also present in the retrieved context. 1.0 = every number is
    traceable to the source; lower scores flag likely fabrication."""
    answer_numbers = set(re.findall(r"\d+", answer))
    if not answer_numbers:
        return 1.0  # nothing numeric to check — not a proof of correctness, just nothing to flag here
    context_numbers = set(re.findall(r"\d+", retrieved_context))
    grounded = answer_numbers & context_numbers
    return len(grounded) / len(answer_numbers)
```

Like Module 5's rule-based hallucination check, be honest about this technique's limit out loud: it only catches *numeric* fabrication, and only when the fabricated number differs from every number actually present in context. It won't catch a fabricated non-numeric claim ("includes a dedicated Slack channel," said of a plan whose document never mentions one) — that gap is exactly where Module 7's LLM-as-a-judge, applied to groundedness instead of general quality, would extend this further; this page keeps the rule-based version to stay explainable and fast for CI use in Module 19.

## Failure: a missing document, revisited with citation

Re-run Module 10's burst-limit question and check the citation this time:

```python
result = ask_with_retrieval("What happens if I burst above my rate limit for a few seconds?", retriever, client)
parsed = json.loads(result["response"].text)
retrieved_ids = [r["document"]["id"] for r in result["retrieved"]]

print(parsed["source_doc_id"], retrieved_ids)
```

**Symptom:** the assistant cites `"free-plan"` as its source for a burst-limit answer, even though `free-plan`'s text says nothing about bursting.

**Investigation, using the separation principle:** was `free-plan` actually retrieved? Yes — `retrieved_ids` includes it, so `citation_is_honest()` passes; this is not a fabricated citation. Does `free-plan`'s text answer the question? No — this is the same missing-document gap Module 10 already diagnosed.

**Root cause:** unchanged from Module 10 — no document covers burst limits. What citation validation adds here isn't a new root cause, it's *proof*: you can now show, mechanically, that the model cited a real-but-irrelevant document instead of declining, rather than inferring it from reading the answer's prose.

**Fix:** the same fix as Module 10 — strengthen the decline behavior, tested directly in `tests/test_rag_out_of_domain.py`. Citation validation doesn't change the fix; it makes the failure easier to catch automatically instead of requiring a human to notice a subtly-off answer.

## Failure: conflicting documents

Add a second, conflicting document to a test-only copy of the knowledge base — a common real-world case where an old policy document wasn't retired when a new one was published:

```python
CONFLICTING_TEST_DOCS = [
    {"id": "pro-plan", "text": "Vespera Pro plan: includes SSO for enterprise identity providers, email support with 1 business day response time."},
    {"id": "pro-plan-legacy-2024", "text": "Vespera Pro plan (2024): includes SSO and phone support during business hours."},
]
```

**Symptom:** asked "does the Pro plan include phone support?", the assistant sometimes cites `pro-plan` (correct, current: no phone support) and sometimes `pro-plan-legacy-2024` (outdated: says yes) — an inconsistent answer to the same question.

**Investigation, using the separation principle:** was retrieval at fault? No — both documents are genuinely relevant to the question; retrieving both is *correct* behavior, not a bug. Is generation at fault? Yes — the model is picking between two retrieved documents without any signal for which one is authoritative, and picking inconsistently.

**Root cause:** the knowledge base itself contains an unresolved conflict, and nothing in the retrieved context or the system prompt tells the model which source to prefer.

**Fix:** two independent fixes, at two different layers — don't let the code fix stand in for the content fix. At the content layer, Vespera's real documentation should retire outdated pages (outside what testing can do). At the code layer, the retriever or prompt can be taught to prefer freshness (e.g., a `last_updated` field on each document, with instructions to prefer the more recent source when documents conflict) — a real improvement, but one that still depends on the content team tagging documents accurately.

**Prevention:** test with a deliberately conflicting pair, as done here, before your real knowledge base ever accumulates one — it's far easier to design the "prefer the newer source" behavior on purpose than to discover the gap in production.
