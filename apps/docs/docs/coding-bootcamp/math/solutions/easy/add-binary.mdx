# Add Binary — Solution

## Problem Overview

Given two binary strings, return their sum as a binary string, with no leading zeros.

## Brute Force Approach

Convert both strings to integers, add them, convert the sum back to a binary string. This works and is genuinely simple, but it silently depends on the language's integer type being large enough — for the stated constraint (`length up to 10^4`), the numeric value can be astronomically larger than any fixed-width integer (`int`, `long`, even 64-bit), so this approach only works reliably in a language with arbitrary-precision integers built in (Python's `int`).

**Complexity Analysis:**
- **Time:** O(n) for the conversions (where language support allows).
- **Space:** O(n) for the result string.

## Optimal Approach: Digit-by-Digit Addition with Carry

**Idea:** Do exactly what you'd do adding two numbers by hand on paper — walk both strings from the *last* character (least significant bit) to the first, adding corresponding bits plus a running carry, one position at a time. This works regardless of string length, with no dependency on any integer type's size.

**Algorithm:**
1. Point two indices at the last character of `a` and `b`. Start `carry = 0`.
2. While either index is still valid, or `carry` is nonzero:
   - Read the current bit from `a` (or `0` if that index has run off the start of the string).
   - Read the current bit from `b` the same way.
   - `total = bitA + bitB + carry`.
   - Append `total % 2` to the result, set `carry = total / 2` (integer division).
   - Move both indices one position left.
3. The result was built least-significant-bit first — reverse it before returning.

**Why This Works:** This is exactly manual long addition, just in base 2 instead of base 10. Treating a missing/out-of-range character as `0` naturally handles strings of different lengths without any special-casing — the shorter string just "runs out" and contributes `0` for the rest of the addition, same as it would on paper.

**Complexity Analysis:**
- **Time:** O(max(len(a), len(b))) — one pass over the longer string, with at most one extra step if there's a final carry.
- **Space:** O(max(len(a), len(b))) for the result string.

## Deep Dive

### Visual Walkthrough

For `a = "1010"`, `b = "1011"`:

```
        1 0 1 0
      + 1 0 1 1
      ---------
carry: 1 1 0 0
result:0 1 0 1

position 0 (rightmost): 0 + 1 + carry(0) = 1 -> digit 1, carry 0
position 1:             1 + 1 + carry(0) = 2 -> digit 0, carry 1
position 2:             0 + 0 + carry(1) = 1 -> digit 1, carry 0
position 3 (leftmost):  1 + 1 + carry(0) = 2 -> digit 0, carry 1
final carry:            1 -> prepend an extra '1'

built (LSB first): 1 0 1 0 1  ->  reversed: "10101"
```

### Edge Cases to Consider

- **Different-length strings**: e.g. `"1000"` and `"111"` — once the shorter string's index runs out, it just contributes `0` for the remaining positions, while the longer string's bits keep being processed normally.
- **A leftover carry past both strings**: e.g. `"11111111" + "1"` — after both strings are exhausted, `carry` can still be `1`, which must be appended as one more digit (this is exactly what makes the result string sometimes *longer* than both inputs).
- **Both inputs are `"0"`**: sums to `"0"` — no leading-zero issue since the result has exactly one digit.
- **Equal-length strings summing with a carry all the way through**: e.g. `"1111" + "1111"` — every position produces a carry, ending in one final leftover carry bit.

def add_binary(a: str, b: str) -> str:
    i, j = len(a) - 1, len(b) - 1
    carry = 0
    result = []
    while i >= 0 or j >= 0 or carry:
        total = carry
        if i >= 0:
            total += int(a[i])
            i -= 1
        if j >= 0:
            total += int(b[j])
            j -= 1
        result.append(str(total % 2))
        carry = total // 2
    return ''.join(reversed(result))

fn add_binary(a: &str, b: &str) -> String {
    let a: Vec<u8> = a.bytes().collect();
    let b: Vec<u8> = b.bytes().collect();
    let mut i = a.len() as i32 - 1;
    let mut j = b.len() as i32 - 1;
    let mut carry = 0;
    let mut result: Vec<u8> = Vec::new();
    while i >= 0 || j >= 0 || carry != 0 {

        if i >= 0 {

            i -= 1;
        }

            total += (b[j as usize] - b'0') as i32;
            j -= 1;
        }
        result.push(b'0' + (total % 2) as u8);
        carry = total / 2;
    }
    result.reverse();
    String::from_utf8(result).unwrap()
}

char* addBinary(char* a, char* b) {
    int la = strlen(a), lb = strlen(b);
    int maxLen = (la > lb ? la : lb) + 2;   // +1 for possible carry, +1 for '\0'
    char* result = (char*)malloc(maxLen * sizeof(char));
    int i = la - 1, j = lb - 1;
    int carry = 0, pos = 0;
    while (i >= 0 || j >= 0 || carry) {
        int total = carry;
        if (i >= 0) total += a[i--] - '0';
        if (j >= 0) total += b[j--] - '0';
        result[pos++] = (char)('0' + total % 2);
        carry = total / 2;
    }
    result[pos] = '\0';
    // reverse in place
    for (int l = 0, r = pos - 1; l < r; l++, r--) {
        char tmp = result[l]; result[l] = result[r]; result[r] = tmp;
    }
    return result;
}

## Key Takeaways

- Digit-by-digit addition with a carry works identically in any base — this is the same algorithm you'd use for base-10 long addition, just with `% 2` / `/ 2` instead of `% 10` / `/ 10`.
- Treating an out-of-range index as digit `0` is a clean way to handle two inputs of different lengths without special-casing the shorter one.
- Never rely on converting to a fixed-width integer type and back — the constraint (`up to 10^4` characters) describes numbers far larger than any 64-bit integer can hold; only an arbitrary-precision type (or the digit-by-digit approach) is safe in general.
- Don't forget the final carry — it can produce a result string one character *longer* than either input.
