# Minimum Moves to Seat Everyone — Solution

## Problem Overview

Given `n` seat positions and `n` student positions, assign each student to a distinct seat, minimizing the total distance moved.

## Brute Force Approach

**Idea:** Try every possible assignment (permutation) of students to seats, compute the total distance for each, and keep the minimum.

**Complexity Analysis:**
- **Time:** O(n!) — every permutation.
- **Space:** O(n).

## Optimal Approach: Sort Both, Pair by Position

**Idea:** Sort the seats and sort the students independently, then pair them up in order — the smallest seat position with the smallest student position, the second-smallest with the second-smallest, and so on. Sum the absolute differences of each pair.

**Algorithm:**
1. Sort `seats` in ascending order.
2. Sort `students` in ascending order.
3. Sum `abs(seats[i] - students[i])` for every index `i`.

**Why This Works:** This is a classic exchange-argument greedy proof: suppose an optimal assignment has two students `A` and `B` (with `A`'s seat position less than `B`'s) assigned to seats in "crossed" order — i.e., `A` gets the farther seat and `B` gets the nearer one. Swapping their seat assignments so the order is no longer crossed can never *increase* the total distance (this can be verified by case analysis on the relative ordering of the four positions involved), and sometimes strictly decreases it. Since any assignment with a "crossing" can be improved (or left equal) by uncrossing it, the fully sorted, non-crossing pairing is always at least as good as any other assignment — making it optimal.

**Complexity Analysis:**
- **Time:** O(n log n) — dominated by the two sorts; the summation itself is O(n).
- **Space:** O(1) extra (beyond the space used by the sort itself, which varies by language/implementation).

## Deep Dive

### Visual Walkthrough

For `seats = [4, 1, 5, 9]`, `students = [1, 3, 2, 6]`:

```
sorted seats:    [1, 4, 5, 9]
sorted students: [1, 2, 3, 6]

pair (1,1): |1-1| = 0
pair (4,2): |4-2| = 2
pair (5,3): |5-3| = 2
pair (9,6): |9-6| = 3

total = 0 + 2 + 2 + 3 = 7
```

### Edge Cases to Consider

- **A single seat and student** (`n = 1`): sorting is a no-op, the answer is just the absolute difference of the two values.
- **Seats and students already in matching sorted order** (e.g. `seats=[1,2,3,4,5]`, `students=[5,4,3,2,1]`): after sorting both, they become *identical* sequences, giving a total of `0` — every student is already exactly where they need to be, even though the *original* (unsorted) arrays looked completely reversed relative to each other.
- **Duplicate positions** (e.g. `seats=[2,2,6,6]`): sorting handles duplicates the same as any other values — ties don't need special handling, since it doesn't matter *which* of two identical seats a student is conceptually assigned to.
- **All seats/students at the same position** (e.g. `seats=[1,1,1]`, `students=[3,3,3]`): every pair contributes the same difference, giving `n` times that single distance.

class Solution {
    public int minMovesToSeat(int[] seats, int[] students) {
        int[] s = seats.clone();
        int[] t = students.clone();
        Arrays.sort(s);
        Arrays.sort(t);
        int total = 0;
        for (int i = 0; i < s.length; i++) {
            total += Math.abs(s[i] - t[i]);

        return total;

## Key Takeaways

- "Sort both, pair by index" is a recurring greedy pattern whenever you're matching two independent sequences to minimize (or maximize) a sum of pairwise differences — it's worth recognizing on sight.
- The exchange argument (showing any "crossed" assignment can be uncrossed without increasing cost) is the standard way to *prove* a sorted pairing is optimal, not just observe that it seems to work on examples.
- Sorting the original arrays in place (Rust, or C/C++ if mutating is acceptable) vs. sorting copies (Java, C#, JS/TS clone first) is purely a matter of whether the problem's contract allows mutating the input — check `starterCode`'s parameter types (`&mut` vs `&`, `int[]` passed by reference, etc.) before deciding.
