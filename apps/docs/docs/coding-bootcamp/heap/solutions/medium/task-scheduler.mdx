# Task Scheduler — Solution

## Problem Overview

Given a list of CPU tasks and a cooldown period `n` between two executions of the *same* task, find the minimum number of time units (including idle slots) needed to run them all.

## Brute Force Approach

**Idea:** Simulate the schedule tick by tick with a max-heap of remaining task counts and a cooldown queue, greedily running whichever available task currently has the highest remaining count.

**Complexity Analysis:**
- **Time:** O(total time units × log 26) — a heap operation per tick, bounded by a constant-size (26 uppercase letters) alphabet.
- **Space:** O(1) — at most 26 distinct tasks.

This simulation works and is a legitimate way to solve the problem, but the counting-based formula below reaches the same answer in a single O(n) pass with no simulation at all.

## Optimal Approach: Frequency-Count Formula

**Idea:** The task with the **highest frequency** is the bottleneck — it forces `(maxFreq - 1)` gaps between its own executions, each gap at least `n` long. Every other task (up to `n` per gap) can be slotted into those gaps for free. If several tasks are tied for the highest frequency, each of them needs one more slot at the very end of the schedule.

**Algorithm:**
1. Count the frequency of each task.
2. Find `maxFreq`, the highest frequency, and `maxCount`, how many distinct tasks share that frequency.
3. Compute the "skeleton" length: `(maxFreq - 1) * (n + 1) + maxCount` — this is the length of a schedule built around the most frequent task(s), including all forced idle slots.
4. Return `max(len(tasks), skeleton)` — if there are enough other tasks to completely fill every gap, the schedule needs no idle time at all, and the true answer is simply the number of tasks.

**Why This Works:** Picture the most frequent task's executions as `maxFreq` fixed posts, each followed by a gap of exactly `n` slots (except the last one). That skeleton has `(maxFreq - 1) * (n + 1) + 1` slots for one bottleneck task; each additional task tied for the max frequency needs its own trailing slot, contributing `+1` more per tie. Every *other* task — no matter how the scheduler is actually simulated — can always be packed into the existing gaps without lengthening the schedule, because there are strictly more gap slots available than lower-frequency tasks to fill them (a consequence of `maxFreq` being the highest count). The only way the schedule needs to be *longer* than the skeleton is if there are simply too many total tasks to fit in it — hence the `max` with `len(tasks)`.

**Complexity Analysis:**
- **Time:** O(n) — one pass to count frequencies (or O(1) if capped at 26 uppercase letters), one pass to find the max and its count.
- **Space:** O(1) — a fixed 26-entry frequency table.

## Deep Dive

### Visual Walkthrough

For `tasks = ["A","A","A","B","B","B"]`, `n = 2`:

```
maxFreq = 3 (both A and B appear 3 times) -> maxCount = 2

Skeleton around A: A _ _ A _ _ A   (length (3-1)*(2+1)+1 = 7)
Slot B into every gap:
A B _ A B _ A B                    (length 7 + 1 tie = 8)

Schedule: A B idle A B idle A B  -> 8 time units, matches expected output.
```

For `tasks = ["A","B","C","D","E","F"]`, `n = 2`:

```
maxFreq = 1, maxCount = 6
skeleton = (1-1)*(2+1) + 6 = 6
len(tasks) = 6

max(6, 6) = 6 -- every task is unique, so no idle time is ever needed.
```

### Edge Cases to Consider

- **`n == 0`** (no cooldown at all): `skeleton = (maxFreq-1)*1 + maxCount`, which always evaluates to at most `len(tasks)` — the `max` correctly falls back to `len(tasks)`, since with zero cooldown any order of tasks works with no idle time.
- **All tasks identical** (e.g. `"A A A A A"` with `n = 4`): every gap must be filled with idle time since there's only one distinct task, so the skeleton length is the true answer and dominates `len(tasks)`.
- **Enough distinct tasks to fill every gap**: the schedule collapses to exactly `len(tasks)`, since `len(tasks) >= skeleton` in that case.
- **A single task with no repeats** (e.g. `"A"`): `maxFreq = 1`, `maxCount = 1`, skeleton `= 0 * (n+1) + 1 = 1`, matching `len(tasks) = 1`.
- **A three-way (or more) tie for the maximum frequency**: `maxCount` scales up correctly since it counts every task at `maxFreq`, not just one.

from collections import Counter

def least_interval(tasks: list[str], n: int) -> int:
    freq = Counter(tasks)
    max_freq = max(freq.values())
    max_count = sum(1 for v in freq.values() if v == max_freq)
    return max(len(tasks), (max_freq - 1) * (n + 1) + max_count)

class Solution {
    public int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        for (char t : tasks) freq[t - 'A']++;
        int maxFreq = 0;
        for (int f : freq) maxFreq = Math.max(maxFreq, f);
        int maxCount = 0;
        for (int f : freq) if (f == maxFreq) maxCount++;
        return Math.max(tasks.length, (maxFreq - 1) * (n + 1) + maxCount);
    }

## Key Takeaways

- The most frequent task defines a "skeleton" schedule with `(maxFreq - 1)` mandatory gaps of length `n` — every other task gets packed into those gaps essentially for free.
- Ties for the maximum frequency each need one extra trailing slot (`maxCount`), since they can't share the very last position in the skeleton.
- The final `max(len(tasks), skeleton)` handles the case where there's enough task diversity to eliminate idle time entirely — the formula alone can undercount when the skeleton is smaller than the task list.
