# K Closest Points to Origin — Solution

## Problem Overview

Given a list of 2D points and an integer `k`, return the `k` points closest to the origin `(0, 0)`, using squared Euclidean distance (no `sqrt` needed since it's monotonic and only relative ordering matters).

## Brute Force Approach

**Idea:** Sort every point by its distance to the origin, then take the first `k`.

**Complexity Analysis:**
- **Time:** O(n log n) — a full sort of all points, even though only the smallest `k` are ever needed.
- **Space:** O(n) for the sorted copy.

This is a perfectly reasonable solution for this problem's constraints (`n <= 10^4`), and is exactly what the JavaScript/TypeScript/Rust/C#/Go solutions below do — sorting the whole array is simple, correct, and fast enough here. The max-heap approach below is the textbook "optimal" answer because it avoids sorting points that will never make the cut.

## Optimal Approach: Max-Heap of Size K

**Idea:** Maintain a max-heap capped at size `k`, keyed by squared distance. Push every point onto the heap; the moment the heap exceeds size `k`, pop the *farthest* point. Whatever remains after processing every point is exactly the `k` closest.

**Algorithm:**
1. For each point `(x, y)`, compute `dist = x*x + y*y`.
2. Push `(dist, x, y)` onto a max-heap (a heap ordered so the largest distance is always on top).
3. If the heap's size exceeds `k`, pop the top (farthest) entry — this discards the point that's currently worst among the survivors.
4. After processing every point, the heap holds exactly the `k` closest points.

**Why This Works:** A max-heap capped at size `k` is a classic "keep only the best `k` seen so far" structure: at any moment, the heap contains the `k` smallest-distance points encountered up to that point, because the only thing ever evicted is the single farthest point among the current `k + 1` candidates. By the time every point has been considered, only the true `k` closest can possibly remain, since any point farther than something already in a full heap gets discarded before it can push out something closer.

**Complexity Analysis:**
- **Time:** O(n log k) — each of the `n` points does at most one O(log k) heap push/pop, versus O(n log n) for sorting everything.
- **Space:** O(k) for the heap.

## Deep Dive

### Visual Walkthrough

For `points = [[3,3],[5,-1],[-2,4]]`, `k = 2`:

```
Distances: [3,3] -> 18   [5,-1] -> 26   [-2,4] -> 20

Push [3,3] (18):     heap = {18}
Push [5,-1] (26):    heap = {18, 26}
Push [-2,4] (20):    heap = {18, 26, 20}, size 3 > k=2 -> pop farthest (26)
                      heap = {18, 20}

Remaining points: [3,3] and [-2,4] -- the two closest, matching the expected answer.
```

### Edge Cases to Consider

- **`k == points.length`**: every point survives — the heap never exceeds size `k`, so nothing is ever popped.
- **All points equidistant from the origin** (e.g. all zeros, or points forming a circle): any `k` of them are equally valid answers — this course's harness canonicalizes the printed output by sorting the selected points, so the exact-match grading only depends on *which* points are chosen, not the order the algorithm found them in.
- **A tie exactly at the cutoff distance** (the k-th and (k+1)-th closest points are equidistant): both are equally "closest" and either could legitimately be selected — worth checking test data for this case specifically, since it can make the *set* of correct answers ambiguous rather than just its order (this file's test data was hand-verified to contain no such ties).
- **`k == 1`**: the heap degenerates to tracking a single running closest point.

import heapq

def k_closest(points: list[list[int]], k: int) -> list[list[int]]:
    heap = []
    for x, y in points:
        dist = x*x + y*y  # no sqrt needed for comparison
        heapq.heappush(heap, (-dist, x, y))  # max-heap via negative
        if len(heap) > k:
            heapq.heappop(heap)
    return [[x, y] for _, x, y in heap]

class Solution {
    public int[][] kClosest(int[][] points, int k) {
        PriorityQueue<int[]> maxHeap = new PriorityQueue<>((a, b) -> b[0] - a[0]);
        for (int[] p : points) {
            int dist = p[0] * p[0] + p[1] * p[1];
            maxHeap.offer(new int[]{dist, p[0], p[1]});
            if (maxHeap.size() > k) maxHeap.poll();
        }
        int[][] result = new int[maxHeap.size()][2];
        int i = 0;
        for (int[] entry : maxHeap) {
            result[i][0] = entry[1];
            result[i][1] = entry[2];
            i++;
        }
        return result;
    }
}

class Solution {
public:
    vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
        priority_queue<pair<int, pair<int, int>>> maxHeap;
        for (auto& p : points) {
            int dist = p[0] * p[0] + p[1] * p[1];
            maxHeap.push({dist, {p[0], p[1]}});
            if ((int)maxHeap.size() > k) maxHeap.pop();
        }
        vector<vector<int>> result;
        while (!maxHeap.empty()) {
            auto top = maxHeap.top();
            maxHeap.pop();
            result.push_back({top.second.first, top.second.second});
        }
        return result;
    }
};

int cmpDist(const void* a, const void* b) {
    int* pa = *(int**)a;
    int* pb = *(int**)b;
    int da = pa[0] * pa[0] + pa[1] * pa[1];
    int db = pb[0] * pb[0] + pb[1] * pb[1];
    return da - db;
}

func kClosest(points [][]int, k int) [][]int {

    copy(sorted, points)

        di := sorted[i][0]*sorted[i][0] + sorted[i][1]*sorted[i][1]
        dj := sorted[j][0]*sorted[j][0] + sorted[j][1]*sorted[j][1]
        return di < dj
    })

## Key Takeaways

- Squared distance avoids floating-point `sqrt` entirely — since `sqrt` is monotonically increasing, comparing squared distances gives the identical ordering.
- A size-capped max-heap is the standard "keep the best k" pattern: push everything, evict the current worst the moment the heap overflows.
- For this problem's constraints, a full sort-and-slice is simple and fast enough — the heap only pays off asymptotically once `k` is meaningfully smaller than `n`.
- Since "closest k points" allows any valid subset when there's no tie at the cutoff, this course's harness sorts the output before printing so exact-match grading only depends on which points were selected, not the order the algorithm happened to produce them in.
