# Decode Ways — Solution

## Problem Overview

Given a digit string, count how many ways it can be decoded back into letters using the mapping `A=1, B=2, ..., Z=26`. A leading zero anywhere a digit-group starts makes that grouping invalid.

## Brute Force Approach

**Idea:** Recursively try both choices at every position — decode one digit, or decode two digits (if valid) — and count how many full decodings succeed.

**Complexity Analysis:**
- **Time:** O(2^n) — each position can branch into two recursive calls.
- **Space:** O(n) — recursion depth.

**Why this could be better:** Many subproblems (suffixes of `s`) get recomputed repeatedly across different branches. Since the number of ways to decode a given position only depends on that position, this is a textbook case for dynamic programming.

## Optimal Approach: Dynamic Programming

**Idea:** Let `dp[i]` be the number of ways to decode the first `i` characters of `s`. Build it up left to right: at each position, a valid decoding either ends with a single-digit group (if that digit isn't `'0'`) or a two-digit group (if the two digits form a number between `10` and `26`).

**Algorithm:**
1. Base cases: `dp[0] = 1` (the empty prefix has exactly one, trivial, decoding), and immediately return `0` if `s[0] == '0'` (a string starting with `0` can never be decoded).
2. For each position `i` from `1` to `n - 1`: start `tmp = 0`.
   - If `s[i] != '0'`, the single digit `s[i]` is a valid one-character group — add `dp[i]` (equivalently, the running `curr` value from the previous iteration).
   - If the two-digit number formed by `s[i-1..i]` is between `10` and `26`, that pair is a valid two-character group — add `dp[i-1]` (the running `prev` value).
3. Roll `prev`/`curr` forward one position and repeat; the final `curr` is the answer.

**Why This Works:** Every valid decoding of the first `i+1` characters either treats the last character as its own group (in which case the rest of the decoding is any valid decoding of the first `i` characters) or treats the last two characters as a group (in which case the rest is any valid decoding of the first `i-1` characters). These two cases are mutually exclusive and cover every possibility, so the count at position `i+1` is exactly the sum of the counts at the two positions that could have led there — this is the recurrence relation directly, expressed as a rolling sum instead of an array.

**Complexity Analysis:**
- **Time:** O(n) — a single left-to-right pass.
- **Space:** O(1) — only the previous two DP values are ever needed, not the full array.

### Edge Cases to Consider

- **A string starting with `'0'`** (e.g. `"06"`): no valid decoding can ever begin with a zero digit standing alone, so the answer is immediately `0` — this must be checked before the loop even starts, since the loop's recurrence has no other way to rule it out.
- **A single `'0'` character**: also returns `0` directly via the same base-case check.
- **A run of multiple `'1'`s** (e.g. `"1111"`, `"11111"`): every adjacent pair is a valid two-digit group (`11 <= 26`), so the count grows following the Fibonacci sequence — a useful sanity check when verifying the recurrence by hand.
- **A `'0'` appearing mid-string with no valid two-digit grouping around it** (e.g. `"100"`, `"301"`): the `'0'` can never stand alone (invalid single-digit group) and if the digit before it can't form a valid `1x`/`2x` pair with it, the whole string becomes undecodable — the running count correctly collapses to `0` and stays there for the rest of the string.
- **A two-digit number greater than `26`** (e.g. `"27"`, `"99"`): the two-digit grouping is simply skipped (not added to `tmp`), leaving only the single-digit path.

def num_decodings(s: str) -> int:
    if not s or s[0] == '0':
        return 0
    prev, curr = 1, 1  # dp[i-2], dp[i-1]
    for i in range(1, len(s)):
        tmp = 0
        if s[i] != '0':
            tmp += curr
        if 10 <= int(s[i-1:i+1]) <= 26:
            tmp += prev
        prev, curr = curr, tmp
    return curr

class Solution {
    public int numDecodings(String s) {
        if (s.isEmpty() || s.charAt(0) == '0') return 0;
        int prev = 1, curr = 1;
        for (int i = 1; i < s.length(); i++) {
            int tmp = 0;
            if (s.charAt(i) != '0') tmp += curr;
            int two = Integer.parseInt(s.substring(i - 1, i + 1));
            if (two >= 10 && two <= 26) tmp += prev;
            prev = curr;
            curr = tmp;
        }
        return curr;
    }
}

## Key Takeaways

- The recurrence `dp[i] = dp[i-1] (if single-digit valid) + dp[i-2] (if two-digit valid)` is a direct translation of "every decoding ends with either a 1-digit or a 2-digit group."
- Only the previous two DP values are ever needed, collapsing an O(n)-space array into two rolling variables.
- A leading `'0'` anywhere it would need to stand alone as a group is what drives the count to `0` — worth tracing by hand on `"100"` or `"301"` to see how a single bad digit propagates through the rest of the string.
