# Construct BST from Preorder Traversal — Solution

## Problem Overview

Given the preorder traversal of a BST (a list of distinct integers), rebuild the exact tree it came from.

## Brute Force Approach

**Idea:** Insert each value into an initially-empty BST, one at a time, using standard BST insertion (compare to root, go left if smaller, right if bigger, repeat until you find an empty spot).

Since preorder always visits a node before either of its children, inserting values in preorder order naturally reconstructs the correct tree — no bounds-tracking needed, just repeated BST insertion.

**Complexity Analysis:**
- **Time:** O(n²) worst case — a skewed input (e.g. already-sorted) makes each insertion take O(k) to walk down k existing nodes, summing to O(n²).
- **Space:** O(n) for the tree, O(h) for the insertion recursion.

## Optimal Approach: Monotonic Stack

**Idea:** Process the array once, left to right, maintaining a stack of "ancestors that might still need a right child." For each new value, pop every stack entry smaller than it — those are exactly the ancestors this value is now to the right of. The **last node popped** (if any) is this value's parent, attached as its right child. If nothing was popped, the new value is instead the *left* child of whatever's now on top of the stack.

**Algorithm:**
1. Create the root from `preorder[0]`. Push it onto a stack.
2. For each remaining value:
   - Pop nodes off the stack while the top is smaller than the current value, remembering the last one popped.
   - If something was popped, attach the new node as that node's **right** child.
   - Otherwise, attach the new node as the **left** child of the (unpopped) node now on top of the stack.
   - Push the new node.
3. Return the root.

**Why This Works:** The stack always holds the chain of ancestors the next value *could* still be a right-descendant of, from most-recently-created back to the root, in decreasing value order (since nodes are popped once something exceeds them). A value that's still smaller than the stack top must be that node's left child (nothing has "closed off" that subtree yet). A value that's bigger than one or more stack entries means those subtrees are now finished, and the value becomes the right child of the deepest one it exceeds — the last one popped.

**Complexity Analysis:**
- **Time:** O(n) — every node is pushed once and popped at most once.
- **Space:** O(n) — the stack, worst case holding every node (for an already-sorted, right-leaning input).

## Deep Dive

### Visual Walkthrough

For `preorder = [8, 5, 1, 7, 10, 12]`:

```
value=8:  stack empty -> root.        stack: [8]
value=5:  5 < 8 (top), nothing popped -> left child of 8.
                                       stack: [8, 5]
value=1:  1 < 5 (top), nothing popped -> left child of 5.
                                       stack: [8, 5, 1]
value=7:  7 > 1 -> pop 1. 7 < 5 (new top) -> stop popping.
          last popped = 1 -> 7 becomes RIGHT child of 1.
                                       stack: [8, 5, 7]
value=10: 10 > 7 -> pop 7. 10 > 5 -> pop 5. 10 > 8 -> pop 8. stack empty.
          last popped = 8 -> 10 becomes RIGHT child of 8.
                                       stack: [10]
value=12: 12 > 10 -> pop 10. stack empty.
          last popped = 10 -> 12 becomes RIGHT child of 10.
                                       stack: [12]

Result:
        8
      /   \
     5     10
    / \      \
   1   7      12
```

### Edge Cases to Consider

- **Single element**: the root is created and nothing else runs — no stack operations needed.
- **Strictly ascending input** (`[1,2,3,4,5]`): every new value is bigger than everything on the stack, so it always becomes the right child of the last thing popped — the stack empties completely on every step after the first, producing a fully right-leaning chain.
- **Strictly descending input** (`[5,4,3,2,1]`): every new value is smaller than the stack top, so nothing is ever popped — every value becomes the left child of the previous one, producing a fully left-leaning chain.
- **Negative values**: comparisons work identically regardless of sign.

```python
def bst_from_preorder(preorder: list[int]):
    if not preorder:
        return None
    root = TreeNode(preorder[0])
    stack = [root]
    for val in preorder[1:]:
        node = TreeNode(val)
        parent = None

        if parent:
            parent.right = node            # closed off that subtree -- right child
        else:
            stack[-1].left = node          # still inside the top's subtree -- left child
```

```rust
fn bst_from_preorder(preorder: Vec<i32>) -> Option<Box<TreeNode>> {
    if preorder.is_empty() { return None; }

    // Build with raw pointers: the stack needs shared mutable access to nodes
    // it doesn't own outright yet (a node stays reachable via its parent's
    // left/right link once attached, while the stack independently tracks it
    // for the "who gets the next right child" decision).
    let mut root = Box::new(TreeNode::new(preorder[0]));
    let mut stack: Vec<*mut TreeNode> = vec![root.as_mut() as *mut TreeNode];

    for &val in preorder.iter().skip(1) {
        let mut parent: Option<*mut TreeNode> = None;
        unsafe {
            while let Some(&top) = stack.last() {
                if (*top).val < val {
                    parent = Some(top);
                    stack.pop();
                } else {
                    break;
                }
            }
            if let Some(p) = parent {
                (*p).right = Some(Box::new(TreeNode::new(val)));
                stack.push((*p).right.as_mut().unwrap().as_mut() as *mut TreeNode);
            } else {
                let top = *stack.last().unwrap();
                (*top).left = Some(Box::new(TreeNode::new(val)));
                stack.push((*top).left.as_mut().unwrap().as_mut() as *mut TreeNode);
            }
        }
    }
    Some(root)
}
```

```c
struct TreeNode* bstFromPreorder(int* preorder, int preorderSize) {
    if (preorderSize == 0) return NULL;
    struct TreeNode* root = (struct TreeNode*)malloc(sizeof(struct TreeNode));
    root->val = preorder[0]; root->left = NULL; root->right = NULL;

    struct TreeNode** stack = (struct TreeNode**)malloc(preorderSize * sizeof(struct TreeNode*));
    int top = 0;
    stack[top++] = root;

    for (int i = 1; i < preorderSize; i++) {
        struct TreeNode* node = (struct TreeNode*)malloc(sizeof(struct TreeNode));
        node->val = preorder[i]; node->left = NULL; node->right = NULL;

        struct TreeNode* parent = NULL;
        while (top > 0 && stack[top - 1]->val < preorder[i]) {
            parent = stack[--top];             // remember the last (deepest) one popped
        }
        if (parent) {
            parent->right = node;              // closed off that subtree -- right child
        } else {
            stack[top - 1]->left = node;       // still inside the top's subtree -- left child
        }
        stack[top++] = node;
    }
    free(stack);
    return root;
}
```

```go
func bstFromPreorder(preorder []int) *TreeNode {

        return nil
    }
    root := &TreeNode{Val: preorder[0]}

        } else {
            stack[len(stack)-1].Left = node          // still inside the top's subtree -- left child
        }
        stack = append(stack, node)
    }
    return root
}
```

## Key Takeaways

- Preorder traversal always visits a node before its children, so a value's position relative to the *current* set of unfinished ancestors is enough to place it correctly in one linear pass — no lookahead needed.
- The monotonic stack trick ("pop while smaller, the last one popped is the new right-child parent") is a reusable pattern for turning O(n²) repeated-insertion problems into O(n) single-pass ones.
- Preorder uniquely determines a BST's shape — this is why printing the reconstructed tree's own preorder traversal and comparing it to the input is a complete correctness check, not just a partial one.
