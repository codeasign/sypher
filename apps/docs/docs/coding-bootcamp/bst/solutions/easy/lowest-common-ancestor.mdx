# Lowest Common Ancestor of a BST — Solution

## Problem Overview

Given a BST and two values `p` and `q` known to exist in it, find the value of their lowest common ancestor — the deepest node that has both as descendants (a node counts as its own descendant).

## Brute Force Approach

Find the path from the root to `p` (a list of node values), find the path from the root to `q`, then walk both paths together and return the last value where they still agree. This works for *any* binary tree, not just a BST.

**Complexity Analysis:**
- **Time:** O(n) — each path can be up to the height of the tree, and finding a path is itself O(h).
- **Space:** O(h) — to store both paths.

## Optimal Approach: BST Property Walk

**Idea:** A general binary tree gives you no shortcut for finding either path except a full search. A *binary search tree* is different — at every node, you already know which subtree `p` and `q` must be in, just by comparing their values to the current node's value. No searching is needed at all.

**Algorithm:**
1. Start at the root.
2. If both `p` and `q` are less than the current node's value, the LCA must be in the left subtree — move to `node.left`.
3. If both `p` and `q` are greater than the current node's value, the LCA must be in the right subtree — move to `node.right`.
4. Otherwise (one is on each side, or one equals the current node's value), the current node is the LCA — return it.

**Why This Works:** As long as `p` and `q` are on the same side of a node, that node can't be their lowest common ancestor — a deeper node further down that same subtree is guaranteed to also be an ancestor of both. The first node where they *stop* being on the same side is, by definition, the deepest node that's still an ancestor of both — the LCA.

**Complexity Analysis:**
- **Time:** O(h), where `h` is the tree's height — at most one downward step per level, no backtracking.
- **Space:** O(1) with the iterative version (no recursion stack).

## Deep Dive

### Visual Walkthrough

For the tree below, finding `LCA(3, 5)`:

```
        6
      /   \
     2     8
    / \   / \
   0   4 7   9
      / \
     3   5

At 6: 3 < 6 and 5 < 6 -> both smaller -> go left to 2
At 2: 3 > 2 and 5 > 2 -> both bigger  -> go right to 4
At 4: 3 < 4 and 5 > 4 -> split!       -> 4 is the LCA
```

### Edge Cases to Consider

- **One value is an ancestor of the other**: e.g. `LCA(2, 4)` where `4` is in `2`'s own subtree — the walk reaches `2` and immediately finds `2 == p` (or `q`), returning `2` without needing to descend further.
- **`p == q`**: the tree has a single node, or the problem guarantees `p != q` otherwise — either way, the walk still terminates correctly at the node holding that value.
- **The LCA is the root itself**: whenever `p` and `q` fall on opposite sides of the very first comparison.
- **Negative values**: the BST comparisons (`<`, `>`) work identically regardless of sign — no special-casing needed.

## Key Takeaways

- A BST's ordering property turns "find the LCA" from a search problem into a single guided walk down the tree — no need to compute two full root-to-node paths.
- The walk terminates the moment `p` and `q` stop being on the same side of the current node — that node is always the answer.
- This runs in O(h) time with O(1) extra space (iteratively) — asymptotically better than the general-tree two-path approach, and simpler to implement.
- This technique only works because the tree is a *binary search tree* — for a general binary tree without the ordering guarantee, you'd need the brute-force two-path approach (or an equivalent recursive search).
