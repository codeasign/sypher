# Construct BST from Preorder Traversal

**Difficulty:** Medium

Given an array `preorder` of distinct integers, representing the **preorder traversal** of a **binary search tree**, construct that tree and return its root.

It's guaranteed that there is always a unique binary search tree whose preorder traversal is exactly `preorder`.

## Example 1

**Input:** `preorder = [8, 5, 1, 7, 10, 12]`

**Output tree:**
```
        8
      /   \
     5     10
    / \      \
   1   7      12
```

Verified by printing that tree's own preorder traversal, which is `[8, 5, 1, 7, 10, 12]` — exactly the input.

## Example 2

**Input:** `preorder = [1, 2, 3, 4, 5]`

**Explanation:** Since every value is larger than the one before it, each new node becomes the *right* child of the previous one — the tree degenerates into a right-leaning chain (1 -> 2 -> 3 -> 4 -> 5, each one level deeper than the last).

## Example 3

**Input:** `preorder = [5, 4, 3, 2, 1]`

**Explanation:** The mirror image of Example 2 — every value is smaller than the one before it, so each new node becomes the *left* child, producing a left-leaning chain.

## Input Specification

- One line: space-separated distinct integers, the preorder traversal (`1 <= preorder.length <= 100`).

## Output Specification

Print the **preorder traversal of the tree you constructed**, space-separated. If you built the correct BST, this will exactly match the input — that's what's being checked.

## Constraints

- `1 <= preorder.length <= 100`
- `-10^9 <= preorder[i] <= 10^9`
- All values in `preorder` are distinct.

## Hints

<details>
<summary>Hint 1</summary>

The first element of any preorder traversal is always the root of that (sub)tree. Every value that comes right after it, up until you hit a value *larger* than the root, belongs in the root's *left* subtree — everything after that belongs in the *right* subtree.
</details>

<details>
<summary>Hint 2</summary>

A clean way to build this in one linear pass: keep a stack of "ancestors we might still attach a right child to." For each new value, pop off the stack every node smaller than it (those are ancestors this value is now to the *right* of) — the **last node popped**, if any, gets this value as its right child. If nothing was popped, this value becomes the *left* child of whatever is still on top of the stack. Either way, push the new node onto the stack afterward.
</details>

<details>
<summary>Hint 3</summary>

A simpler (if slightly less efficient) recursive approach: pass down a valid upper bound for each subtree. Take the next value off the front of the array — if it's within the current bound, it's part of this subtree; recurse left with the current value as the new upper bound, then recurse right with the same bound as before.
</details>
