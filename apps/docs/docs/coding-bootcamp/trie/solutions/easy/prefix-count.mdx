# Prefix Count — Solution

## Problem Overview

Given a list of words and a prefix string, count how many words start with that prefix.

## Brute Force Approach

**Idea:** For each word, directly check whether it starts with `prefix` using the language's built-in string-prefix check.

**Complexity Analysis:**
- **Time:** O(n × p), where `n` is the number of words and `p` is the prefix length — each check compares up to `p` characters.
- **Space:** O(1) extra.

This is a perfectly good solution on its own for this problem's constraints. The trie-based approach below doesn't improve the asymptotic complexity for a *single* query — its real value is amortizing the cost across *many* prefix queries against the same word list (each query becomes O(prefix length) instead of O(n × p)), which is the more realistic scenario a trie is built for.

## Optimal Approach: Trie with a Per-Node Pass-Through Count

**Idea:** Build a trie from all the words, but track one extra piece of information at each node: how many words passed *through* that node during insertion (not just how many words *end* there). To answer a prefix query, walk down the trie following the prefix's characters — the count stored at the final node is exactly the number of words sharing that prefix. If the walk ever hits a missing child, no word has that prefix at all, so the answer is `0`.

**Algorithm:**
1. Build a trie. Each node has up to 26 children (lowercase letters) and a `count` field.
2. Insert each word: walk from the root, creating child nodes as needed for each character, and **increment `count` at every node visited along the way** (not just at the final node) — this node has now had one more word pass through it.
3. To query a prefix: walk from the root following each character of the prefix. If a required child doesn't exist, return `0` immediately. If the full prefix is successfully walked, return the `count` at the final node reached.

**Why This Works:** Every word that has `prefix` as a prefix must, by definition, pass through the exact same sequence of trie nodes that spelling out `prefix` character-by-character would visit. So the node at the end of that path has been "passed through" by insertion exactly once for every word sharing that prefix — which is precisely the count the query needs, with no need to scan the word list at query time.

**Complexity Analysis:**
- **Time:** O(total characters across all words) to build the trie; O(prefix length) per query.
- **Space:** O(total characters across all words) for the trie structure.

## Deep Dive

### Visual Walkthrough

Inserting `["apple", "app", "application"]`, tracking pass-through counts:

```
root
 └─ a (count=3)
     └─ p (count=3)
         └─ p (count=3)     <- "app" ends here, but count reflects ALL words passing through
             └─ l (count=2)
                 └─ e (count=2)   <- "apple" ends here
             └─ l (count=1, only "application" continues this way)
                 ... (rest of "application")
```

Querying prefix `"app"`: walk `a -> p -> p`, arriving at the node with `count = 3` — matching all three words (`apple`, `app`, `application`) that share this prefix.

### Edge Cases to Consider

- **The prefix exactly equals a full word** (e.g. `prefix = "app"` when `"app"` itself is in the word list): that word still contributes to the pass-through count at the "app" node just like any other word continuing past it — no special-casing needed, since insertion increments the count at every node visited regardless of whether a word terminates there.
- **No word has the given prefix**: the trie walk hits a missing child partway through (or immediately, if the prefix's first character was never inserted) — return `0` as soon as that happens, without needing to reach the end of the prefix.
- **Duplicate words** (e.g. `"apple apple apple"`): each insertion still increments every node along the path, so three identical insertions correctly contribute `3` to every prefix shared by `"apple"`.
- **The prefix equals an entire word with no continuations** (e.g. `prefix = "word"` matching only the single word `"word"`): the walk succeeds all the way to the end, landing on a count of `1`.

class TrieNode:
    def __init__(self):
        self.children = {}
        self.count = 0

def prefix_count(words: list, prefix: str) -> int:
    root = TrieNode()
    for word in words:
        node = root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
            node.count += 1          # one more word passed through this node

    node = root
    for ch in prefix:
        if ch not in node.children:
            return 0                 # no word has this prefix at all
        node = node.children[ch]
    return node.count

struct TrieNode {
    children: [Option<Box<TrieNode>>; 26],
    count: i32,
}

impl TrieNode {
    fn new() -> Self {
        TrieNode { children: Default::default(), count: 0 }
    }
}

fn prefix_count(words: &[&str], prefix: &str) -> i32 {
    let mut root = TrieNode::new();
    for word in words {
        let mut node = &mut root;
        for b in word.bytes() {
            let idx = (b - b'a') as usize;
            if node.children[idx].is_none() {
                node.children[idx] = Some(Box::new(TrieNode::new()));
            }
            node = node.children[idx].as_mut().unwrap();
            node.count += 1;          // one more word passed through this node
        }
    }

    let mut node = &root;
    for b in prefix.bytes() {
        let idx = (b - b'a') as usize;
        match &node.children[idx] {
            None => return 0,          // no word has this prefix at all
            Some(child) => node = child,
        }
    }
    node.count
}

## Key Takeaways

- Tracking a count at *every* node a word passes through during insertion (not just at terminal nodes) is what turns a trie into an efficient prefix-frequency structure — this is a different bit of bookkeeping than the "is this the end of a word" flag a typical trie uses for exact lookups.
- For a single prefix query against a word list, a plain linear scan with `startsWith` is equally valid and simpler — the trie's advantage only shows up when the same word list needs to answer many prefix queries.
- Returning `0` as soon as the prefix walk hits a missing child (rather than always walking the full prefix length) is a small but correct short-circuit — no word can share a prefix whose earlier characters were never inserted.
