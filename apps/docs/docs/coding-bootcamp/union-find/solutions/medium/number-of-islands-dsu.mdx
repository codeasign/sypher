# Number of Islands (DSU) — Solution

## Problem Overview

Given a grid of `0`s (water) and `1`s (land), count the number of distinct islands — groups of `1`s connected horizontally or vertically — using a Disjoint Set Union.

## Brute Force Approach

**Idea:** Flood-fill (BFS/DFS) from every unvisited land cell, marking its entire connected region as visited, and count how many flood-fills it takes to cover all the land.

**Complexity Analysis:**
- **Time:** O(rows × cols) — every cell is visited a constant number of times across all flood-fills.
- **Space:** O(rows × cols) for the visited grid and the BFS/DFS stack/queue.

This is asymptotically identical to the DSU approach for a single grid. DSU's advantage shows up when the grid arrives incrementally (land cells added one at a time, as in "Number of Islands II") — this problem is a good place to learn the DSU machinery before that harder variant needs it.

## Optimal Approach: DSU over a Flattened Grid

**Idea:** Treat every cell as a node in a Disjoint Set Union, flattening 2D coordinates `(r, c)` into a single index `r * cols + c`. Start by counting every land cell as its own island. Then, for each land cell, check its **up** and **left** neighbors only (checking just two of the four directions avoids ever double-processing the same adjacency) — if a neighbor is also land and belongs to a *different* component, merge the two components and decrement the island count by one.

**Algorithm:**
1. Initialize a `parent` array of size `rows * cols`, one entry per cell, each pointing to itself.
2. Initialize `count = 0`.
3. For every cell `(r, c)`: if it's land, increment `count` (it starts as its own island). Then check the **up** neighbor `(r-1, c)` and **left** neighbor `(r, c-1)` — for each that is also land, find both cells' roots; if the roots differ, union them and decrement `count`.
4. Return `count`.

**Why This Works:** Checking only up/left (rather than all four directions) is sufficient because by the time a cell is processed, every cell above or to its left has already been visited — so any merge involving a *later* neighbor (down/right) will be handled when that later cell is itself processed and looks back at *this* cell. This avoids redundant union calls without missing any adjacency. Each successful merge means two previously-separate islands turn out to be the same island, so decrementing the running count exactly tracks the number of distinct components as they're discovered.

**Complexity Analysis:**
- **Time:** O(rows × cols × α(rows × cols)) ≈ O(rows × cols) — every cell is processed once, with near-O(1) `find`/`union` calls.
- **Space:** O(rows × cols) for the `parent` array.

## Deep Dive

### Visual Walkthrough

For:
```
1 1 0
1 0 0
0 0 1
```

- `(0,0)`: land, `count = 1`. No up/left neighbor.
- `(0,1)`: land, `count = 2`. Left neighbor `(0,0)` is land, different root → union, `count = 1`.
- `(0,2)`: water, skip.
- `(1,0)`: land, `count = 2`. Up neighbor `(0,0)` is land, different root → union, `count = 1`.
- `(1,1)`: water, skip.
- `(1,2)`: water, skip.
- `(2,0)`, `(2,1)`: water, skip.
- `(2,2)`: land, `count = 2`. No land up or left neighbor.

Final `count = 2` — matching the two visually-distinct islands (the L-shaped block in the top-left, and the single cell in the bottom-right).

### Edge Cases to Consider

- **An all-water grid**: `count` never increments past `0`, since no cell is ever treated as land — correctly returns `0`.
- **An all-land grid**: every interior cell successfully unions with both its up and left neighbor, collapsing the count down to exactly `1`.
- **A checkerboard pattern** (land cells with no two adjacent): every land cell increments `count`, but no union ever succeeds (up/left neighbors are always water), so the final count equals the number of land cells — each is its own island.
- **A single row or single column**: only one of "up" or "left" is ever in-bounds, but the algorithm doesn't need to special-case this — the neighbor check's bounds test naturally skips whichever direction doesn't exist.
- **A ring-shaped island** (land forming a loop around a water center): the up/left-only merge strategy still correctly unifies the entire ring into one component, since the ring is fully connected through cells that do have an in-bounds up or left land neighbor somewhere along the loop.

def number_of_islands(grid: list) -> int:
    rows = len(grid)
    cols = len(grid[0]) if rows else 0
    parent = list(range(rows * cols))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] != 1:
                continue
            count += 1
            idx = r * cols + c
            if r > 0 and grid[r - 1][c] == 1:
                ra, rb = find(idx), find(idx - cols)
                if ra != rb:
                    parent[ra] = rb
                    count -= 1
            if c > 0 and grid[r][c - 1] == 1:
                ra, rb = find(idx), find(idx - 1)
                if ra != rb:
                    parent[ra] = rb
                    count -= 1

    return count

## Key Takeaways

- Flattening a 2D grid into a 1D DSU (`index = r * cols + c`) is the standard technique for applying Union-Find to grid-connectivity problems.
- Checking only the up and left neighbors (not all four directions) avoids redundant union calls without missing any adjacency — every merge gets discovered exactly once, from whichever cell is processed second in reading order.
- Tracking the island count as "start at number of land cells, decrement on every successful merge" avoids a separate final pass to count distinct roots — the count is exact the moment the grid scan finishes.
