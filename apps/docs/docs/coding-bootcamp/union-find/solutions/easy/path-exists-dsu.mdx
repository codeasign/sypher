# Find if Path Exists (DSU) — Solution

## Problem Overview

Given an undirected graph and two nodes `source` and `destination`, determine whether any path connects them.

## Brute Force Approach

**Idea:** Build an adjacency list and run a BFS or DFS starting from `source`, checking whether `destination` is ever reached.

**Complexity Analysis:**
- **Time:** O(n + m) — a standard graph traversal, visiting every node and edge once.
- **Space:** O(n + m) for the adjacency list and visited-set/queue.

This is a perfectly valid solution on its own. The DSU approach below is the same asymptotic complexity for a single query, but it generalizes far better: once built, a DSU answers "are these two nodes connected?" for *any* pair in near O(1), without re-traversing the graph — which is the real reason this pattern gets its own module.

## Optimal Approach: Disjoint Set Union (Union-Find)

**Idea:** Maintain a `parent` array where each node starts as its own component. Process every edge with a `union` operation, merging the two endpoints' components together. Afterward, `source` and `destination` have a path between them if and only if they end up in the same component — checked by comparing `find(source)` and `find(destination)`.

**Algorithm:**
1. Initialize `parent[i] = i` for every node (each node is its own component).
2. For every edge `(u, v)`, call `union(u, v)`: find each endpoint's root and merge one root under the other.
3. `find(x)` walks up the parent chain until it reaches a node that is its own parent (the root), applying **path compression** along the way — every visited node gets re-pointed directly at the root, flattening the tree for future lookups.
4. After processing all edges, return `find(source) == find(destination)`.

**Why This Works:** Union-Find directly maintains the graph's connected components as a forest of trees, one tree per component. Two nodes are reachable from each other exactly when they belong to the same tree — which `find` detects by comparing roots. Path compression keeps every tree nearly flat, so `find` and `union` both run in near-constant amortized time (technically O(α(n)), the inverse Ackermann function, which is effectively a small constant for any input size that could ever occur in practice).

**Complexity Analysis:**
- **Time:** O((n + m) · α(n)) ≈ O(n + m) — processing every edge with near-O(1) `find`/`union` calls, plus O(1) for the final check.
- **Space:** O(n) for the `parent` array.

## Deep Dive

### Visual Walkthrough

For `n = 6`, edges `[[0,1],[0,2],[3,5],[5,4],[4,3]]`, checking `source = 0`, `destination = 5`:

```
Union(0,1): parent[0] -> 1        (component: {0,1})
Union(0,2): find(0)=1, parent[1] -> 2   (component: {0,1,2})
Union(3,5): parent[3] -> 5        (component: {3,5})
Union(5,4): parent[5] -> 4        (component: {3,4,5})
Union(4,3): find(4)=4, find(3)=4  (already same root -- no-op)

find(0) walks 0 -> 1 -> 2, root = 2
find(5) walks 5 -> 4, root = 4

2 != 4  ->  false (0 and 5 are in different components)
```

### Edge Cases to Consider

- **`source == destination`**: trivially `true` — a node always has a (zero-length) path to itself, and `find(source) == find(destination)` holds automatically since they're literally the same node.
- **`n == 1` with zero edges**: the single node is its own component; `source` and `destination` must both be `0`, so the check still resolves correctly.
- **Zero edges with `source != destination`**: every node is its own isolated component, so `find` returns different roots and the answer is correctly `false`.
- **A self-loop edge** (`u == v`) or **duplicate edge**: `union(u, u)` is a harmless no-op (both `find` calls return the same root already), and re-unioning an already-merged pair is equally harmless — DSU is naturally idempotent, so malformed-looking input doesn't require special-casing.
- **A long chain of edges** (`0-1-2-3-...-n-1`): without path compression, `find` on the far end degrades to O(n) per call; path compression is what keeps repeated queries fast even on a long, skinny component.

def path_exists_dsu(n, edges, source, destination):
    parent = list(range(n))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]  # path compression
            x = parent[x]
        return x

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra != rb:
            parent[ra] = rb

    for a, b in edges:
        union(a, b)

    return find(source) == find(destination)

            x = parent[x];

        }

## Key Takeaways

- Union-Find turns "are these two nodes connected?" into an amortized near-O(1) lookup after an O(n + m) build — a BFS/DFS answers one query at that same cost, but a query against an already-built DSU is far cheaper than re-traversing the graph.
- Path compression (`parent[x] = parent[parent[x]]` while walking to the root) is what keeps `find` fast — without it, a long chain of unions degrades to O(n) per lookup.
- Self-loops and duplicate edges are harmless no-ops under `union` — DSU doesn't need input validation for either, since re-merging an already-merged (or identical) pair simply does nothing.
