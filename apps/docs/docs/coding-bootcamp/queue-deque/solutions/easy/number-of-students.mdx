# Number of Students Unable to Eat Lunch — Solution

## Problem Overview

Students in a queue each prefer a circular (`0`) or square (`1`) sandwich. If the student at the front doesn't want the top sandwich, they go to the back of the queue; otherwise they take it and leave. Find how many students are stuck once nobody in the queue wants the remaining top sandwich.

## Brute Force Approach

**Idea:** Directly simulate the described process with an actual queue and stack. Repeatedly check the student at the front: if they want the top sandwich, both are removed; otherwise, the student is moved to the back. Track how many consecutive students have been rotated through without a match — if that count ever reaches the current queue's length, nobody left wants the current sandwich, and the simulation stops.

**Complexity Analysis:**
- **Time:** O(n²) worst case — a queue can be fully rotated through (up to `n` times) between each successful match.
- **Space:** O(n) for the queue.

## Optimal Approach: Count-and-Consume

**Idea:** The queue-rotation mechanic is really just a roundabout way of saying "as long as *any* student in the queue wants the current top sandwich, someone will eventually get to the front and take it — the exact order students rotate in doesn't matter, only how many of each preference remain." So skip simulating the rotation entirely: count how many students prefer `0` and how many prefer `1`, then walk through the sandwich stack directly. For each sandwich, if there's still a student who wants that type, one such student "eats" (decrement that count); the moment a sandwich type has zero remaining takers, every student still left is permanently stuck (no rotation could ever produce a different outcome, since the only students left all want the *other* type, and the sandwich stack order is fixed).

**Algorithm:**
1. Count `zeros` = number of students preferring `0`, `ones` = number of students preferring `1`.
2. For each sandwich in the stack, from top to bottom:
   - If it's `0`: if `zeros == 0`, stop (nobody left wants it) — otherwise decrement `zeros`.
   - If it's `1`: if `ones == 0`, stop — otherwise decrement `ones`.
3. Return `zeros + ones` — however many students of either preference are still left unmatched.

**Why This Works:** The queue-rotation process can only ever get "stuck" at a sandwich when *no* remaining student wants that specific type — and since rotating only reorders students without changing which preferences are still present, the final stuck point depends only on the *counts* of each preference, not their order in the queue. This turns an O(n²) simulation into a single O(n) pass with two counters.

**Complexity Analysis:**
- **Time:** O(n) — one pass to count preferences, one pass over the sandwich stack.
- **Space:** O(1) — two counters, no queue or stack data structure needed.

## Deep Dive

### Visual Walkthrough

For `students = [1,1,1,0,0,1]`, `sandwiches = [1,0,0,0,1,1]`:

```
zeros = 2 (two students prefer 0), ones = 4 (four students prefer 1)

sandwich 1: ones > 0 -> consume -> ones = 3
sandwich 0: zeros > 0 -> consume -> zeros = 1
sandwich 0: zeros > 0 -> consume -> zeros = 0
sandwich 0: zeros == 0 -> STOP (nobody left wants a circular sandwich)

remaining: zeros(0) + ones(3) = 3
```

### Edge Cases to Consider

- **Everyone gets fed** (e.g. `students=[1,1,0,0]`, `sandwiches=[0,1,0,1]`): both counters reach `0` exactly as the sandwich stack is exhausted — answer `0`.
- **Nobody's preference matches the very first sandwich** (e.g. `students=[0]`, `sandwiches=[1]`): the corresponding counter is already `0` on the very first check — the single student is immediately stuck.
- **All students share one preference, all sandwiches are the other** (e.g. `students=[0,0,0]`, `sandwiches=[1,1,1]`): the very first sandwich check finds zero takers for `1` (since every student prefers `0`) — all students are stuck immediately, even though the queue "looks" non-empty.
- **More sandwiches remaining than students** doesn't occur here since the problem guarantees equal lengths, but the algorithm would still be correct if the sandwich stack ran out first — the loop simply ends and whatever counts remain (which would be `0`) are returned.

def number_of_students(students: list, sandwiches: list) -> int:
    zeros = students.count(0)
    ones = students.count(1)

            zeros -= 1
        else:
            if ones == 0:

class Solution {

        }

                if (zeros == 0) break;

## Key Takeaways

- When a simulation's outcome only depends on *counts* of a small number of categories, not the specific order elements appear in, that's a strong signal the simulation can be replaced with simple counters — turning O(n²) into O(n).
- The queue-rotation mechanic in the original problem statement is a red herring for the optimal solution: it describes *how* students get fed, but the *number* left unfed depends only on when a sandwich type first runs out of takers.
- Recognizing "this repeated rotation always eventually succeeds if a match exists anywhere in the remaining group" is the key insight that justifies skipping the rotation simulation entirely.
