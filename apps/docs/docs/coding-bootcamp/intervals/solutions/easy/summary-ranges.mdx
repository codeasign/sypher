# Summary Ranges — Solution

## Problem Overview

Given a sorted array of unique integers, group consecutive runs into ranges, formatted as `"a->b"` (or just `"a"` for a single-element run).

## Brute Force Approach

There isn't a meaningfully different "brute force" here — the array is already sorted, so a single linear scan detecting where consecutive runs break **is** the direct, optimal approach.

## Optimal Approach: Single Pass, Track the Current Run's Start

**Idea:** Walk through the array once, remembering where the *current* consecutive run started. Whenever the next value isn't exactly one more than the current value (or the array ends), the current run is finished — emit it, and start tracking a new run from the next value.

**Algorithm:**
1. If the array is empty, return an empty list immediately.
2. Set `start = nums[0]`.
3. For each index `i` from `1` to `n` (inclusive of one past the last valid index, to flush the final run):
   - If `i == n` (end of array) or `nums[i] != nums[i-1] + 1` (the run just broke), the run from `start` to `nums[i-1]` just ended — format and emit it, then (if `i < n`) set `start = nums[i]` to begin the next run.
4. Return the collected range strings.

**Why This Works:** Because the array is sorted and every value is unique, "consecutive" is equivalent to "each value is exactly one more than the previous" — there's no need to check anything beyond adjacent pairs. Iterating one index past the end of the array (checking `i == n`) is a clean way to force the *final* run to be emitted using the same code path as every other run, rather than needing a separate "flush what's left" step after the loop.

**Complexity Analysis:**
- **Time:** O(n) — a single pass.
- **Space:** O(1) extra, beyond the output list itself.

## Deep Dive

### Visual Walkthrough

For `nums = [0, 1, 2, 4, 5, 7]`:

```
start = 0

i=1: nums[1]=1 == nums[0]+1=1 -> still in the run, continue
i=2: nums[2]=2 == nums[1]+1=2 -> still in the run, continue
i=3: nums[3]=4 != nums[2]+1=3 -> run broke! emit "0->2" (start=0, end=nums[2]=2)
     new start = nums[3] = 4
i=4: nums[4]=5 == nums[3]+1=5 -> still in the run, continue
i=5: nums[5]=7 != nums[4]+1=6 -> run broke! emit "4->5" (start=4, end=nums[4]=5)
     new start = nums[5] = 7
i=6 (== n): end of array -> emit "7" (start=7, end=nums[5]=7, and start==end so no arrow)

result: ["0->2", "4->5", "7"]  -> joined: "0->2,4->5,7"
```

### Edge Cases to Consider

- **Empty array**: return an empty list directly — there's no `nums[0]` to even start a run from, so this must be checked before anything else runs.
- **Single element**: the loop runs exactly once with `i == n`, immediately emitting that one value as its own range (`start == end`, so no arrow).
- **Every element consecutive** (e.g. `[0..9]`): the run never breaks until `i == n`, producing exactly one range spanning the whole array.
- **No two elements consecutive** (e.g. `[1, 3, 5, 7]`): every step breaks the run immediately, producing one single-element range per input value.
- **Negative numbers and numbers spanning zero**: the "exactly one more than the previous" check works identically regardless of sign — no special-casing needed around zero.

def summary_ranges(nums: list[int]) -> list[str]:
    if not nums:
        return []
    result = []
    start = nums[0]
    n = len(nums)
    for i in range(1, n + 1):
        if i == n or nums[i] != nums[i - 1] + 1:
            end = nums[i - 1]
            result.append(str(start) if start == end else f"{start}->{end}")
            if i < n:
                start = nums[i]
    return result

## Key Takeaways

- Looping one index *past* the end of the array (`i` up to and including `n`) is a clean trick for flushing a "current run in progress" without duplicating the emit logic in a separate post-loop step.
- Since the input is guaranteed sorted and unique, "consecutive" reduces to a single cheap check (`nums[i] == nums[i-1] + 1`) — no need for anything more elaborate.
- The `start == end` check for whether to use the arrow format is a small but easy detail to miss — a single-element run must print as just `"start"`, not `"start->start"`.
