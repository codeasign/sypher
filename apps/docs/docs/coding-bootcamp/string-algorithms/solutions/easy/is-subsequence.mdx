# Is Subsequence — Solution

## Problem Overview

Given two strings `s` and `t`, determine whether `s` can be formed by deleting zero or more characters from `t` without reordering what's left.

## Brute Force Approach

Generate every possible subsequence of `t` and check whether any of them equals `s`. This is exponential and wildly impractical — with `t` up to `10^4` characters, there are up to `2^10000` subsequences. There's no reason to go this route; the direct two-pointer approach below is both simpler to write and vastly faster.

**Complexity Analysis:**
- **Time:** O(2^m) — not viable.
- **Space:** O(2^m).

## Optimal Approach: Two Pointers

**Idea:** Walk through `t` once, left to right, and greedily try to match characters of `s` in order. Keep a pointer into `s` that only advances when the current character of `t` matches the character `s` is currently looking for.

**Algorithm:**
1. `i = 0` (pointer into `s`).
2. For each character `c` in `t`:
   - If `i < len(s)` and `s[i] == c`, increment `i`.
3. After scanning all of `t`, `s` is a subsequence of `t` if and only if `i == len(s)` (every character of `s` was found, in order).

**Why This Works:** Greedily matching the *earliest* possible occurrence of each character in `s` is always at least as good as matching a later one — using an earlier match in `t` never removes an opportunity that a later match would have kept, but it can only ever open up more room for the remaining characters of `s` to be found afterward. So there's no need for backtracking or trying alternate matches: the greedy left-to-right scan is guaranteed to find a valid subsequence match if one exists.

**Complexity Analysis:**
- **Time:** O(n), where `n = len(t)` — one pass over `t`, regardless of `s`'s length.
- **Space:** O(1) — just the one index variable.

## Deep Dive

### Visual Walkthrough

For `s = "abc"`, `t = "ahbgdc"`:

```
t:  a  h  b  g  d  c
    ^
s[0]='a' -- matches 'a' -- advance i to 1

t:  a  h  b  g  d  c
       ^
s[1]='b' -- 'h' doesn't match, keep looking

t:  a  h  b  g  d  c
          ^
s[1]='b' -- matches 'b' -- advance i to 2

t:  a  h  b  g  d  c
             ^  ^
s[2]='c' -- 'g', 'd' don't match, keep looking

t:  a  h  b  g  d  c
                   ^
s[2]='c' -- matches 'c' -- advance i to 3

i == len(s) (3 == 3) -- true
```

### Edge Cases to Consider

- **`s` is empty**: the loop body never advances `i` past `0`, but `i` already equals `len(s) == 0` before the loop even starts — the empty string is correctly a subsequence of anything, with no special-case code needed.
- **`t` is empty (and `s` isn't)**: the loop never executes at all, `i` stays `0`, and `0 == len(s)` is false unless `s` was also empty — correctly returns `false`.
- **`s` longer than `t`**: impossible for `i` to ever reach `len(s)`, since `t` runs out of characters first — no special-casing needed, the general loop handles it correctly, though it can be a useful early-exit optimization to check `len(s) > len(t)` upfront.
- **Repeated characters** (e.g. `s = "zz"` against a `t` containing only one `'z'`): the second `'z'` in `s` simply never finds a second match, so `i` stops advancing partway through — correctly returns `false`.

## Key Takeaways

- The greedy "match the earliest possible occurrence" strategy is provably optimal here — there's never a benefit to deliberately skipping an available match in favor of a later one, so no backtracking is needed.
- This is an O(n) single-pass algorithm regardless of `s`'s length — the work is driven entirely by scanning `t` once.
- The empty-string case falls out of the general loop condition for free (`i` starts already equal to `len(s) == 0`) — a sign the algorithm is well-formed, not a coincidence to special-case around.
