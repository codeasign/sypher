# Spiral Matrix II — Solution

## Problem Overview

Given `n`, build an `n x n` matrix filled with `1` through `n²` in spiral order (right along the top, down the right side, left along the bottom, up the left side, then shrink inward and repeat).

## Brute Force Approach

There isn't a meaningfully different "brute force" here — filling in spiral order **is** the direct simulation; there's no redundant work to eliminate. The two standard implementation styles (shrinking boundaries vs. a direction vector that rotates on collision) are both O(n²) and are really just different bookkeeping for the same walk.

## Optimal Approach: Shrinking Boundaries

**Idea:** Track four boundaries — `top`, `bottom`, `left`, `right` — marking the still-unfilled region of the matrix. Fill one full side at a time (top row left-to-right, right column top-to-bottom, bottom row right-to-left, left column bottom-to-top), then shrink the boundary that side just completed inward. Repeat until the boundaries cross.

**Algorithm:**
1. Initialize `top = 0`, `bottom = n-1`, `left = 0`, `right = n-1`, and `num = 1`.
2. While `top <= bottom` and `left <= right`:
   - Fill row `top` from `left` to `right`, incrementing `num` each time; then `top += 1`.
   - Fill column `right` from the new `top` to `bottom`; then `right -= 1`.
   - **If `top <= bottom` still holds** (there's still at least one row left), fill row `bottom` from `right` down to `left`; then `bottom -= 1`.
   - **If `left <= right` still holds** (there's still at least one column left), fill column `left` from `bottom` up to the new `top`; then `left += 1`.
3. Return the filled matrix.

**Why This Works:** After the top row and right column are filled, the remaining unfilled region is always still a valid rectangle bounded by the *updated* `top`/`bottom`/`left`/`right` — so the same four-sides-in-order logic applies recursively to a shrinking sub-rectangle. The two guard checks (before filling the bottom row and before filling the left column) exist because odd dimensions eventually shrink to a single row or single column, at which point the "bottom row" or "left column" fill would either repeat cells already filled by the top-row/right-column pass or write nothing at all — skipping them when the boundaries have already crossed avoids exactly that.

**Complexity Analysis:**
- **Time:** O(n²) — every cell is filled exactly once.
- **Space:** O(n²) for the output matrix (unavoidable, since that's the required return value); O(1) extra beyond it.

## Deep Dive

### Visual Walkthrough

For `n = 3`:

```
top=0,bottom=2,left=0,right=2, num=1

Fill top row (r=0, c=0..2):      1  2  3

                                  .  .  .
top becomes 1.

Fill right col (c=2, r=1..2):    1  2  3
                                  .  .  4
                                  .  .  5
right becomes 1.

top(1) <= bottom(2): fill bottom row (r=2, c=1..0):
                                  1  2  3
                                  .  .  4
                                  7  6  5
bottom becomes 1.

left(0) <= right(1): fill left col (c=0, r=1..1):
                                  1  2  3
                                  8  .  4
                                  7  6  5
left becomes 1.

top(1) <= bottom(1) and left(1) <= right(1): one more pass, fills the center:
                                  1  2  3
                                  8  9  4
                                  7  6  5
top becomes 2, now top > bottom -- loop ends.
```

### Edge Cases to Consider

- **`n = 1`**: `top == bottom == left == right == 0`. The top-row fill places `1` at `(0,0)` and immediately advances `top` past `bottom`; the right-column fill's range is now empty (`top=1 > bottom=0`), and both guard checks (`top <= bottom`, `left <= right`) are already false, so nothing else runs. Result: the single-cell matrix `[[1]]`.
- **Even `n`** (e.g. `n=4`): the spiral shrinks all the way down to a 2x2 remainder, filled by one final top-row-then-right-column pass with no center cell left over.
- **Odd `n`** (e.g. `n=3`, `n=5`): the spiral shrinks down to a single center cell, filled by the top-row pass of the final iteration (a "row" of length 1) — the guard checks correctly skip the redundant bottom-row/left-column fills at that point.
- **The two guard checks are the detail most likely to be gotten wrong**: omitting them causes either a crash (writing to already-out-of-range indices) or double-writes/incorrect ordering on the final ring of a rectangle that's shrunk to a single row or column.

def generateMatrix(n: int) -> list[list[int]]:
    matrix = [[0] * n for _ in range(n)]
    top, bottom, left, right = 0, n - 1, 0, n - 1
    num = 1
    while top <= bottom and left <= right:
        for c in range(left, right + 1):
            matrix[top][c] = num
            num += 1
        top += 1
        for r in range(top, bottom + 1):
            matrix[r][right] = num
            num += 1
        right -= 1
        if top <= bottom:
            for c in range(right, left - 1, -1):
                matrix[bottom][c] = num
                num += 1
            bottom -= 1
        if left <= right:
            for r in range(bottom, top - 1, -1):
                matrix[r][left] = num
                num += 1
            left += 1
    return matrix

class Solution {
    public int[][] generateMatrix(int n) {
        int[][] matrix = new int[n][n];
        int top = 0, bottom = n - 1, left = 0, right = n - 1;
        int num = 1;
        while (top <= bottom && left <= right) {
            for (int c = left; c <= right; c++) matrix[top][c] = num++;
            top++;
            for (int r = top; r <= bottom; r++) matrix[r][right] = num++;
            right--;
            if (top <= bottom) {
                for (int c = right; c >= left; c--) matrix[bottom][c] = num++;
                bottom--;
            }
            if (left <= right) {
                for (int r = bottom; r >= top; r--) matrix[r][left] = num++;
                left++;
            }
        }
        return matrix;
    }
}

## Key Takeaways

- Four shrinking boundary variables (`top`, `bottom`, `left`, `right`) are enough to track "what's left to fill" without needing to check whether individual cells are already visited.
- The two guard checks (`if top <= bottom`, `if left <= right`) before the bottom-row and left-column fills are what correctly handle the final ring of a shrinking rectangle — both odd and even `n` reduce to this same edge case, just via a single row vs. a single column.
- This is the mirror image of "traverse an existing matrix in spiral order" — instead of reading cells in spiral order, this problem writes increasing numbers into them in that same order, using the identical boundary-shrinking walk.
