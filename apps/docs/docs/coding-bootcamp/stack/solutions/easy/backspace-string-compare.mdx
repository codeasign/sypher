# Backspace String Compare — Solution

## Problem Overview

Given two strings containing lowercase letters and `#` (backspace) characters, determine whether typing each one into a text editor produces the same final text.

## Brute Force Approach

**Idea:** Simulate typing each string into a stack — push regular characters, and pop (if the stack isn't empty) on `#`. Once both strings are fully processed, compare the two resulting stacks (or the strings built from them) for equality.

**Complexity Analysis:**
- **Time:** O(m + n) — one pass to build each stack.
- **Space:** O(m + n) — both stacks (or their string forms) are stored in full before comparing.

## Optimal Approach: Two Pointers from the End, O(1) Space

**Idea:** You don't actually need to materialize either processed string. Walk both strings **backwards**, from the last character toward the first, keeping a running count of pending backspaces for each. A `#` increments the pending count; a regular character is either skipped (if a backspace is still pending, consuming one) or is the next character to compare. Advance both pointers in lockstep, comparing one "surviving" character at a time.

**Algorithm:**
1. Point `i` at the last index of `s`, `j` at the last index of `t`.
2. Define a helper: from a given starting index, walk backwards skipping `#` characters (incrementing a backspace counter) and any character consumed by a pending backspace, stopping at the next character that actually survives (or falling off the front of the string).
3. Repeatedly find the next surviving character in `s` (moving `i` backward) and the next surviving character in `t` (moving `j` backward):
   - If one has run out of characters and the other hasn't, they're unequal — return `false`.
   - If both have run out, they're equal — return `true`.
   - Otherwise, compare the two surviving characters — if they differ, return `false`; if they match, continue.

**Why This Works:** Processing backspaces from the *end* of the string is equivalent to processing them from the start with a stack, just without needing to store anything — a backspace at the end always cancels out the character immediately before it, and walking backward naturally applies cancellations in the right order without needing to look ahead.

**Complexity Analysis:**
- **Time:** O(m + n) — each pointer visits each character at most once.
- **Space:** O(1) — only a few index/counter variables, no stack or rebuilt string.

## Deep Dive

### Visual Walkthrough

For `s = "ab#c"`:

```
index:  0 1 2 3
chars:  a b # c

Start at index 3 ('c'): not '#', no pending backspace -- 'c' survives.
Next, start at index 2 ('#'): backspace pending += 1, move to index 1.
  index 1 ('b'): pending backspace > 0 -- consume it, skip 'b', move to index 0.
  index 0 ('a'): no pending backspace -- 'a' survives.

Surviving characters (in reverse-scan order): 'c', then 'a'
Reconstructed forward: "ac"
```

Comparing against `t = "ad#c"` processed the same way also yields `"ac"` — equal, so the answer is `true`, matching the direct stack simulation without ever building either string.

### Edge Cases to Consider

- **Backspacing past the start of the string** (e.g. `"a##c"`): once the pointer would go past index `0`, there's simply nothing left to skip — the walk-backward helper just stops, it doesn't need to guard against a negative index specially beyond the loop's own bound check.
- **One string entirely backspaced to empty** (e.g. `"a#b#c#"` vs. `""`): both "surviving character" searches run out at the same time — equal, `true`.
- **Same processed result reached via a different number of characters/backspaces** (e.g. `"xywrrmp"` vs. `"xywrrmu#p"`): the two pointers don't need to move in lockstep through the *original* strings, only through the *surviving* characters — this is exactly why simulating from the end works even when the raw lengths and backspace counts differ.
- **Multiple consecutive backspaces** (e.g. `"hello##"`): the pending-backspace counter accumulates across consecutive `#` characters before any letters get consumed, correctly deleting more than one character.

def backspace_string_compare(s: str, t: str) -> bool:
    def next_valid_index(string: str, index: int) -> int:
        skip = 0
        while index >= 0:
            if string[index] == '#':
                skip += 1
                index -= 1
            elif skip > 0:
                skip -= 1
                index -= 1
            else:
                break
        return index

    i, j = len(s) - 1, len(t) - 1
    while i >= 0 or j >= 0:
        i = next_valid_index(s, i)
        j = next_valid_index(t, j)
        if i >= 0 and j >= 0:
            if s[i] != t[j]:
                return False
        elif i >= 0 or j >= 0:
            return False           # one ran out, the other didn't
        i -= 1
        j -= 1
    return True

## Key Takeaways

- Processing backspaces from the *end* of a string toward the front is equivalent to a stack simulation from the front, but needs no extra storage — a trailing `#` always cancels the character immediately preceding it.
- The two pointers don't need to move through the same number of raw characters in `s` and `t` — only through the same number of *surviving* characters, which is exactly what makes strings of different lengths and different backspace counts still comparable.
- The stack-based brute force is a perfectly reasonable answer on its own (and easier to write correctly under pressure) — the O(1)-space version is worth knowing as a follow-up optimization, not a requirement for a first working solution.
