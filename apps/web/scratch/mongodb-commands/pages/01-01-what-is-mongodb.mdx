MongoDB is a free, open-source **document database**. Instead of tables with rows and columns, it stores **documents**: flexible, JSON-like records that can hold nested objects and lists. You ask questions about them with a query language of your own, and you can change the shape of your data whenever your application changes.

## What you'll learn

- What a document, a collection and a database are
- How MongoDB differs from a relational (SQL) database
- What the DVD Rental database looks like as documents
- Where MongoDB fits, and where it does not

## The idea in plain English

A relational database keeps each kind of thing in its own table and links tables with keys. MongoDB keeps a whole thing, with its related details, in **one document**.

- A **document** is one record: a set of `field: value` pairs. Values can be text, numbers, true/false, dates, lists (arrays) and even other documents (embedded documents).
- A **collection** is a group of documents, roughly what a table is in SQL. Documents in one collection need not all have the same fields.
- A **database** is a set of collections.
- Every document has an `_id` that is unique in its collection. It is the primary key, and MongoDB creates an index on it for you.

## The DVD Rental database as documents

This course uses one sample database, **DVD Rental**, the records of a DVD-rental company. In SQL it is 15 linked tables. Here it is only **3 collections**, because related data is embedded:

| Collection | One document is | What is embedded in it |
|---|---|---|
| `films` | A film | its actors (a list), its category, its language |
| `customers` | A customer | their address, and every rental they made, each with its payments |
| `stores` | A store | its address, its staff, and its inventory (which copies it holds) |

## Seeing it for real

Here is one whole film document. Notice the nested `category` and `language` objects, and the `specialFeatures` list:

```js
db.films.findOne({ _id: 1 }, { actors: 0 })
```

  lastUpdated: '2006-02-15 05:03:42',

  rating: 'PG',
  releaseYear: 2006,

And the same film's cast is a list of small documents:

```js
db.films.findOne({ _id: 1 }, { title: 1, actors: 1 }).actors.slice(0, 3)
```

```text

```

There are 1000 films, 599 customers and 2 stores.

## MongoDB versus SQL

| SQL | MongoDB |
|---|---|
| Database | Database |
| Table | Collection |
| Row | Document |
| Column | Field |
| Join | Embedding, or `$lookup` |
| `SELECT ... WHERE ...` | `find({ ... })` |
| `GROUP BY` | aggregation pipeline `$group` |
| Schema is fixed by `CREATE TABLE` | Schema is flexible (and can be enforced with validation) |

## Watch out

- **Flexible does not mean "no design".** A collection full of inconsistent documents is hard to query. You still choose a shape, and you can enforce it with validation (module 13).
- **There are no joins in the SQL sense.** Related data is either embedded in one document or looked up with `$lookup`. Deciding which is the heart of MongoDB data modelling.
- **MongoDB, BSON and JSON are different things.** MongoDB is the database, BSON is the binary format it stores (JSON plus extra types such as dates and `ObjectId`), and JSON is the text form you usually see.

## Interview corner

**"What is MongoDB, and how does it differ from a relational database?"**
It is a document database: data is stored as flexible JSON-like documents in collections, related data can be embedded in one document, and the schema is not fixed up front. Relational databases use fixed tables and joins.

**"What is a document, and what is a collection?"**
A document is one BSON record of field/value pairs, possibly with nested documents and arrays. A collection is a group of documents, comparable to a table.

**"What is `_id`?"**
The primary key of a document. It must be unique in the collection, is indexed automatically, and defaults to an `ObjectId` if you do not supply one.
