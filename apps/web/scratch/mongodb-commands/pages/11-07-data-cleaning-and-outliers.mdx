Real collections are messy: mixed types, stray spaces, wrong cases, impossible values. Interviewers like to ask how you would find and fix them. This page uses a scratch collection with deliberate problems, so each fix can be verified.

## What you'll learn

- Finding fields with mixed types
- Trimming, case-normalising and converting values
- Finding outliers with the standard deviation and with quartiles
- Fixing everything with update pipelines

## Syntax

```js
db.c.aggregate([ { $group: { _id: { $type: "$field" }, n: { $sum: 1 } } } ])
db.c.updateMany({}, [ { $set: { field: { $trim: { input: "$field" } } } } ])
```

## Examples

```js
const lab = db.getSiblingDB("lab_clean")

  { _id: 6, name: "Flo", age: 29, email: "flo@x.com", score: 500 }

lab.people.countDocuments()
```

### Problem 1: which types does a field hold?

```js
lab.people.aggregate([
  { $group: { _id: { $type: "$age" }, n: { $sum: 1 }, ids: { $push: "$_id" } } },
  { $sort: { _id: 1 } }
])
```

```text
[
  { _id: 'int', n: 3, ids: [ 1, 3, 6 ] },
  { _id: 'missing', n: 1, ids: [ 5 ] },
  { _id: 'null', n: 1, ids: [ 4 ] },
  { _id: 'string', n: 1, ids: [ 2 ] }
]
```

`missing` is the type of the document without an `age` field. Mixed `int`, `string`, `null` and `missing` in one field is the usual result of several writers.

### Problem 2: find the bad rows

```js
lab.people.find({ age: { $not: { $type: "number" } } }, { name: 1 }).sort({ _id: 1 }).toArray().map((d) => d._id)
```

```text
[ 2, 4, 5 ]
```

### Problem 3: normalise strings

Trim spaces and lower-case the email; title-case is not built in, so approximate with `$toUpper` of the first letter plus `$toLower` of the rest:

```js
lab.people.aggregate([
  { $project: {
      email: { $toLower: { $trim: { input: "$email" } } },
      name: { $let: {
        vars: { n: { $trim: { input: "$name" } } },
        in: { $concat: [{ $toUpper: { $substrCP: ["$$n", 0, 1] } }, { $toLower: { $substrCP: ["$$n", 1, { $strLenCP: "$$n" }] } }] }
      } } } },
  { $sort: { _id: 1 } }
])
```

```text
[
  { _id: 1, email: 'ann@x.com', name: 'Ann' },
  { _id: 2, email: 'bob@x.com', name: 'Bob' },
  { _id: 3, email: 'cy@x.com', name: 'Cy' },
  { _id: 4, email: 'di@x.com', name: 'Di' },
  { _id: 5, email: 'ed@x.com', name: 'Ed' },
  { _id: 6, email: 'flo@x.com', name: 'Flo' }
]
```

### Problem 4: convert types safely

`$convert` with `onError` and `onNull` avoids failures on bad values:

```js
lab.people.aggregate([
  { $project: { age: { $convert: { input: "$age", to: "int", onError: -1, onNull: -1 } } } },
  { $sort: { _id: 1 } }
])
```

```text
[
  { _id: 1, age: 31 },
  { _id: 2, age: 27 },
  { _id: 3, age: 45 },
  { _id: 4, age: -1 },
  { _id: 5, age: -1 },
  { _id: 6, age: 29 }
]
```

`missing` fields convert to `null`, which `onNull` handles.

### Problem 5: fix it all in place

One update pipeline applies all the fixes. Test on a copy or with a filter first:

```js
lab.people.updateMany({}, [{ $set: {
  name: { $trim: { input: "$name" } },
  email: { $toLower: { $trim: { input: "$email" } } },
  age: { $convert: { input: "$age", to: "int", onError: null, onNull: null } }
} }]);
lab.people.find({}, { _id: 1, name: 1, email: 1, age: 1 }).sort({ _id: 1 }).toArray().map((d) => [d._id, d.name, d.email, d.age])
```

```text
[
  [ 1, 'Ann', 'ann@x.com', 31 ],
  [ 2, 'bob', 'bob@x.com', 27 ],
  [ 3, 'CY', 'cy@x.com', 45 ],
  [ 4, 'Di', 'di@x.com', null ],
  [ 5, 'Ed', 'ed@x.com', null ],
  [ 6, 'Flo', 'flo@x.com', 29 ]
]
```

### Problem 6: outliers with the standard deviation

Scores more than 2 standard deviations from the mean:

```js
lab.people.aggregate([
  { $group: { _id: null, avg: { $avg: "$score" }, sd: { $stdDevPop: "$score" }, docs: { $push: { id: "$_id", score: "$score" } } } },
  { $unwind: "$docs" },
  { $match: { $expr: { $gt: [{ $abs: { $subtract: ["$docs.score", "$avg"] } }, { $multiply: ["$sd", 2] }] } } },
  { $project: { _id: 0, id: "$docs.id", score: "$docs.score" } }
])
```

```text
[ { id: 6, score: 500 } ]
```

### Problem 7: outliers with quartiles (IQR)

The standard deviation is dragged by the outlier itself. The interquartile range is more robust: anything beyond 1.5 IQR outside the quartiles is an outlier:

```js
const q = lab.people.aggregate([{ $group: { _id: null, q: { $percentile: { input: "$score", p: [0.25, 0.75], method: "approximate" } } } }]).toArray()[0].q;
const iqr = q[1] - q[0];
lab.people.find({ $or: [{ score: { $lt: q[0] - 1.5 * iqr } }, { score: { $gt: q[1] + 1.5 * iqr } }] }, { score: 1 }).toArray().map((d) => [d._id, d.score])
```

```text
[ [ 6, 500 ] ]
```

### Real data: are all film lengths plausible?

```js
db.films.aggregate([
  { $group: { _id: null, min: { $min: "$lengthMinutes" }, max: { $max: "$lengthMinutes" }, avg: { $avg: "$lengthMinutes" }, sd: { $stdDevPop: "$lengthMinutes" } } },
  { $project: { _id: 0, min: 1, max: 1, avg: { $round: ["$avg", 1] }, sd: { $round: ["$sd", 1] } } }
])
```

```text
[ { min: 46, max: 185, avg: 115.3, sd: 40.4 } ]
```

## Try it yourself

Add a document with a negative age and a document with `email: ""`, then extend the checks to find both. Write the update that sets invalid ages to `null`.

## Watch out

### Fix on a copy, then swap

An `updateMany` with a wrong conversion is hard to undo. Back up the collection or fix a copy and compare.

### `$convert` can hide problems

`onError: -1` turns bad data into a value that looks valid. Prefer `null` and count the nulls, or record the failures.

### Standard deviation outliers need enough data

With a handful of values one outlier inflates the deviation so much that it hides itself. Use quartiles for small samples.

### Missing is not null

Decide how to treat absent fields; `$type` reports `"missing"` in aggregation, but a `find` uses `$exists`.

## Interview corner

**"How do you find documents where a field has the wrong type?"**
`{ field: { $not: { $type: "expected" } } }` in `find`, or `$group` by `{ $type: "$field" }` to see all types.

**"How do you clean strings in bulk?"**
An update pipeline with `$trim`, `$toLower`, `$replaceAll` and `$convert`.

**"How do you detect outliers?"**
Compare with mean and standard deviation, or use the interquartile range from `$percentile`.

### Core: convert with a fallback

Convert the same `v` values to integers, using `-1` when conversion fails, and return the array of results ordered by `_id`.

**Your result should look like this:**

```text
[ 1, 2, -1, 3 ]
```

<details>
<summary>Hint</summary>

`$convert` with `onError: -1`.

</details>

<details>
<summary>Show solution</summary>

```js
const lab = db.getSiblingDB("lab_clean")
lab.t.insertMany([{ _id: 1, v: 1 }, { _id: 2, v: "2" }, { _id: 3, v: "x" }, { _id: 4, v: 3 }]);
const r = lab.t.aggregate([{ $project: { v: { $convert: { input: "$v", to: "int", onError: -1 } } } }, { $sort: { _id: 1 } }]).toArray().map((d) => d.v)
lab.dropDatabase();
r
```
