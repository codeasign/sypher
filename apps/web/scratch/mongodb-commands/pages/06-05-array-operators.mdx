Arrays are everywhere in this database: a film's cast, its special features, a customer's rentals. A plain equality on an array field works, but three operators give you precise control: `$all`, `$elemMatch` and `$size`.

## What you'll learn

- How a condition on an array field is evaluated
- `$all`: the array contains every listed value
- `$elemMatch`: one element satisfies several conditions
- `$size` and array position queries

## Syntax

```js
{ tags: "a" }                                  // some element equals "a"
{ tags: { $all: ["a", "b"] } }                 // contains both
{ items: { $elemMatch: { qty: { $gt: 5 }, price: { $lt: 2 } } } }
{ tags: { $size: 3 } }                         // exactly three elements
{ "tags.0": "a" }                              // first element is "a"
```

## Examples

### Plain equality and comparison

For an array field, a condition is true if **any element** satisfies it:

```js
[
  db.films.countDocuments({ specialFeatures: "Trailers" }),
  db.films.countDocuments({ "actors.actorId": 1 })
]
```

```text
[ 535, 19 ]
```

### $all: contains every value

```js
[
  db.films.countDocuments({ specialFeatures: { $all: ["Trailers", "Commentaries"] } }),
  db.films.countDocuments({ specialFeatures: { $in: ["Trailers", "Commentaries"] } })
]
```

```text
[ 276, 798 ]
```

`$all` is AND across values, `$in` is OR.

### The trap: conditions that match different elements

Two conditions on the same array of documents can be satisfied by **different** elements:

```js
db.films.countDocuments({ "actors.firstName": "PENELOPE", "actors.lastName": "CHASE" })
```

```text
5
```

That counts films with some PENELOPE and some CHASE, even if they are two different people. There is no actor called PENELOPE CHASE.

### $elemMatch: the same element

`$elemMatch` requires **one element** to satisfy all the conditions together:

```js
db.films.countDocuments({ actors: { $elemMatch: { firstName: "PENELOPE", lastName: "CHASE" } } })
```

```text
0
```

```js
db.films.countDocuments({ actors: { $elemMatch: { firstName: "PENELOPE", lastName: "GUINESS" } } })
```

```text
19
```

### $elemMatch on nested rentals

Customers who have a rental that is **both** unreturned **and** from store 2:

```js
db.customers.countDocuments({ rentals: { $elemMatch: { returnDate: null, storeId: 2 } } })
```

```text
84
```

### $size

An exact number of elements:

```js
db.films.countDocuments({ specialFeatures: { $size: 4 } })
```

```text
61
```

`$size` accepts only an exact number. For "at least 3", test that the **third** element exists:

```js
db.films.countDocuments({ "specialFeatures.2": { $exists: true } })
```

```text
319
```

### Position

```js
db.films.countDocuments({ "specialFeatures.0": "Deleted Scenes" })
```

```text
132
```

### Matching the whole array

An exact array needs every element in the same order:

```js
db.films.countDocuments({ specialFeatures: ["Trailers", "Commentaries"] })
```

```text
72
```

### Arrays of plain values

For an array of numbers, `$elemMatch` applies operators to the elements themselves:

```js
const lab = db.getSiblingDB("lab_arr")
lab.scores.insertMany([{ _id: 1, s: [3, 9] }, { _id: 2, s: [7, 8] }, { _id: 3, s: [12] }]);
[
  lab.scores.find({ s: { $gt: 5, $lt: 8 } }).toArray().map((d) => d._id),
  lab.scores.find({ s: { $elemMatch: { $gt: 5, $lt: 8 } } }).toArray().map((d) => d._id)
]
```

```text
[ [ 1, 2 ], [ 2 ] ]
```

The first matches ids 1, 2 (3 satisfies `<8` and 9 satisfies `>5` at different positions). The second needs one element between 5 and 8: only document 2, through 7.

```js
lab.dropDatabase()
```

```text
{ ok: 1, dropped: 'lab_arr' }
```

## Try it yourself

Find the films that have **both** `Behind the Scenes` and `Deleted Scenes` as special features, and the customers with a rental whose `storeId` is 1 and whose `returnDate` is `null`.

## Watch out

### Without `$elemMatch`, conditions on array fields are independent

This is the single most common array mistake. If two conditions must apply to the **same** element, use `$elemMatch`.

### `$size` is exact

It cannot express ranges. Store a count field in the document if you often query by array length, or use `$expr` with `{ $size: ... }`.

### `$all` with one value equals plain equality

`{ tags: { $all: ["a"] } }` is the same as `{ tags: "a" }`.

### Order matters only for whole-array equality

`{ tags: ["a", "b"] }` does not match `["b", "a"]`, while `$all` does not care about order.

## Interview corner

**"What is the difference between `$in` and `$all`?"**
`$in` is true when the array contains **any** of the values (OR). `$all` needs **all** of them (AND).

**"Why is `$elemMatch` needed?"**
Without it, several conditions on an array of subdocuments can be satisfied by different elements. `$elemMatch` forces one element to satisfy them all.

**"How do you find arrays with at least N elements?"**
`{ "arr.N-1": { $exists: true } }`, or `$expr` with `$size` and `$gte`.
