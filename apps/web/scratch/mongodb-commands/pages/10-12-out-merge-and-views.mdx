An aggregation normally returns its result to you. Two stages can **write the result into a collection** instead, and a **view** saves a pipeline under a name so it can be queried like a collection. Together they give you summary tables, ETL jobs and reusable reports.

## What you'll learn

- `$out` to write (replace) a collection
- `$merge` to insert, update or merge into an existing collection
- Views: saved pipelines
- Materialised summaries and when to refresh them

## Syntax

```js
{ $out: "summary" }
{ $out: { db: "reports", coll: "summary" } }
{ $merge: { into: "summary", on: "_id", whenMatched: "merge", whenNotMatched: "insert" } }
db.createView("viewName", "sourceCollection", [ ...pipeline ])
```

## Examples

```js
const lab = db.getSiblingDB("lab_reports")
db.films.aggregate([{ $group: { _id: "$rating", films: { $sum: 1 } } }, { $out: { db: "lab_reports", coll: "rating_summary" } }]);
lab.rating_summary.find().sort({ _id: 1 }).toArray()
```

```text
[
  { _id: 'G', films: 178 },
  { _id: 'NC-17', films: 210 },
  { _id: 'PG', films: 194 },
  { _id: 'PG-13', films: 223 },
  { _id: 'R', films: 195 }
]
```

### $out replaces the target

Running it again replaces the collection completely (atomically at the end). It must be the **last** stage:

```js
db.films.aggregate([{ $match: { rating: "G" } }, { $group: { _id: "$rating", films: { $sum: 1 } } }, { $out: { db: "lab_reports", coll: "rating_summary" } }]);
lab.rating_summary.find().toArray()
```

```text
[ { _id: 'G', films: 178 } ]
```

### $merge: update an existing collection

`$merge` can insert new documents and update existing ones by a key. Rebuild the full summary first, then refresh two ratings with new numbers:

```js
db.films.aggregate([{ $group: { _id: "$rating", films: { $sum: 1 } } }, { $merge: { into: { db: "lab_reports", coll: "rating_summary" }, on: "_id", whenMatched: "replace", whenNotMatched: "insert" } }]);
lab.rating_summary.countDocuments()
```

```text
5
```

### whenMatched choices

| `whenMatched` | Effect |
|---|---|
| `replace` | Replace the existing document |
| `merge` | Merge the fields into it |
| `keepExisting` | Leave it as is |
| `fail` | Raise an error |
| a pipeline | Compute the new value from the old and the incoming one |

A pipeline lets you accumulate: add today's count to a running total.

```js
lab.totals.insertOne({ _id: "G", films: 100 });
db.films.aggregate([
  { $match: { rating: "G" } },
  { $group: { _id: "$rating", films: { $sum: 1 } } },
  { $merge: { into: { db: "lab_reports", coll: "totals" }, on: "_id", whenMatched: [{ $set: { films: { $add: ["$films", "$$new.films"] } } }], whenNotMatched: "insert" } }
]);
lab.totals.findOne({ _id: "G" })
```

```text
{ _id: 'G', films: 278 }
```

### $merge needs a unique index on the `on` fields

`_id` always has one. For any other key, create a unique index first:

```js
db.films.aggregate([{ $project: { title: 1, rating: 1 } }, { $merge: { into: { db: "lab_reports", coll: "titles" }, on: "_id" } }]);
lab.titles.countDocuments()
```

```text
1000
```

### Views: a saved pipeline

A view has no data of its own. Every query runs the pipeline again on the source collection:

```js
lab.createView("long_films", "films", [{ $match: { lengthMinutes: { $gt: 180 } } }, { $project: { title: 1, lengthMinutes: 1 } }]);
lab.getCollectionInfos({ name: "long_films" })[0].type
```

```text
view
```

The view lives in the database where you created it, so the source must be in the same database. Copy the films there first:

```js
db.films.aggregate([{ $out: { db: "lab_reports", coll: "films" } }]);
lab.long_films.countDocuments()
```

```text
39
```

```js
lab.long_films.find({}, { _id: 0 }).sort({ lengthMinutes: -1, title: 1 }).limit(2)
```

```text
[
  { lengthMinutes: 185, title: 'CHICAGO NORTH' },
  { lengthMinutes: 185, title: 'CONTROL ANTHEM' }
]
```

### Views hide fields

A view can serve as a safe window on a collection, for example without the staff password hashes:

```js
db.stores.aggregate([{ $out: { db: "lab_reports", coll: "stores" } }]);
lab.createView("stores_public", "stores", [{ $project: { managerStaffId: 1, "address.city": 1, "address.country": 1, staffCount: { $size: "$staff" } } }]);
lab.stores_public.find().sort({ _id: 1 }).toArray()
```

```text
[
  {
    _id: 1,
    address: { city: 'Lethbridge', country: 'Canada' },
    managerStaffId: 1,
    staffCount: 1
  },
  {
    _id: 2,
    address: { city: 'Woodridge', country: 'Australia' },
    managerStaffId: 2,
    staffCount: 1
  }
]
```

### Clean up

```js
lab.dropDatabase()
```

```text
{ ok: 1, dropped: 'lab_reports' }
```

Build a `category_stats` collection with `$out` (films, average length per category), then re-run it with `$merge` after changing a film in a scratch copy, and compare.

## Watch out

### `$out` is destructive

It drops and replaces the target collection when it completes. Never point it at a collection you want to keep. In `$out` the source and target must be different.

### `$merge` needs a unique index on `on`

Without it the stage fails. For sharded targets, the `on` fields must include the shard key.

### A view is recomputed on every query

It is not a cache. A heavy pipeline behind a view is slow on every read. For speed, materialise into a collection and refresh it on a schedule.

### Views cannot be indexed directly

A query on a view uses the indexes of the **source** collection where it can. Views also cannot use `$text` or `$out` and are read-only.

### Materialised data goes stale

A summary written with `$out` or `$merge` is a snapshot. Decide when it is refreshed (cron, change streams) and show its age.

## Interview corner

**"What is the difference between `$out` and `$merge`?"**
`$out` replaces the whole target collection. `$merge` inserts or updates into an existing collection by key, with control over what happens on a match.

**"What is a view?"**
A read-only, named aggregation pipeline over a collection. It stores no data, and its pipeline runs on each query.

**"How would you keep a summary table up to date?"**
Recompute it with `$merge` on a schedule (or after changes), or use a change stream to update it incrementally.
