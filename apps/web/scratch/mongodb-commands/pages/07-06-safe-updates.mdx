MongoDB has no `ROLLBACK` for an ordinary update and no confirmation prompt. A mistyped filter can change thousands of documents in milliseconds. Safe habits cost seconds and save days.

## What you'll learn

- Previewing exactly which documents a filter selects
- Backing up the affected documents before a bulk change
- Verifying the result with counts and samples
- Undoing a mistake, and using a transaction when you need all-or-nothing

## Syntax

```js
db.c.countDocuments(filter)                         // 1. how many?
db.c.find(filter).limit(5)                          // 2. which ones?
db.c.aggregate([{ $match: filter }, { $out: "c_backup" }])   // 3. backup
db.c.updateMany(filter, update)                     // 4. change
```

## Examples

This page changes the real `films` collection on purpose. The course restores it afterwards.

### Step 1: preview the filter

We want to raise the rental rate of `G` films that cost `0.99`. First, how many, and which:

```js
db.films.countDocuments({ rating: "G", rentalRate: 0.99 })
```

```text
64
```

```js
db.films.find({ rating: "G", rentalRate: 0.99 }, { title: 1, rentalRate: 1, _id: 0 }).sort({ title: 1 }).limit(3)
```

```text
[
  { rentalRate: 0.99, title: 'ALAMO VIDEOTAPE' },
  { rentalRate: 0.99, title: 'ANNIE IDENTITY' },
  { rentalRate: 0.99, title: 'ARMAGEDDON LOST' }
]
```

### Step 2: back up the affected documents

`$out` writes the selected documents into a new collection:

```js
db.films.aggregate([{ $match: { rating: "G", rentalRate: 0.99 } }, { $project: { rentalRate: 1 } }, { $out: "films_backup_rate" }]);
db.films_backup_rate.countDocuments()
```

```text
64
```

### Step 3: change, then check the counts

```js
const r = db.films.updateMany({ rating: "G", rentalRate: 0.99 }, { $set: { rentalRate: 1.49 } });
[r.matchedCount, r.modifiedCount]
```

```text
[ 64, 64 ]
```

The two counts equal the preview count, so the filter did what we expected. Now confirm nothing else moved:

```js
[db.films.countDocuments({ rentalRate: 1.49 }), db.films.countDocuments({ rating: "G", rentalRate: 0.99 })]
```

```text
[ 64, 0 ]
```

### Step 4: undo from the backup

If the change was wrong, restore the old values from the backup collection:

```js
db.films_backup_rate.find().forEach((b) => db.films.updateOne({ _id: b._id }, { $set: { rentalRate: b.rentalRate } }));
[db.films.countDocuments({ rentalRate: 1.49 }), db.films.countDocuments({ rating: "G", rentalRate: 0.99 })]
```

```text
[ 0, 64 ]
```

### Step 5: remove the backup when you are sure

```js
db.films_backup_rate.drop()
```

```text
true
```

### Guard rails inside the update

Make the filter narrow enough to be safe to re-run. Here the filter includes the old value, so running it twice changes nothing the second time:

```js
[
  db.films.updateMany({ rentalRate: 4.99, rating: "NC-17" }, { $set: { rentalRate: 5.49 } }).modifiedCount,
  db.films.updateMany({ rentalRate: 4.99, rating: "NC-17" }, { $set: { rentalRate: 5.49 } }).modifiedCount
]
```

```text
[ 71, 0 ]
```

### All-or-nothing with a transaction

A transaction makes several updates succeed or fail together, but it needs a replica set. A later module runs one for real. The shape is:

```js
const session = db.getMongo().startSession()
session.withTransaction(() => {
  session.getDatabase("shop").accounts.updateOne({ _id: "a" }, { $inc: { bal: -50 } })
  session.getDatabase("shop").accounts.updateOne({ _id: "b" }, { $inc: { bal: 50 } })
})
```

## Watch out

### Backups must hold the old values of the fields you change

A backup of `_id` only is useless. Project the fields you are about to overwrite, or copy the whole documents.

### `$out` replaces the target collection

If `films_backup_rate` already exists, `$out` overwrites it. Use a new name each time, for example with a date.

### `mongodump` is the real backup

Copying a few documents is a safety net for one change. For real recovery use `mongodump` or snapshots (module 15) and know how to restore them.

### Run on a copy first for risky changes

Restore a backup into a scratch database, run the update there, and inspect the result before touching production.

### Changes are visible immediately

There is no staging area. Other clients see each document as soon as it is updated.

## Interview corner

**"How do you make a bulk update safer?"**
Preview with `countDocuments`/`find` using the same filter, back up the affected documents, make the filter idempotent, then verify counts and a sample, and keep a way to undo.

**"Can you roll back an `updateMany`?"**
Not by itself. Inside a multi-document transaction (replica set required) you can abort, otherwise you restore from a backup or reverse the change.

**"What does `modifiedCount` tell you that `matchedCount` does not?"**
How many documents really changed. It exposes updates that matched but wrote the same value.

### Stretch: change and undo

Back up the `rentalRate` of films 1 to 3 into `bk`, set them to 6.99, then restore them from `bk`, and return the list of the three rates (ordered by `_id`).

**Your result should look like this:**

```text
[ 0.99, 4.99, 2.99 ]
```

<details>
<summary>Hint</summary>

`$out` into "bk", `updateMany`, then loop over `bk` to restore.

</details>

<details>
<summary>Show solution</summary>

```js
db.films.aggregate([{ $match: { _id: { $in: [1, 2, 3] } } }, { $project: { rentalRate: 1 } }, { $out: "bk" }]);
db.films.updateMany({ _id: { $in: [1, 2, 3] } }, { $set: { rentalRate: 6.99 } });
db.bk.find().forEach((b) => db.films.updateOne({ _id: b._id }, { $set: { rentalRate: b.rentalRate } }));
const rates = db.films.find({ _id: { $in: [1, 2, 3] } }).sort({ _id: 1 }).toArray().map((d) => d.rentalRate);
db.bk.drop();
rates
```

</details>
