`LIKE` matches text against a pattern. Two wildcard characters let you say "anything can go here". `ILIKE` does the same without caring about capital letters.

## What you'll learn

- The `%` and `_` wildcards
- Starts with, ends with, contains
- `LIKE` versus `ILIKE`
- Matching a literal `%` or `_`

## Syntax

```sql show
SELECT column1
FROM table_name
WHERE column1 LIKE 'pattern';    -- case-sensitive

SELECT column1
FROM table_name
WHERE column1 ILIKE 'pattern';   -- ignores case (PostgreSQL only)
```

`%` matches any number of characters (including none). `_` matches exactly one character.

## Examples

### Starts with

Film titles that start with `ZO`:

```sql run
SELECT title
FROM film
WHERE title LIKE 'ZO%'
ORDER BY title;
```

### Ends with

Titles that end with `LOVE`:

```sql run
SELECT title
FROM film
WHERE title LIKE '%LOVE'
ORDER BY title;
```

### Contains

Titles with `LOVE` anywhere in them:

```sql run
SELECT title
FROM film
WHERE title LIKE '%LOVE%'
ORDER BY title;
```

### One character at a time

`_` stands for exactly one character. Titles whose *second* letter is `A`:

```sql run
SELECT title
FROM film
WHERE title LIKE '_A%'
ORDER BY title;
```

### Ignoring case with ILIKE

The titles are stored in capitals, so a lower-case pattern finds nothing with `LIKE` but works with `ILIKE`:

```sql run
SELECT
  (SELECT COUNT(*) FROM film WHERE title LIKE '%love%') AS with_like,
  (SELECT COUNT(*) FROM film WHERE title ILIKE '%love%') AS with_ilike;
```

## Try it yourself

Find the films with `DOG` anywhere in the title, and the customers whose first name ends in `Y`.

## Watch out

### LIKE is case-sensitive in PostgreSQL

MySQL's `LIKE` ignores case; PostgreSQL's does not. If a search "finds nothing" for text you can see, check the case, and use `ILIKE`.

### A leading wildcard is slow

`LIKE 'ZO%'` can use a normal index on the column (with the right operator class), because the start of the value is known. `LIKE '%LOVE%'` cannot: PostgreSQL must read every row. Module 14 shows how a `pg_trgm` index fixes that.

### Matching a real percent sign

To search for a literal `%` or `_`, put a backslash before it (`LIKE '100\%'`). You can pick another escape character with `ESCAPE`.

### LIKE never matches NULL

A `NULL` value matches no pattern, including `'%'`. Use `IS NULL` for empty values.

### There are shortcuts

`~~` is `LIKE`, `~~*` is `ILIKE`, and `^@` means "starts with". They are less readable than the words, so you will mostly see them in query plans.

## Interview corner

**"What is the difference between `%` and `_`?"**
`%` matches any number of characters (zero or more); `_` matches exactly one.

**"What is the difference between `LIKE` and `ILIKE`?"**
`ILIKE` ignores case. It is PostgreSQL-specific; in other databases you write `LOWER(col) LIKE LOWER(pattern)`.

**"Why is `LIKE '%text%'` slow, and how would you speed it up?"**
A pattern that starts with a wildcard cannot use a normal (B-tree) index, so PostgreSQL scans the whole table. A trigram index (`pg_trgm` with GIN) or full-text search speeds it up.

## Practice

### Warm-up: titles starting with B

Show the `title` of every film that starts with `B`, ordered alphabetically. Show the first rows.

```sql practice
-- hint: `LIKE 'B%'`.
SELECT title
FROM film
WHERE title LIKE 'B%'
ORDER BY title;
```

### Core: names ending in `EN`

Show the `first_name` and `last_name` of actors whose first name ends in `EN`. Order by first name, then last name.

```sql practice
-- hint: `LIKE '%EN'`.
SELECT first_name, last_name
FROM actor
WHERE first_name LIKE '%EN'
ORDER BY first_name, last_name;
```

### Stretch: a pattern in the middle, ignoring case

Show the `title` of every film whose **third and fourth** letters are `dr` (in any case), so use `ILIKE`: two letters of anything, then `dr`, then anything else. Order alphabetically.

```sql practice
-- hint: `ILIKE '__dr%'` (two underscores).
SELECT title
FROM film
WHERE title ILIKE '__dr%'
ORDER BY title;
```
