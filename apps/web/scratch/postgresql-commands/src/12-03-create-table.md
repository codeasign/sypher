`CREATE TABLE` defines a new table: its name, its columns, and the type of each. It is where a design on paper becomes something you can store data in.

## What you'll learn

- Writing a `CREATE TABLE` statement
- Column options: `NOT NULL`, `DEFAULT`, identity columns
- Generated columns
- Inspecting the result with `\d` and `information_schema`

## Syntax

```sql show
CREATE TABLE [IF NOT EXISTS] table_name (
  column1 data_type [NOT NULL] [DEFAULT expression],
  column2 data_type [GENERATED ALWAYS AS IDENTITY],
  ...
);
```

Columns are separated by commas, and the whole list sits in one pair of brackets.

## Examples

### A first table

An `author` table for a bookshop. The `id` fills itself in, and `name` must always be given:

```sql run destructive
CREATE TABLE author (
  author_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name text NOT NULL
);

INSERT INTO author (name) VALUES ('Ursula K. Le Guin'), ('Terry Pratchett') RETURNING *;
```

### A table with defaults

A `DEFAULT` is the value used when you do not supply one:

```sql run destructive
CREATE TABLE book (
  book_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title text NOT NULL,
  price numeric(6, 2) NOT NULL DEFAULT 9.99,
  in_stock boolean NOT NULL DEFAULT true,
  added_at timestamptz NOT NULL DEFAULT now()
);
```

`now()` fills in the moment the row is inserted.

### Insert and read back

Give only the columns that have no default, and let PostgreSQL fill in the rest:

```sql run destructive
INSERT INTO book (title) VALUES ('The Dispossessed') RETURNING book_id, title, price, in_stock;
```

The `price` and `in_stock` columns took their default values.

### Generated columns

A **generated column** is calculated by PostgreSQL from other columns of the same row, and cannot be written to. The DVD Rental `film` table has two:

```sql run destructive
CREATE TABLE invoice_line (
  qty integer NOT NULL,
  unit_price numeric(8, 2) NOT NULL,
  line_total numeric(10, 2) GENERATED ALWAYS AS (qty * unit_price) STORED
);

INSERT INTO invoice_line (qty, unit_price) VALUES (3, 2.50), (10, 0.99);

SELECT * FROM invoice_line;
```

`STORED` saves the value on disk. Since PostgreSQL 18 you can also write `VIRTUAL`, which is calculated when read, as `film.rentals_to_breakeven` is.

### See the full definition

`information_schema.columns` shows the definition as data:

```sql run destructive
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_name = 'book'
ORDER BY ordinal_position;
```

In `psql`, `\d book` shows the same in one screen.

## Try it yourself

Create a `customer_note` table with an id, a note (text, required) and a `created_at` that fills itself in, then insert a note.

## Watch out

### The table must not already exist

`CREATE TABLE IF NOT EXISTS author (...)` skips it quietly when it exists. Drop the old one first if you want to recreate it.

### Give every table a primary key

A table without one has no reliable way to point at a single row, and many features (logical replication, foreign keys) work badly. Even a link table needs a key, often made of its two columns.

### GENERATED ALWAYS refuses your own value

An identity column declared `ALWAYS` rejects an explicit value unless you say `OVERRIDING SYSTEM VALUE`:

```sql run error destructive
INSERT INTO author (author_id, name) VALUES (99, 'Someone');
```

Use `GENERATED BY DEFAULT AS IDENTITY` if you want to allow your own ids.

### Choose names you will not regret

Use lower-case words with underscores (`order_item`), singular or plural consistently, and avoid reserved words (`order`, `group`, `user`) as names. Unquoted names are folded to lower case.

### DEFAULT must be a simple expression

You can use constants and functions such as `now()` or `gen_random_uuid()`. You cannot refer to other columns in a default: use a generated column for that.

## Interview corner

**"What is the difference between `CREATE TABLE` and `CREATE TABLE IF NOT EXISTS`?"**
The first errors if the table exists. The second does nothing in that case.

**"What does `GENERATED ALWAYS AS IDENTITY` do?"**
It gives the column an automatic sequence of numbers (the modern, standard replacement for `serial`), and refuses manually supplied values unless overridden.

**"What is a generated column?"**
A column whose value PostgreSQL calculates from other columns of the row. `STORED` columns are written to disk; `VIRTUAL` columns (PostgreSQL 18) are computed on read.

## Practice

### Warm-up: a small table

Create `genre` with `genre_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY` and `name text NOT NULL`. Insert `Fantasy` and `Mystery`, and return both rows.

```sql practice destructive
-- hint: `INSERT ... RETURNING *` or a SELECT afterwards.
CREATE TABLE genre (genre_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY, name text NOT NULL);
INSERT INTO genre (name) VALUES ('Fantasy'), ('Mystery');

SELECT * FROM genre ORDER BY genre_id;
```

### Core: defaults at work

Create `member` with `member_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY`, `name text NOT NULL`, and `level text NOT NULL DEFAULT 'bronze'`. Insert two members giving only names, and return `name` and `level`.

```sql practice destructive
-- hint: The default fills `level`.
CREATE TABLE member (member_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY, name text NOT NULL, level text NOT NULL DEFAULT 'bronze');
INSERT INTO member (name) VALUES ('Asha'), ('Ben');

SELECT name, level FROM member ORDER BY member_id;
```

### Stretch: a generated column

Create `rectangle (w integer, h integer, area integer GENERATED ALWAYS AS (w * h) STORED)`. Insert `(3, 4)` and `(5, 6)`, and return `w`, `h`, `area`, ordered by `area`.

```sql practice destructive
-- hint: Do not supply `area`; PostgreSQL calculates it.
CREATE TABLE rectangle (w integer, h integer, area integer GENERATED ALWAYS AS (w * h) STORED);
INSERT INTO rectangle (w, h) VALUES (3, 4), (5, 6);

SELECT w, h, area FROM rectangle ORDER BY area;
```
