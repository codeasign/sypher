`NOT` flips a condition: it keeps the rows that do **not** match.

Ask for "every film that is *not* rated G" and PostgreSQL hands back everything except the G films. You will use it constantly, both to exclude things you don't want and to ask "who is missing?" questions.

## What you'll learn

- `NOT` with a comparison, and the built-in forms `NOT LIKE`, `NOT IN`, `NOT BETWEEN` and `IS NOT NULL`
- Why `NOT IN` and `NULL` do not mix
- Why `NOT` needs brackets when combined with `AND` or `OR`

## Syntax

```sql
SELECT column1
FROM table_name
WHERE NOT condition;
```

`NOT` goes in front of a condition. Some conditions have their own built-in forms: `NOT LIKE`, `NOT IN`, `NOT BETWEEN` and `IS NOT NULL`.

## Examples

### NOT with a comparison

Every film that is not rated G:

```sql
SELECT title, rating
FROM film
WHERE NOT rating = 'G'
ORDER BY title;
```

| title | rating |
|---|---|
| ACADEMY DINOSAUR | PG |
| ADAPTATION HOLES | NC-17 |
| AGENT TRUMAN | PG |
| AIRPLANE SIERRA | PG-13 |
| AIRPORT POLLOCK | R |
| … | … |

*Showing the first 5 of 822 rows.*

`NOT rating = 'G'` means the same as `rating <> 'G'`. Both count the same number of films:

```sql
SELECT
  (SELECT COUNT(*) FROM film WHERE NOT rating = 'G') AS with_not,
  (SELECT COUNT(*) FROM film WHERE rating <> 'G') AS with_not_equal;
```

| with_not | with_not_equal |
|---:|---:|
| 822 | 822 |

*1 row returned.*

### NOT LIKE

Every film whose title does **not** start with the letter A:

```sql
SELECT title
FROM film
WHERE title NOT LIKE 'A%'
ORDER BY title;
```

| title |
|---|
| BABY HALL |
| BACKLASH UNDEFEATED |
| BADMAN DAWN |
| BAKED CLEOPATRA |
| BALLOON HOMEWARD |
| … |

*Showing the first 5 of 954 rows.*

### NOT IN

Every film that is neither rated G nor PG:

```sql
SELECT title, rating
FROM film
WHERE rating NOT IN ('G', 'PG')
ORDER BY title;
```

| title | rating |
|---|---|
| ADAPTATION HOLES | NC-17 |
| AIRPLANE SIERRA | PG-13 |
| AIRPORT POLLOCK | R |
| ALABAMA DEVIL | PG-13 |
| ALADDIN CALENDAR | NC-17 |
| … | … |

*Showing the first 5 of 628 rows.*

### NOT BETWEEN

Films that are unusually short or long, meaning outside the 60 to 150 minute range:

```sql
SELECT title, length
FROM film
WHERE length NOT BETWEEN 60 AND 150
ORDER BY length, title;
```

| title | length |
|---|---:|
| ALIEN CENTER | 46 |
| IRON MOON | 46 |
| KWAI HOMEWARD | 46 |
| LABYRINTH LEAGUE | 46 |
| RIDGEMONT SUBMARINE | 46 |
| … | … |

*Showing the first 5 of 338 rows.*

`BETWEEN` includes both ends, so a 60 minute or 150 minute film is *not* returned here.

### IS NOT NULL

`NULL` means "no value", and you can't test it with `=`. To keep only the rentals that have already been returned:

```sql
SELECT rental_id, upper(rental_period) AS returned_at
FROM rental
WHERE upper(rental_period) IS NOT NULL
ORDER BY rental_id
LIMIT 5;
```

| rental_id | returned_at |
|---:|---|
| 1 | 2005-05-26 22:04:30 |
| 2 | 2005-05-28 19:40:33 |
| 3 | 2005-06-01 22:12:39 |
| 4 | 2005-06-03 01:43:41 |
| 5 | 2005-06-02 04:33:21 |

*5 rows returned.*

## Watch out

### NOT IN and NULL

This is the most famous trap. In this database, every film's `original_language_id` is empty (`NULL`). Let's find films whose `language_id` is not in that list:

```sql
SELECT COUNT(*) AS found
FROM film
WHERE language_id NOT IN (SELECT original_language_id FROM film);
```

| found |
|---:|
| 0 |

*1 row returned.*

Every film should qualify, because the list has no real values in it, yet we get zero. If the list contains even one `NULL`, `NOT IN` can never say "yes": PostgreSQL can't be sure the value isn't equal to that unknown. The fix is to keep `NULL`s out of the list:

```sql
SELECT COUNT(*) AS found
FROM film
WHERE language_id NOT IN (SELECT original_language_id FROM film WHERE original_language_id IS NOT NULL);
```

| found |
|---:|
| 1000 |

*1 row returned.*

### NOT applies to the next condition only

Without brackets, `NOT` only covers the condition right after it. These two lines look alike but ask different questions:

```sql
SELECT
  (SELECT COUNT(*) FROM film WHERE NOT rating = 'G' AND length < 60) AS not_g_and_short,
  (SELECT COUNT(*) FROM film WHERE NOT (rating = 'G' AND length < 60)) AS not_both;
```

| not_g_and_short | not_both |
|---:|---:|
| 75 | 979 |

*1 row returned.*

The first means "not rated G, **and** shorter than 60 minutes". The second means "**not** (rated G and shorter than 60 minutes)", which lets in every film that fails either half. When you mix `NOT` with `AND` or `OR`, add brackets.

### NOT never rescues a NULL

If a value is `NULL`, both `= 1` and `NOT = 1` are "unknown", and `WHERE` only keeps rows that are definitely true:

```sql
SELECT COUNT(*) AS found
FROM film
WHERE NOT original_language_id = 1;
```

| found |
|---:|
| 0 |

*1 row returned.*

To include the empty ones, ask for them explicitly:

```sql
SELECT COUNT(*) AS found
FROM film
WHERE original_language_id IS DISTINCT FROM 1;
```

| found |
|---:|
| 1000 |

*1 row returned.*

## Interview corner

**"What is the difference between `NOT IN` and `NOT EXISTS`?"**
`NOT IN` returns nothing if the list contains a `NULL` (see *NOT IN and NULL* above). `NOT EXISTS` doesn't have that problem, so it is the safer choice when the list comes from a subquery. You will write it properly in Module 7, but here is the same question answered with it:

```sql
SELECT COUNT(*) AS found
FROM film f
WHERE NOT EXISTS (SELECT 1 FROM film o WHERE o.original_language_id = f.language_id);
```

| found |
|---:|
| 1000 |

*1 row returned.*

**"Is `NOT LIKE` case-sensitive?"**
Yes in PostgreSQL (`'a' NOT LIKE 'A'` is true). Use `NOT ILIKE` to ignore case:

```sql
SELECT 'a' NOT LIKE 'A' AS not_like, 'a' NOT ILIKE 'A' AS not_ilike;
```

| not_like | not_ilike |
|---|---|
| t | f |

*1 row returned.*

**"How would you write `NOT BETWEEN` without using `NOT`?"**
Use `OR` on the two sides. It returns exactly the same films:

```sql
SELECT COUNT(*) AS found
FROM film
WHERE length < 60 OR length > 150;
```

| found |
|---:|
| 338 |

*1 row returned.*

### Stretch: films without trailers

The `special_features` column is an **array** of extras such as `Trailers` or `Deleted Scenes`. Show the `title` and `special_features` of every film that does **not** include `Trailers`, alphabetical by title. (`'Trailers' = ANY (special_features)` tests for membership.)

**Your result should look like this:**

|---|---|

| AFFAIR PREJUDICE | {Commentaries,"Behind the Scenes"} |

<summary>Hint</summary>
