`IN` checks whether a value matches any value in a list. It is a shorter, cleaner way to write several `OR` conditions on the same column.

## What you'll learn

- Testing a value against a list
- `IN` as a shortcut for repeated `OR`
- `= ANY (array)`, the PostgreSQL way to test against an array
- `NOT IN`

## Syntax

```sql
SELECT column1
FROM table_name
WHERE column1 IN (value1, value2, value3);
```

## Examples

### A list of text values

Films rated G or PG:

```sql
SELECT title, rating
FROM film
WHERE rating IN ('G', 'PG')
ORDER BY title;
```

| title | rating |
|---|---|
| ACADEMY DINOSAUR | PG |
| ACE GOLDFINGER | G |
| AFFAIR PREJUDICE | G |
| AFRICAN EGG | G |
| AGENT TRUMAN | PG |
| … | … |

*Showing the first 5 of 372 rows.*

### A list of numbers

Customers with particular ids:

```sql
SELECT customer_id, first_name, last_name
FROM customer
WHERE customer_id IN (1, 5, 10, 100)
ORDER BY customer_id;
```

| customer_id | first_name | last_name |
|---:|---|---|
| 1 | MARY | SMITH |
| 5 | ELIZABETH | BROWN |
| 10 | DOROTHY | TAYLOR |
| 100 | ROBIN | HAYES |

*4 rows returned.*

### Same as a string of ORs

`IN` and repeated `OR` give the same rows. These two counts match:

```sql
SELECT
  (SELECT COUNT(*) FROM film WHERE rating IN ('G', 'PG')) AS with_in,
  (SELECT COUNT(*) FROM film WHERE rating = 'G' OR rating = 'PG') AS with_or;
```

| with_in | with_or |
|---:|---:|
| 372 | 372 |

*1 row returned.*

`IN` is easier to read, and easier to extend when you need one more value.

### ANY with an array

PostgreSQL can hold a whole list in one value, an **array**. `= ANY (array)` is the same test as `IN`, and lets you pass the list as one parameter from an application:

```sql
SELECT title, rating
FROM film
WHERE rating = ANY (ARRAY['G', 'PG']::mpaa_rating[])
ORDER BY title;
```

| title | rating |
|---|---|
| ACADEMY DINOSAUR | PG |
| ACE GOLDFINGER | G |
| AFFAIR PREJUDICE | G |
| AFRICAN EGG | G |
| AGENT TRUMAN | PG |
| … | … |

*Showing the first 5 of 372 rows.*

## Watch out

### A NULL in a NOT IN list matches nothing

`NULL` is never equal to anything, even `NULL`. With `NOT IN`, one `NULL` in the list makes every answer unknown:

```sql
SELECT
  (SELECT COUNT(*) FROM film WHERE language_id NOT IN (2, 3)) AS without_null,
  (SELECT COUNT(*) FROM film WHERE language_id NOT IN (2, 3, NULL)) AS with_null;
```

| without_null | with_null |
|---:|---:|
| 1000 | 0 |

*1 row returned.*

Every film is in language 1, so the first count is all of them. Add one `NULL` to the list and the count drops to zero. Use `NOT EXISTS` (Module 7) or make sure the list has no `NULL`.

### The types must match

`IN ('G', 'XX')` on an enum column fails, because `'XX'` is not a valid rating. On a number column, `IN ('1', '2')` works but hides bugs. Match the list's type to the column's type.

## Interview corner

**"What is the difference between `IN` and `OR`?"**
Nothing in the result: `col IN (a, b, c)` is a shorthand for `col = a OR col = b OR col = c`. `IN` reads better, and can also take a subquery instead of a fixed list.

**"Can `IN` contain a subquery?"**
Yes: `WHERE film_id IN (SELECT film_id FROM inventory)`. You will use this in Module 7.

**"How do you pass a list of ids from application code?"**
As one array parameter: `WHERE id = ANY($1)`, so the number of ids does not change the query text.
