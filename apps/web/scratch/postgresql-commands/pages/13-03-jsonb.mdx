PostgreSQL can store JSON documents in a column and query inside them with SQL. Use `jsonb` (the binary form): it is indexed, compared and processed efficiently. This page uses the DVD Rental rows themselves as documents, then builds a small table of events.

## What you'll learn

- Turning rows into JSON, and JSON into rows
- The operators `->`, `->>`, `@>` and `?`
- Building and changing JSON
- Indexing `jsonb` with GIN

## Syntax

```sql
SELECT doc -> 'key', doc ->> 'key', doc #>> '{a,b}' FROM t;
SELECT * FROM t WHERE doc @> '{"type": "click"}';
SELECT jsonb_build_object('a', 1), jsonb_agg(x), jsonb_set(doc, '{a}', '2');
```

## Examples

### A row as a JSON document

```sql
SELECT to_jsonb(c) AS customer
FROM (SELECT customer_id, first_name, last_name, activebool FROM customer WHERE customer_id = 1) c;
```

| customer |
|---|
| {"last_name": "SMITH", "activebool": true, "first_name": "MARY", "customer_id": 1} |

*1 row returned.*

### Building JSON by hand

```sql
SELECT jsonb_build_object('title', title, 'length', length, 'rating', rating) AS doc
FROM film
WHERE film_id = 1;
```

| doc |
|---|
| {"title": "ACADEMY DINOSAUR", "length": 86, "rating": "PG"} |

*1 row returned.*

### A table with a jsonb column

```sql
CREATE TABLE app_event (
  event_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  payload jsonb NOT NULL
);

INSERT INTO app_event (payload) VALUES
  ('{"type": "click", "page": "/home", "tags": ["nav", "blue"], "user": {"id": 7, "plan": "free"}}'),
  ('{"type": "view", "page": "/pricing", "tags": ["blue"], "user": {"id": 8, "plan": "paid"}}'),
  ('{"type": "click", "page": "/pricing", "user": {"id": 7, "plan": "free"}}');

SELECT event_id, payload FROM app_event ORDER BY event_id;
```

| event_id | payload |
|---:|---|
| 1 | {"page": "/home", "tags": ["nav", "blue"], "type": "click", "user": {"id": 7, "plan": "free"}} |
| 2 | {"page": "/pricing", "tags": ["blue"], "type": "view", "user": {"id": 8, "plan": "paid"}} |
| 3 | {"page": "/pricing", "type": "click", "user": {"id": 7, "plan": "free"}} |

*3 rows returned.*

### Reading values: -> and ->>

`->` returns JSON. `->>` returns text. Chain them to go deeper:

```sql
SELECT event_id,
       payload -> 'type' AS type_json,
       payload ->> 'type' AS type_text,
       payload -> 'user' ->> 'plan' AS plan,
       (payload #>> '{user,id}')::int AS user_id
FROM app_event
ORDER BY event_id;
```

| event_id | type_json | type_text | plan | user_id |
|---:|---|---|---|---:|
| 1 | "click" | click | free | 7 |
| 2 | "view" | view | paid | 8 |
| 3 | "click" | click | free | 7 |

*3 rows returned.*

### Filtering: @> means "contains"

```sql
SELECT event_id, payload ->> 'page' AS page
FROM app_event
WHERE payload @> '{"type": "click", "user": {"plan": "free"}}'
ORDER BY event_id;
```

| event_id | page |
|---:|---|
| 1 | /home |
| 3 | /pricing |

*2 rows returned.*

### Keys and arrays

`?` tests for a top-level key, and `jsonb_array_elements_text` turns a JSON array into rows:

```sql
SELECT COUNT(*) FILTER (WHERE payload ? 'tags') AS with_tags, COUNT(*) AS total FROM app_event;

SELECT event_id, tag
FROM app_event, jsonb_array_elements_text(payload -> 'tags') AS tag
ORDER BY event_id, tag;
```

| with_tags | total |
|---:|---:|
| 2 | 3 |

*1 row returned.*

| event_id | tag |
|---:|---|
| 1 | blue |
| 1 | nav |
| 2 | blue |

*3 rows returned.*

### Aggregating into JSON

```sql
SELECT jsonb_agg(payload ->> 'page' ORDER BY event_id) AS pages,
       jsonb_object_agg(event_id, payload ->> 'type' ORDER BY event_id) AS types
FROM app_event;
```

| pages | types |
|---|---|
| ["/home", "/pricing", "/pricing"] | {"1": "click", "2": "view", "3": "click"} |

*1 row returned.*

### Changing JSON

`jsonb_set` replaces a value at a path, and `||` merges objects. They return a new value, so use them in `UPDATE`:

```sql
UPDATE app_event
SET payload = jsonb_set(payload, '{user,plan}', '"paid"') || '{"reviewed": true}'
WHERE event_id = 1
RETURNING payload;
```

| payload |
|---|
| {"page": "/home", "tags": ["nav", "blue"], "type": "click", "user": {"id": 7, "plan": "paid"}, "reviewed": true} |

*1 row returned.*

### A GIN index for @>

```sql
CREATE INDEX idx_event_payload ON app_event USING gin (payload);

SELECT indexdef FROM pg_indexes WHERE indexname = 'idx_event_payload';
```

| indexdef |
|---|
| CREATE INDEX idx_event_payload ON public.app_event USING gin (payload) |

*1 row returned.*

## Watch out

### `->` versus `->>`

`payload -> 'type'` is JSON (with quotes: `"click"`), `payload ->> 'type'` is text (`click`). Compare with `->>` when you mean plain text.

### Missing keys are NULL, not errors

`payload ->> 'nope'` is `NULL`. That is handy, and it hides typos in key names.

### json versus jsonb

`json` stores the text exactly as typed (whitespace, duplicate keys) and re-parses it on every use. `jsonb` stores a parsed binary form: faster to query, indexable, but it reorders keys and drops duplicates. Use `jsonb`.

### JSON is not a substitute for columns

If every row has the same keys, and you filter or join on them, use real columns with types and constraints. JSON suits flexible or rarely queried attributes.

### Updating one key rewrites the whole document

Big documents that change often make large row versions. Keep hot, frequently updated values in their own columns.

## Interview corner

**"What is the difference between `json` and `jsonb`?"**
`json` keeps the input text; `jsonb` is a decomposed binary format that is faster to process, supports indexing and containment operators, and does not preserve key order or duplicates.

**"How do you query inside a jsonb column efficiently?"**
Use `@>` with a GIN index for containment, or an expression index on one key (`CREATE INDEX ON t ((payload ->> 'type'))`) for equality on a single field.

**"When would you store JSON in PostgreSQL?"**
For semi-structured data such as event payloads, settings or API responses, where the shape varies. Keep core, queried fields as normal columns.

### Stretch: search by containment

Create `note (body jsonb)` with the rows `{"tags": ["a", "b"]}`, `{"tags": ["b", "c"]}` and `{"tags": ["c"]}`. Return how many notes have the tag `b`, as `with_b`, using `@>`.

**Your result should look like this:**

| with_b |
|---:|
| 2 |

*1 row returned.*

<details>
<summary>Hint</summary>

`body @> '{"tags": ["b"]}'`.

</details>

<details>
<summary>Show solution</summary>

```sql
CREATE TABLE note (body jsonb);
INSERT INTO note VALUES ('{"tags": ["a", "b"]}'), ('{"tags": ["b", "c"]}'), ('{"tags": ["c"]}');

SELECT COUNT(*) AS with_b FROM note WHERE body @> '{"tags": ["b"]}';
```

</details>
