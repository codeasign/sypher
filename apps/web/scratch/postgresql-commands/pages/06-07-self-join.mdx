A **self join** joins a table to itself. It sounds odd, but it is how you compare rows of the same table with each other, for example "which actors share a last name?" or "which employees earn more than their manager?".

## What you'll learn

- Joining a table to itself with two aliases
- Comparing rows of the same table
- Avoiding duplicate and mirrored pairs

## Syntax

```sql
SELECT a.column1, b.column1
FROM table1 a
JOIN table1 b ON a.some_column = b.some_column AND a.id < b.id;
```

You must give the two copies different aliases, because otherwise PostgreSQL cannot tell them apart.

## Examples

### Pairs that share a value

Actors who share a last name. The two copies of `actor` are `a1` and `a2`:

```sql
SELECT a1.first_name AS first_actor, a2.first_name AS second_actor, a1.last_name
FROM actor a1
JOIN actor a2 ON a1.last_name = a2.last_name AND a1.actor_id < a2.actor_id
WHERE a1.last_name = 'AKROYD'
ORDER BY a1.actor_id, a2.actor_id;
```

| first_actor | second_actor | last_name |
|---|---|---|
| CHRISTIAN | KIRSTEN | AKROYD |
| CHRISTIAN | DEBBIE | AKROYD |
| KIRSTEN | DEBBIE | AKROYD |

*3 rows returned.*

The condition `a1.actor_id < a2.actor_id` matters. Without it, every actor would be paired with themselves, and each pair would appear twice (`A, B` and `B, A`).

### Films of the same length and rating

```sql
SELECT f1.title AS film_one, f2.title AS film_two, f1.length, f1.rating
FROM film f1
JOIN film f2 ON f1.length = f2.length AND f1.rating = f2.rating AND f1.film_id < f2.film_id
WHERE f1.length = 46
ORDER BY f1.film_id, f2.film_id
LIMIT 5;
```

| film_one | film_two | length | rating |
|---|---|---:|---|
| KWAI HOMEWARD | LABYRINTH LEAGUE | 46 | PG-13 |
| KWAI HOMEWARD | RIDGEMONT SUBMARINE | 46 | PG-13 |
| LABYRINTH LEAGUE | RIDGEMONT SUBMARINE | 46 | PG-13 |

*3 rows returned.*

### Comparing a row with others in its table

For each film, count how many films are shorter than it. Restricting to a few films keeps the work small:

```sql
SELECT f1.title, f1.length, COUNT(f2.film_id) AS shorter_films
FROM film f1
LEFT JOIN film f2 ON f2.length < f1.length
WHERE f1.film_id <= 3
GROUP BY f1.film_id, f1.title, f1.length
ORDER BY f1.film_id;
```

| title | length | shorter_films |
|---|---:|---:|
| ACADEMY DINOSAUR | 86 | 299 |
| ACE GOLDFINGER | 48 | 12 |
| ADAPTATION HOLES | 50 | 28 |

*3 rows returned.*

## Watch out

### Without the "less than" filter, you get self-pairs and mirrors

Compare the number of pairs with and without `a1.actor_id < a2.actor_id`:

```sql
SELECT
  (SELECT COUNT(*) FROM actor a1 JOIN actor a2 ON a1.last_name = a2.last_name) AS all_pairs,
  (SELECT COUNT(*) FROM actor a1 JOIN actor a2 ON a1.last_name = a2.last_name AND a1.actor_id < a2.actor_id) AS unique_pairs;
```

| all_pairs | unique_pairs |
|---:|---:|
| 416 | 108 |

*1 row returned.*

The first count includes each actor paired with themselves (one row per actor) and every real pair twice.

### Self joins on big tables are expensive

Comparing every row with every other row can mean millions of pairs. Index the joining columns, and filter before you join.

### Window functions are often better

"Compare each row with the previous one" is usually neater with `LAG` (Module 8) than with a self join.

## Interview corner

**"What is a self join, and when do you use it?"**
Joining a table to itself under two aliases. Use it to compare rows within a table: rows with the same value, an employee and their manager, consecutive rows.

**"How do you avoid seeing each pair twice in a self join?"**
Add an inequality such as `a.id < b.id`, so each pair is returned once and no row pairs with itself.

### Stretch: customers in the same city

Show pairs of customers who live in the same city, as `customer_one` and `customer_two` (the two `customer_id`s), each pair once, ordered by both. Show the first rows. (Join `customer` to `address` twice, or first find each customer's `city_id`.)

**Your result should look like this:**

| customer_one | customer_two |
|---:|---:|
| 252 | 512 |
| 330 | 537 |

*2 rows returned.*

<details>
<summary>Hint</summary>

Put `address` next to each `customer` copy and compare `city_id`.

</details>

<details>
<summary>Show solution</summary>

```sql
SELECT c1.customer_id AS customer_one, c2.customer_id AS customer_two
FROM customer c1
JOIN address a1 ON a1.address_id = c1.address_id
JOIN address a2 ON a2.city_id = a1.city_id
JOIN customer c2 ON c2.address_id = a2.address_id AND c1.customer_id < c2.customer_id
ORDER BY c1.customer_id, c2.customer_id;
```

</details>
