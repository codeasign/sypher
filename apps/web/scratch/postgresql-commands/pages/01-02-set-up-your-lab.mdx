Reading about SQL is not enough. You learn it by running queries and seeing what comes back. This page gets a real PostgreSQL database running on your own computer in a few minutes.

## What you'll need

- **Docker Desktop** (Windows or macOS), or Docker Engine with the Compose plugin (Linux). It runs PostgreSQL for you, so you don't install PostgreSQL itself.
- The **sypher-db-lab** folder. It contains the DVD Rental database and everything needed to load it, and it is supplied with this course as a ready-to-run folder: you do not download the data separately, and starting PostgreSQL only pulls the official PostgreSQL image from Docker Hub. If you do not have the folder yet, get it from whoever gave you this course before you continue.

Check that Docker works:

```bash
docker version
docker compose version
```

## Start PostgreSQL

Open a terminal in the `sypher-db-lab` folder and run:

```bash
docker compose up -d postgres
docker compose ps
```

The first start downloads PostgreSQL and loads the DVD Rental database, which takes a minute or two. Wait until the `STATUS` column says `healthy`.

## Connect

This command opens a PostgreSQL prompt (called **psql**) inside the running container:

```bash
docker compose exec postgres psql -U sypher -d sypher-postgresql-DvdRental
```

Your prompt now looks like `sypher-postgresql-DvdRental=#`. Type a query, end it with a semicolon, and press Enter. Try this one:

```sql
SELECT current_database() AS current_database, current_user AS user_name;
```

| current_database | user_name |
|---|---|
| sypher-postgresql-DvdRental | sypher |

*1 row returned.*

If you see something like the table above, you are connected to the right database. To leave the prompt, type `\q`.

The connection details, in case a tool asks for them:

| Setting | Value |
|---|---|
| Host | `localhost` |
| Port | `5432` |
| Database | `sypher-postgresql-DvdRental` |
| User | `sypher` |
| Password | `password` |

These simple credentials are fine for a practice database on your own machine. Never use them for anything real.

## Two ways to run queries

1. **The command line** (`psql`) you just used. Fast, and available everywhere. Section 1.3 is a tour of it.
2. **A visual tool** such as DBeaver or pgAdmin. Connect with the details above. Many people prefer these for longer queries, because you can save and edit them.

Use whichever you like. Every query in this course works in both.

## Start again from scratch

You will practise `INSERT`, `UPDATE`, `DELETE` and `DROP` in this course. The lab has a script that puts the database back exactly as it was, and checks that it did. Run it from the `sypher-db-lab` folder whenever you want a clean copy:

```bash
bash scripts/reset-postgres.sh
```

It prints `RESTORED` when the database matches the original again. (On Windows use Git Bash, which comes with Git for Windows.)

## Watch out

- **The database name needs double quotes in SQL.** `sypher-postgresql-DvdRental` has hyphens and capital letters, so inside a SQL command (for example `\c` or `CREATE DATABASE ... TEMPLATE`) write it as `"sypher-postgresql-DvdRental"`. On the command line after `-d`, no quotes are needed.
- **Port 5432 already in use.** Another PostgreSQL is running on your machine. In `docker-compose.yml`, change `"5432:5432"` to `"5433:5432"` and connect on port `5433`.
- **A query "does nothing".** Every statement must end with `;`. If the prompt changes to `sypher-postgresql-DvdRental-#`, PostgreSQL is still waiting for the end. Type `;` and press Enter.

## Interview corner

**"How would you run PostgreSQL locally without installing it?"**
In a container, for example with Docker Compose. It keeps the database isolated, makes it easy to reset, and matches how many teams run databases in development.
