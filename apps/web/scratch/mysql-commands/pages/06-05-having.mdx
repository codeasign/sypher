`HAVING` filters **groups**. It is `WHERE` for the results of `GROUP BY`, and the only place where you can filter on an aggregate such as `COUNT(*)` or `SUM(...)`.

## What you'll learn

- Filtering groups with `HAVING`
- `WHERE` versus `HAVING`
- Using both in one query

## Syntax

```sql
SELECT column, AGGREGATE_FUNCTION(other_column)
FROM table_name
WHERE row_condition
GROUP BY column
HAVING group_condition
ORDER BY column;
```

## Examples

### Groups above a size

Ratings that have more than 200 films:

```sql
SELECT rating, COUNT(*) AS films
FROM film
GROUP BY rating
HAVING COUNT(*) > 200
ORDER BY films DESC;
```

| rating | films |
|---|---:|
| PG-13 | 223 |
| NC-17 | 210 |

*2 rows returned.*

### Big spenders

Customers who have paid more than 190 dollars in total:

```sql
SELECT customer_id, SUM(amount) AS total_spent
FROM payment
GROUP BY customer_id
HAVING SUM(amount) > 190
ORDER BY total_spent DESC;
```

| customer_id | total_spent |
|---:|---:|
| 526 | 221.55 |
| 148 | 216.54 |
| 144 | 195.58 |
| 137 | 194.61 |
| 178 | 194.61 |

*5 rows returned.*

MySQL lets `HAVING` use the alias too, so `HAVING total_spent > 190` also works. Repeating the aggregate is more portable to other databases.

### WHERE and HAVING together

`WHERE` removes rows **first**. `HAVING` removes groups **afterwards**. Customers who made at least 3 payments of over 5 dollars:

```sql
SELECT customer_id, COUNT(*) AS big_payments
FROM payment
WHERE amount > 5
GROUP BY customer_id
HAVING COUNT(*) >= 3
ORDER BY big_payments DESC, customer_id;
```

| customer_id | big_payments |
|---:|---:|
| 137 | 15 |
| 144 | 15 |
| 522 | 15 |
| 526 | 15 |
| 176 | 14 |
| … | … |

*Showing the first 5 of 576 rows.*

## Watch out

### WHERE cannot use an aggregate

```sql
SELECT rating, COUNT(*) AS films
FROM film
WHERE COUNT(*) > 200
GROUP BY rating;
```

```text
ERROR 1111 (HY000): Invalid use of group function
```

At the `WHERE` stage the groups do not exist yet, so there is nothing to count. Use `HAVING`.

### Put row filters in WHERE, not HAVING

These two queries return the same rows, but the second one is better, because `WHERE` throws rows away *before* the work of grouping:

```sql
SELECT rating, COUNT(*) AS films
FROM film
GROUP BY rating
HAVING rating = 'PG';
```

| rating | films |
|---|---:|
| PG | 194 |

*1 row returned.*

```sql
SELECT rating, COUNT(*) AS films
FROM film
WHERE rating = 'PG'
GROUP BY rating;
```

| rating | films |
|---|---:|
| PG | 194 |

*1 row returned.*

Use `HAVING` only for conditions on aggregates.

## Interview corner

**"What is the difference between `WHERE` and `HAVING`?"**
`WHERE` filters individual rows before grouping and cannot use aggregates. `HAVING` filters groups after `GROUP BY` and is where aggregate conditions go.

**"Can you use `HAVING` without `GROUP BY`?"**
Yes, the whole table is then treated as one group, but it is rarely useful.

**"Write a query for duplicate values."**
Group by the column and keep the groups with more than one row: `GROUP BY email HAVING COUNT(*) > 1`. You will do this on the DVD Rental data in Module 10.

### Stretch: WHERE and HAVING together

Among payments made on or after `2005-07-01`, show each `customer_id` whose total is **over 60 dollars** (`total`). Order by `total` descending, then `customer_id`.

**Your result should look like this:**

| customer_id | total |
|---:|---:|
| 148 | 188.60 |
| 137 | 171.66 |
| 526 | 166.67 |
| 144 | 166.66 |
| 459 | 157.70 |
| … | … |

*Showing the first 5 of 541 rows.*

<details>
<summary>Hint</summary>

Filter rows by date with WHERE, group by customer, then HAVING on the SUM.

</details>

<details>
<summary>Show solution</summary>

```sql
SELECT customer_id, SUM(amount) AS total
FROM payment
WHERE payment_date >= '2005-07-01'
GROUP BY customer_id
HAVING SUM(amount) > 60
ORDER BY total DESC, customer_id;
```
