`LAG` looks at the **previous** row, and `LEAD` looks at the **next** row, without a self join. They answer questions like "how much did this differ from last time?" and "how long until the next one?".

## What you'll learn

- Reading the previous row with `LAG`
- Reading the next row with `LEAD`
- Calculating changes between consecutive rows

## Syntax

```sql
LAG(column, offset, default)  OVER (PARTITION BY group ORDER BY sort)
LEAD(column, offset, default) OVER (PARTITION BY group ORDER BY sort)
```

`offset` is how many rows back or forward (default 1), and `default` is what to return when there is no such row (default `NULL`). The `ORDER BY` inside `OVER` is required: "previous" needs an order.

## Examples

### The previous payment

Customer 1's payments, each with the one before it:

```sql
SELECT payment_id, payment_date, amount,
       LAG(amount) OVER (ORDER BY payment_date) AS previous_amount
FROM payment
WHERE customer_id = 1
ORDER BY payment_date;
```

| payment_id | payment_date | amount | previous_amount |
|---:|---|---:|---|
| 1 | 2005-05-25 11:30:37 | 2.99 | NULL |
| 2 | 2005-05-28 10:35:23 | 0.99 | 2.99 |
| 3 | 2005-06-15 00:54:12 | 5.99 | 0.99 |
| 4 | 2005-06-15 18:02:53 | 0.99 | 5.99 |
| 5 | 2005-06-15 21:08:46 | 9.99 | 0.99 |
| … | … | … | … |

*Showing the first 5 of 32 rows.*

The first row has no previous row, so it shows `NULL`.

### Change from one row to the next

```sql
SELECT payment_id, amount,
       amount - LAG(amount) OVER (ORDER BY payment_date) AS change_from_previous
FROM payment
WHERE customer_id = 1
ORDER BY payment_date;
```

| payment_id | amount | change_from_previous |
|---:|---:|---|
| 1 | 2.99 | NULL |
| 2 | 0.99 | -2.00 |
| 3 | 5.99 | 5.00 |
| 4 | 0.99 | -5.00 |
| 5 | 9.99 | 9.00 |
| … | … | … |

*Showing the first 5 of 32 rows.*

### Days between events

How many days passed between one rental and the next, for customer 1:

```sql
SELECT rental_id, rental_date,
       DATEDIFF(rental_date, LAG(rental_date) OVER (ORDER BY rental_date)) AS days_since_previous
FROM rental
WHERE customer_id = 1
ORDER BY rental_date;
```

| rental_id | rental_date | days_since_previous |
|---:|---|---|
| 76 | 2005-05-25 11:30:37 | NULL |
| 573 | 2005-05-28 10:35:23 | 3 |
| 1185 | 2005-06-15 00:54:12 | 18 |
| 1422 | 2005-06-15 18:02:53 | 0 |
| 1476 | 2005-06-15 21:08:46 | 0 |
| … | … | … |

*Showing the first 5 of 32 rows.*

### For every customer at once

Add `PARTITION BY` and the "previous row" restarts for each customer:

```sql
SELECT customer_id, payment_id, amount,
       LAG(amount, 1, 0) OVER (PARTITION BY customer_id ORDER BY payment_date) AS previous_amount
FROM payment
WHERE customer_id IN (1, 2)
ORDER BY customer_id, payment_date;
```

| customer_id | payment_id | amount | previous_amount |
|---:|---:|---:|---:|
| 1 | 1 | 2.99 | 0.00 |
| 1 | 2 | 0.99 | 2.99 |
| 1 | 3 | 5.99 | 0.99 |
| 1 | 4 | 0.99 | 5.99 |
| 1 | 5 | 9.99 | 0.99 |
| … | … | … | … |

*Showing the first 5 of 59 rows.*

Here the third argument `0` replaces the `NULL` at the start of each customer.

## Watch out

### The first (or last) row is NULL

`LAG` has nothing before the first row and `LEAD` has nothing after the last. Give them a third argument, or handle `NULL`, before you calculate with the result.

### Without PARTITION BY the rows all form one sequence

Over the whole `payment` table, the "previous" row for a customer's first payment would be another customer's last payment. Partition by the thing whose history you want.

### Order decides everything

`LAG` follows the `ORDER BY` **inside** `OVER`. If two rows tie on it, which is "previous" is arbitrary. Add a unique column as a tiebreaker.

## Interview corner

**"What do `LAG` and `LEAD` do?"**
They return a value from a previous (`LAG`) or following (`LEAD`) row in the window's order, in the same row as the current one.

**"How would you calculate month-over-month growth?"**
Aggregate to one row per month, then use `LAG(total) OVER (ORDER BY month)` and compute `(total - previous) / previous`.

**"How do you find the gap between consecutive events per user?"**
`DATEDIFF(event_date, LAG(event_date) OVER (PARTITION BY user ORDER BY event_date))`.

## Practice

### Warm-up: previous film length

Show `title`, `length` and `previous_length` (the length of the film before it, in `film_id` order) for films with `film_id` up to 5. Order by `film_id`.

**Your result should look like this:**

| title | length | previous_length |
|---|---:|---|
| ACADEMY DINOSAUR | 86 | NULL |
| ACE GOLDFINGER | 48 | 86 |
| ADAPTATION HOLES | 50 | 48 |
| AFFAIR PREJUDICE | 117 | 50 |
| AFRICAN EGG | 130 | 117 |

*5 rows returned.*

<details>
<summary>Hint</summary>

`LAG(length) OVER (ORDER BY film_id)`, then filter after computing.

</details>

<details>
<summary>Show solution</summary>

```sql
WITH lagged AS (
  SELECT film_id, title, length, LAG(length) OVER (ORDER BY film_id) AS previous_length
  FROM film
)
SELECT title, length, previous_length
FROM lagged
WHERE film_id <= 5
ORDER BY film_id;
```

</details>

### Stretch: the biggest jump

For customer 1, show the `payment_id`, `amount` and `change_from_previous` for every payment where the amount **went up** compared with the previous one. Order by `payment_date`.

**Your result should look like this:**

| payment_id | amount | change_from_previous |
|---:|---:|---:|
| 3 | 5.99 | 5.00 |
| 5 | 9.99 | 9.00 |
| 9 | 3.99 | 3.00 |
| 10 | 5.99 | 2.00 |
| 14 | 7.99 | 3.00 |
| … | … | … |

*Showing the first 5 of 13 rows.*

<details>
<summary>Hint</summary>

Compute the change in a CTE, and keep rows where it is above 0.

</details>

<details>
<summary>Show solution</summary>

```sql
WITH changes AS (
  SELECT payment_id, payment_date, amount,
         amount - LAG(amount) OVER (ORDER BY payment_date) AS change_from_previous
  FROM payment
  WHERE customer_id = 1
)
SELECT payment_id, amount, change_from_previous
FROM changes
WHERE change_from_previous > 0
ORDER BY payment_date;
```

</details>
