`NOT` flips a condition: it keeps the rows that do **not** match.

Ask for "every film that is *not* rated G" and MySQL hands back everything except the G films. You will use it constantly, both to exclude things you don't want and to ask "who is missing?" questions.

## What you'll learn

- `NOT` with a comparison, and the built-in forms `NOT LIKE`, `NOT IN`, `NOT BETWEEN` and `IS NOT NULL`
- Why `NOT IN` and `NULL` do not mix
- Why `NOT` needs brackets when combined with `AND` or `OR`

## Syntax

```sql
SELECT column1, column2
FROM table_name
WHERE NOT condition;
```

`NOT` goes in front of a condition. Some conditions have their own built-in forms: `NOT LIKE`, `NOT IN`, `NOT BETWEEN` and `IS NOT NULL`.

## The data we'll use

All the examples use the `film` table from the DVD Rental database. It has 1000 films. Here is a peek at the first 8 rows and the columns we care about:

```sql
SELECT film_id, title, rating, length, rental_rate
FROM film
WHERE film_id <= 8;
```

| film_id | title | rating | length | rental_rate |
|---:|---|---|---:|---:|
| 1 | ACADEMY DINOSAUR | PG | 86 | 0.99 |
| 2 | ACE GOLDFINGER | G | 48 | 4.99 |
| 3 | ADAPTATION HOLES | NC-17 | 50 | 2.99 |
| 4 | AFFAIR PREJUDICE | G | 117 | 2.99 |
| 5 | AFRICAN EGG | G | 130 | 2.99 |
| 6 | AGENT TRUMAN | PG | 169 | 2.99 |

`length` is the running time in minutes. `rating` is one of `G`, `PG`, `PG-13`, `R` or `NC-17`.

## Examples

### NOT with a comparison

Every film that is not rated G:

```sql
SELECT title, rating
FROM film
WHERE NOT rating = 'G'
ORDER BY title;
```

| title | rating |
|---|---|
| ACADEMY DINOSAUR | PG |
| ADAPTATION HOLES | NC-17 |
| AGENT TRUMAN | PG |
| AIRPLANE SIERRA | PG-13 |
| AIRPORT POLLOCK | R |
| … | … |

*Showing the first 5 of 822 rows.*

`NOT rating = 'G'` means the same as `rating <> 'G'`. Both count the same number of films:

```sql
SELECT COUNT(*) AS films_not_rated_g
FROM film
WHERE rating <> 'G';
```

| films_not_rated_g |
|---:|
| 822 |

*1 row returned.*

The same trick works with the other comparisons. `NOT length > 60` keeps films that are 60 minutes or shorter (`length <= 60`).

### NOT LIKE

Every film whose title does **not** start with the letter A:

```sql
SELECT title
FROM film
WHERE title NOT LIKE 'A%'
ORDER BY title;
```

| title |
|---|
| BABY HALL |
| BACKLASH UNDEFEATED |
| BADMAN DAWN |
| BAKED CLEOPATRA |
| BALLOON HOMEWARD |
| … |

*Showing the first 5 of 954 rows.*

`%` stands for "any characters", so `'A%'` means "starts with A".

### NOT IN

Every film that is neither rated G nor PG:

```sql
SELECT title, rating
FROM film
WHERE rating NOT IN ('G', 'PG')
ORDER BY title;
```

| title | rating |
|---|---|
| ADAPTATION HOLES | NC-17 |
| AIRPLANE SIERRA | PG-13 |
| AIRPORT POLLOCK | R |
| ALABAMA DEVIL | PG-13 |
| ALADDIN CALENDAR | NC-17 |
| … | … |

*Showing the first 5 of 628 rows.*

### NOT BETWEEN

Films that are unusually short or long, meaning outside the 60 to 150 minute range:

```sql
SELECT title, length
FROM film
WHERE length NOT BETWEEN 60 AND 150
ORDER BY length, title;
```

| title | length |
|---|---:|
| ALIEN CENTER | 46 |
| IRON MOON | 46 |
| KWAI HOMEWARD | 46 |
| LABYRINTH LEAGUE | 46 |
| RIDGEMONT SUBMARINE | 46 |
| … | … |

*Showing the first 5 of 338 rows.*

`BETWEEN` includes both ends, so a 60 minute or 150 minute film is *not* returned here.

### IS NOT NULL

`NULL` means "no value", and you can't test it with `=`. To keep only the rentals that have already been returned:

```sql
SELECT rental_id, rental_date, return_date
FROM rental
WHERE return_date IS NOT NULL
ORDER BY rental_id;
```

| rental_id | rental_date | return_date |
|---:|---|---|
| 1 | 2005-05-24 22:53:30 | 2005-05-26 22:04:30 |
| 2 | 2005-05-24 22:54:33 | 2005-05-28 19:40:33 |
| 3 | 2005-05-24 23:03:39 | 2005-06-01 22:12:39 |
| 4 | 2005-05-24 23:04:41 | 2005-06-03 01:43:41 |
| 5 | 2005-05-24 23:05:21 | 2005-06-02 04:33:21 |
| … | … | … |

*Showing the first 5 of 15861 rows.*

## Watch out

### NOT IN and NULL

This is the most famous trap. In this database, every film's `original_language_id` is empty (`NULL`). Let's find films whose `language_id` is not in that list:

```sql
SELECT COUNT(*) AS films_found
FROM film
WHERE language_id NOT IN (SELECT original_language_id FROM film);
```

| films_found |
|---:|
| 0 |

*1 row returned.*

Every film should qualify, because the list has no real values in it, yet we get zero. If the list contains even one `NULL`, `NOT IN` can never say "yes": MySQL can't be sure the value isn't equal to that unknown. The fix is to keep `NULL`s out of the list:

```sql
SELECT COUNT(*) AS films_found
FROM film
WHERE language_id NOT IN (
  SELECT original_language_id
  FROM film
  WHERE original_language_id IS NOT NULL
);
```

| films_found |
|---:|
| 1000 |

*1 row returned.*

### NOT applies to the next condition only

Without brackets, `NOT` only covers the condition right after it. These two lines look alike but ask different questions:

```sql
SELECT COUNT(*) AS not_g_and_short
FROM film
WHERE NOT rating = 'G' AND length < 60;

SELECT COUNT(*) AS not_both
FROM film
WHERE NOT (rating = 'G' AND length < 60);
```

| not_g_and_short |
|---:|
| 75 |

*1 row returned.*

| not_both |
|---:|
| 979 |

*1 row returned.*

The first means "not rated G, **and** shorter than 60 minutes". The second means "**not** (rated G and shorter than 60 minutes)", which lets in every film that fails either half. When you mix `NOT` with `AND` or `OR`, add brackets.

### NOT never rescues a NULL

If a value is `NULL`, both `= 1` and `NOT = 1` are "unknown", and `WHERE` only keeps rows that are definitely true:

```sql
SELECT COUNT(*) AS films_found
FROM film
WHERE NOT original_language_id = 1;
```

| films_found |
|---:|
| 0 |

*1 row returned.*

To include the empty ones, ask for them explicitly:

```sql
SELECT COUNT(*) AS films_found
FROM film
WHERE original_language_id IS NULL OR original_language_id <> 1;
```

| films_found |
|---:|
| 1000 |

*1 row returned.*

## Interview corner

**"What is the difference between `NOT IN` and `NOT EXISTS`?"**
`NOT IN` returns nothing if the list contains a `NULL` (see *NOT IN and NULL* above). `NOT EXISTS` doesn't have that problem, so it is the safer choice when the list comes from a subquery. You will write it properly in Module 8, but here is the same question answered with it:

```sql
SELECT COUNT(*) AS films_found
FROM film f
WHERE NOT EXISTS (
  SELECT 1 FROM film o WHERE o.original_language_id = f.language_id
);
```

| films_found |
|---:|
| 1000 |

*1 row returned.*

**"Is `NOT LIKE` case-sensitive?"**
It depends on the column's collation. MySQL's default (`utf8mb4_0900_ai_ci`) ignores case, so `'a' NOT LIKE 'A'` is false:

```sql
SELECT 'a' NOT LIKE 'A' AS result;
```

| result |
|---:|
| 0 |

*1 row returned.*

`0` means false: the two letters count as a match under this collation.

**"How would you write `NOT BETWEEN` without using `NOT`?"**
Use `OR` on the two sides. It returns exactly the same films:

```sql
SELECT COUNT(*) AS films_found
FROM film
WHERE length < 60 OR length > 150;
```

| films_found |
|---:|
| 338 |

*1 row returned.*

The `special_features` column is a `SET`, a list of extras such as `Trailers` or `Deleted Scenes`. Show the `title` and `special_features` of every film that does **not** include `Trailers`, alphabetical by title.
