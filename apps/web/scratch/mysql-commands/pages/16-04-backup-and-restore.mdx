Every database will one day lose data: a mistaken `DELETE`, a bad deployment, a failed disk. A **backup** is the only real protection, and **a backup you have never restored is only a hope**. This page shows how to take a backup with `mysqldump`, restore it, and prove it worked.

## What you'll learn

- Logical backups with `mysqldump`
- Backing up one table, or a whole database with its procedures and triggers
- Restoring a backup, and checking it
- Point-in-time recovery, and what else to know

## Logical and physical backups

| Kind | What it is | Tools |
|---|---|---|
| **Logical** | SQL statements (`CREATE TABLE`, `INSERT`) that rebuild the data | `mysqldump`, `mysqlsh` dump utilities |
| **Physical** | a copy of the data files themselves | Percona XtraBackup, MySQL Enterprise Backup, storage snapshots |

Logical backups are portable and easy to read and restore, and they are slower on very large databases. This page uses `mysqldump`, which ships with MySQL.

## Take a backup, and restore it somewhere else

The commands below run in a terminal on your machine, in the `sypher-db-lab` folder. They dump one table, create an empty scratch database, load the dump into it, and finish by checking the row counts match:

```bash
docker compose exec -T mysql mysqldump -uroot -ppassword --single-transaction sypher-mysql-DvdRental category > backup_demo_category.sql

grep -E "^CREATE TABLE" backup_demo_category.sql

docker compose exec -T mysql mysql -uroot -ppassword -e "DROP DATABASE IF EXISTS restore_test; CREATE DATABASE restore_test"

docker compose exec -T mysql mysql -uroot -ppassword restore_test < backup_demo_category.sql

docker compose exec -T mysql mysql -uroot -ppassword -N -e "SELECT CONCAT('original: ', COUNT(*)) FROM \`sypher-mysql-DvdRental\`.category UNION ALL SELECT CONCAT('restored: ', COUNT(*)) FROM restore_test.category"
```

```text
CREATE TABLE `category` (
original: 16
restored: 16
```

The dump file is plain SQL text you can open in any editor. The `--single-transaction` option takes a consistent snapshot without locking the tables, so people can keep working during the backup (it works for InnoDB tables).

Now check it from inside MySQL, and remove the scratch database:

```sql
SELECT (SELECT COUNT(*) FROM restore_test.category) AS restored_rows,
       (SELECT COUNT(*) FROM `sypher-mysql-DvdRental`.category) AS original_rows;

DROP DATABASE restore_test;
```

| restored_rows | original_rows |
|---:|---:|
| 16 | 16 |

*1 row returned.*

## A full backup: tables, procedures, triggers, events

A dump of a whole database should also include the stored programs, or the restored database will be missing them:

```bash
docker compose exec -T mysql mysqldump -uroot -ppassword --single-transaction --routines --triggers --events sypher-mysql-DvdRental | gzip > backup_demo_full.sql.gz

gzip -t backup_demo_full.sql.gz && echo "backup file is a valid gzip archive"

zcat backup_demo_full.sql.gz | grep -q "film_in_stock" && echo "stored procedures are in the backup"
zcat backup_demo_full.sql.gz | grep -q "upd_film" && echo "triggers are in the backup"
```

```text
backup file is a valid gzip archive
stored procedures are in the backup
triggers are in the backup
```

Piping through `gzip` makes the file several times smaller.

## Restoring a whole database

To restore a full dump into an empty database, feed it back to `mysql`:

```bash
gunzip < backup.sql.gz | docker compose exec -T mysql mysql -uroot -ppassword sypher-mysql-DvdRental
```

That is the same command used to restore the single table above. Add `--databases` when you take the dump if the file should also contain the `CREATE DATABASE` line.

## Windows: PowerShell and redirection

In Windows PowerShell, the `>` operator does not write plain UTF-8: depending on the version and settings it writes UTF-16, or UTF-8 with a hidden byte-order mark. Either can make `mysql` fail to read the dump back (typically with a syntax error on the very first line). To stay safe, let MySQL write the file itself inside the container and copy it out:

```bash
docker compose exec -T mysql sh -c 'mysqldump -uroot -ppassword --single-transaction --result-file=/tmp/backup_demo.sql sypher-mysql-DvdRental category'

docker compose cp mysql:/tmp/backup_demo.sql backup_demo_copied.sql

docker compose exec -T mysql rm /tmp/backup_demo.sql

grep -c "^INSERT INTO" backup_demo_copied.sql
```

```text
1
 sypher-db-lab-mysql-1 copy sypher-db-lab-mysql-1:/tmp/backup_demo.sql to backup_demo_copied.sql Copying
 sypher-db-lab-mysql-1 copy sypher-db-lab-mysql-1:/tmp/backup_demo.sql to backup_demo_copied.sql Copied
```

## Point-in-time recovery

A nightly backup means losing up to a day of work. To recover to *just before a mistake*, MySQL also keeps a **binary log** of every change. Restore the last backup, then replay the log up to the moment before the accident. These are the settings that make it possible:

```sql
SELECT @@log_bin AS binary_log_on,
       @@binlog_format AS log_format,
       @@binlog_expire_logs_seconds / 86400 AS keep_days;
```

| binary_log_on | log_format | keep_days |
|---:|---|---:|
| 1 | ROW | 30.0000 |

*1 row returned.*

The binary log is on, records each changed row, and is kept for 30 days by default. The tool that replays it is `mysqlbinlog`.

## Watch out

### An untested backup is not a backup

Restore into a scratch database regularly, and check the row counts and a few real queries. Discovering that a backup file is empty or corrupt during an emergency is far too late.

### Keep backups somewhere else

A backup on the same disk as the database dies with it. Copy backups to another machine or to cloud storage, and keep several generations.

### Backups contain everything, including secrets

The dump holds all your data (and password hashes, if you dump the `mysql` database). Encrypt it and control who can read it.

### `--single-transaction` needs InnoDB

For older `MyISAM` tables it does not give a consistent snapshot. Use `--lock-all-tables` if you have any.

### Passwords on the command line are visible

`-ppassword` can show up in a process list, and MySQL warns about it. In real scripts, use a protected options file (`--defaults-extra-file`) or a login path.

### Know your recovery targets

How much data can you afford to lose (**RPO**), and how long can you be down (**RTO**)? A nightly dump gives an RPO of a day. Binary logs bring it to seconds, and a replica shortens the RTO.

## Interview corner

**"How do you back up a MySQL database?"**
Logically with `mysqldump` (add `--single-transaction` for consistency without locking, and `--routines --triggers --events` to include stored programs), or physically with a tool such as Percona XtraBackup or a storage snapshot for large databases.

**"How do you restore a backup?"**
Pipe the dump into `mysql`: `mysql db < backup.sql` (or `gunzip < backup.sql.gz | mysql db`).

**"What is point-in-time recovery?"**
Restoring the last full backup and then replaying the binary log up to just before the failure, so you lose almost nothing.

**"How do you know a backup is good?"**
By restoring it regularly to a test server and verifying the data.

**"What are RPO and RTO?"**
Recovery Point Objective: the most data loss you accept, measured in time. Recovery Time Objective: how long recovery may take.

### Stretch: recover from a mistake

Simulate a disaster and a recovery. Make a working copy `category_work` of `category`, and a backup copy `category_backup` of it. Then "accidentally" delete every row of `category_work`, restore its rows from `category_backup`, and return the number of rows in `category_work` as `rows_after_recovery`.

**Your result should look like this:**

| rows_after_recovery |
|---:|
| 16 |

*1 row returned.*

<details>
<summary>Hint</summary>

</details>

<details>
<summary>Show solution</summary>

```sql

DROP TABLE IF EXISTS category_backup;
CREATE TABLE category_work LIKE category;
INSERT INTO category_work SELECT * FROM category;
CREATE TABLE category_backup LIKE category;
INSERT INTO category_backup SELECT * FROM category_work;

DELETE FROM category_work;
INSERT INTO category_work SELECT * FROM category_backup;

SELECT COUNT(*) AS rows_after_recovery FROM category_work;
```
