Every quarter-over-quarter regression across the year got tagged with a root cause: 21 traced to inherently complex new features, 34 to known unaddressed technical debt, 12 to environment differences, 15 to a gap in the release process itself.

| Cause | Count | Share |
| --- | --- | --- |
| Feature complexity | 21 | 25.6% |
| Technical debt | 34 | 41.5% |
| Environment | 12 | 14.6% |
| Process gap | 15 | 18.3% |

![Donut chart of Compass QA quarter-over-quarter regressions split by root cause, feature complexity, technical debt, environment, and process gap](https://syhpher-next-datastore-gvaf.b-cdn.net/svgs/measuring-quality-trends/regression-root-cause.svg)

*Shown as a donut chart because this is composition, how the whole set of regressions splits by root cause.*

Technical debt accounts for 41.5% of the year’s regressions, more than any other single cause. That connects directly back to a different course in this series: technical debt is not just a code cleanliness concern, it is measurably the single biggest source of quality regressions at Compass across the whole year.

This chart is what turns "quality improved this year" from a vague feeling into an actionable plan for next year: whatever technical debt work is funded next should be aimed specifically at the debt most likely to cause a regression, not spread evenly across the whole backlog.
